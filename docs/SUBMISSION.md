## Решение по размещению прототипа

Выбран отдельный **Linux x86_64 стенд с существующим Docker Compose и HTTPS reverse proxy**. Это сохраняет реальный Node/PostgreSQL/RabbitMQ/Python контур и имеющиеся контракты. Статическая публикация `apps/web/dist` сама по себе не даёт рабочую загрузку и анализ.

Порядок подготовки:

1. На выделенном для демонстрации хосте выполнить [Docker profiles](operations/DOCKER_PROFILES.md); для конкурсного GPU использовать [H100 launch](operations/COMPETITION_H100_LAUNCH.md). Установить секреты и выбранные профили по инструкции, пройти preflight.
2. Сохранить внутренние API, БД, RabbitMQ, MinIO и provider ports внутри Docker/loopback. Публичный HTTPS reverse proxy направить только на web, который проксирует API. Настроить внешний origin и `SESSION_COOKIE_SECURE=1`.
3. Использовать отдельную демонстрационную БД и организацию: `INSPECTOR_OPEN_WORKSPACE=1` даёт посетителям общие права изменения. В таком стенде должны находиться только согласованные демонстрационные материалы.
4. Подготовить три примера по [PUBLIC_REVIEW_VISITOR](operations/PUBLIC_REVIEW_VISITOR_20260929.md), проверить исходники и реальные результаты выбранного профиля.
5. Открыть HTTPS-адрес с другого устройства без SSH и без сохранённой сессии. Проверить загрузку PDF, завершение фонового анализа, просмотр оригинала, решение и экспорт. Только после этого вставить URL в форму.

На 29 сентября доступный внешний сервер/домен в этой среде не найден. Указанный в старых журналах SSH alias `homeserver` здесь не разрешается. Случайный временный tunnel не используется как окончательная конкурсная ссылка. Развёртывание требует доступа к выбранному хосту; покупка сервера или домена не выполнялась.

## Короткий сценарий для жюри

1. Открыть кабинет и подготовленный публичный объект.
2. Посмотреть комплект: стадия документа, исходный файл и страницы.
3. Открыть подсказку и соответствующий оригинал. Проверить редакцию, согласование и связь источников.
4. Сохранить решение с обоснованием. Объяснить разницу между подсказкой и подтверждённым замечанием.
5. Проверить покрытие: непройденные правила и отсутствующие источники остаются видимыми.
6. Открыть протокол и экспорт. При `PARTIAL` явно учесть ограничения.

Сценарий реального анализа должен быть повторён на размещённом стенде. На текущем локальном компьютере проверены UI, API и PostgreSQL, но нет полного OCR/inference/queue контура; подробности в [финальном отчёте](FINAL_VALIDATION_2026-09-29.md).
