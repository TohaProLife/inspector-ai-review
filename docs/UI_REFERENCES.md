# UI-референсы Mobbin

Примечание к архитектуре от 17 сентября 2026: этот документ сохраняет визуальные источники. Актуальные сценарии, состояния и поведение viewer заданы в [UX](UX.md) и [10_FRONTEND](architecture/10_FRONTEND.md). Референс или mockup не подтверждает работоспособность функции, правильность кода параметра, confidence или счётчика.

Дата поиска: 15 сентября 2026 года. Платформа: web. Поиск выполнен через MCP Mobbin. Локальные изображения — водяные preview Mobbin для внутреннего дизайн-анализа. Canonical links сохранены рядом.

## Выбор

Главный продуктовый референс — связка двух паттернов:

1. Airwallex: документ слева, извлечённые поля справа, решения в фиксированной зоне.
2. Semrush: синхронный split-view, явная подсветка различий, два исхода review.

Один экран не покрывает задачу полностью. «Инспектор ИИ» должен объединить review-механику этих продуктов с compliance dashboard из Vanta.

## 1. Airwallex — основной workflow-референс

[Открыть flow «Approving a bill» в Mobbin](https://mobbin.com/flows/aeeb29f6-cc4c-439c-857a-7b5f22c5606a).

[Открыть ключевой review screen в Mobbin](https://mobbin.com/screens/d6fa70dc-46b6-41e0-9771-d61e758980a3).

[Изображение не включено в публичный снимок.]

Сильные решения:

- исходный документ остаётся виден во время проверки;
- структурированные поля сгруппированы справа;
- approve/reject находятся в ожидаемой фиксированной зоне;
- viewer имеет минимальные zoom/download controls;
- следующий статус появляется сразу после действия.

Адаптация:

- слева не один invoice, а viewers ПД/РД/ИД;
- справа evidence values, confidence, rationale и решение инспектора;
- `Approve` заменяется на «Подтвердить нарушение» только как действие человека;
- при отсутствии данных основной путь — «Уточнить» или «Дозагрузить».

## 2. Semrush — основной референс сравнения

[Открыть split review screen в Mobbin](https://mobbin.com/screens/ed82aafc-c4dc-442d-87fc-359f7347f940).

[Изображение не включено в публичный снимок.]

Сильные решения:

- два источника имеют одинаковый визуальный вес;
- изменения подсвечены внутри контента;
- пользователь понимает, что именно изменилось;
- решения расположены после просмотра полного сравнения;
- review mode отделён от обычного режима.

Адаптация:

- синхронный zoom и pan;
- bbox/polygon вместо подсветки строк;
- точные file ID, page и sheet;
- третий источник ИД через split 3-up или tabs;
- sticky decision panel.

## 3. Vanta — очередь контрольных пунктов

[Открыть Vanta Tests screen в Mobbin](https://mobbin.com/screens/d33c50cb-a1db-4dbd-a420-49bbf678ba3d).

[Изображение не включено в публичный снимок.]

Сильные решения:

- `OK` и `Needs attention` разделены до таблицы;
- категория видна рядом с навигацией;
- фильтры не скрывают текущий scope;
- таблица рассчитана на большой объём проверок;
- status, owner и type читаются без открытия строки.

Адаптация:

- summary: кандидаты, уточнения, missing documents, без расхождений;
- фильтры: стадия, раздел, критичность, статус, reviewer;
- строки параметров открывают evidence card;
- confirmed и candidate никогда не используют одинаковый визуальный статус.

## 4. AWS — технический upload/progress

[Открыть AWS upload status screen в Mobbin](https://mobbin.com/screens/d0b2a1fa-99a9-4c29-ba83-f77a3f850d40).

[Изображение не включено в публичный снимок.]

Сильные решения:

- общий прогресс и детальные статусы файлов показаны вместе;
- success, progress, pending и failed видны построчно;
- ошибка привязана к конкретному файлу;
- пользователь может уйти после понимания состояния задачи.

Адаптация:

- вместо общей таблицы — группы ПД, РД и ИД;
- после upload показывать validation, OCR и checking;
- ошибки разделять на технические и предметные;
- missing stage не оформлять как failed upload.

## Карта применения

| Экран «Инспектор ИИ» | Основной референс | Что взять |
|---|---|---|
| Загрузка объекта | AWS | Общий прогресс и file-level statuses |
| Анализ | AWS + Vanta | Pipeline и сводка внимания |
| Результаты | Vanta | Summary, filters, dense table |
| Карточка доказательства | Semrush + Airwallex | Split diff, document viewer, decision panel |
| Недостаточно данных | Airwallex | Блокирующее состояние и следующий шаг |
| Протокол | Airwallex | Review outcome и переход состояния |

## Не копировать

- брендинг и цвета референсов;
- финансовую терминологию Airwallex;
- SEO-метрики Semrush;
- перегруженную глобальную навигацию;
- автоматическое применение решения без причины;
- статус «нарушение» до действия инспектора.

## Рекомендуемый desktop layout

```text
Left rail: objects, checks, protocols
Center: PD/RD/ID document workspace
Right rail: extracted values, confidence, rationale, decision
Top: object, parameter, stage and revision context
Bottom or sticky right: confirm, reject, clarify
```

## Принятое визуальное направление

После browser review интерфейс переведён из «витринного dashboard» в спокойный рабочий инструмент:

- светлая нейтральная навигация вместо тёмной брендированной панели;
- один синий акцент только для выбора и основного действия;
- числовая сводка одной строкой вместо сетки одинаковых карточек;
- таблица результатов как главный объект страницы;
- полноэкранный evidence mode без глобальной навигации;
- фиксированная панель решения, которая не уходит за нижнюю границу окна;
- `Golos Text` для рабочего текста и `Commissioner` для коротких заголовков;
- основной desktop-текст не меньше 13 px, видимый keyboard focus и `prefers-reduced-motion`;
- статус передаётся текстом и формой индикатора, а не одним цветом.

Дизайн-контекст и анти-референсы сохранены в [`.impeccable.md`](../.impeccable.md). Слайды из `output/user-flow-slides` остаются ранним концептом пользовательского пути и больше не считаются визуальным эталоном реализации.
