# UX и пользовательские сценарии

Версия 1.1, 18 сентября 2026. Целевой UX; текущие mockups служат только визуальными материалами. Уточнения из сессии вопросов и ответов — в [HACKATHON_QA_SESSION](HACKATHON_QA_SESSION.md). Детальная архитектура экранов, server state, viewer и ошибок — [10_FRONTEND](architecture/10_FRONTEND.md).

## Принципы

Пользователь должен видеть, какие документы проверены, почему сделан вывод и какое решение ожидается. Кандидат отличается от подтверждённого нарушения; машинный отрицательный результат — от экспертно проверенного. Неполнота, неподдержанное правило и технический сбой имеют разные подписи. Цвет дополняет текст, но не заменяет смысл.

Каждый вывод открывает его оригинал, нужную страницу и область, выбранную редакцию и сведения о согласовании. Уверенность отображается только при реальной оценке; иначе «не оценена». Дозагрузка продолжается внутри текущей проверки, а история остаётся доступной.

## Основные пути

| Путь | Результат для пользователя |
|---|---|
| Объект → проверка → файлы → анализ | Принятые оригиналы и наблюдаемый реальный прогресс |
| Сводка → очередь → evidence → решение | Причина, автор, версия источников и следующий item |
| Неполнота → дозагрузка → новый run | Видны новые/изменённые результаты и перенесённые решения |
| Конфликт редакций → metadata resolution → новый run | Выбор источника обоснован и версионирован |
| SUSPICION → evidence → promotion | Ручная lineage без изменения исходного прогноза |
| Рабочая сводка → preview snapshot → finalize | Сохранённый протокол, отдельный статус rendering и sync |
| FINAL → разрешённый отзыв → новый цикл работы | История и прежний snapshot сохранены |

## Что обязательно в evidence workspace

Все страницы документа, zoom/pan и fit, исходный файл, соседние листы, ПД/РД/ИД и согласование, выбранные/альтернативные версии, normalized overlay, extracted values с единицами/допусками. Переход между источниками не теряет выбранную находку. Два статичных изображения не закрывают этот сценарий.

Действия решения используют reason code и комментарий. Конфликт 412 сохраняет текст пользователя и предлагает сверить чужое решение; timeout повторяет ту же команду идемпотентно. Finalize показывает конкретные blockers и отдельно подтверждение ограничений PARTIAL.

Инспектор может выбрать несколько однородных atomic items и применить общее действие с видимым основанием, но не подтверждать или отклонять всю очередь одной кнопкой. Для каждого item сохраняется отдельное решение. Выбор обоснованной редакции или корректировка evidence создаёт новую human version; исходный файл, OCR и machine result остаются неизменными.

## Проверка удобства

Пять инспекторов; согласованный комплект на 132 параметра/14 отклонений; ≤30 минут и ≤3 осознанных действий от карточки до сохранения типового решения. Ввод причины считается отдельно. Зафиксировать успешность задач, ошибки, время, действия и затруднения; не заменять проверку экспертами субъективным впечатлением команды. Клавиатура, focus, доступные labels, ошибки и reduced motion входят в проверку.

Визуальные референсы — [UI_REFERENCES](UI_REFERENCES.md). Подписи и цифры на старых изображениях сверяются с каталогом и runtime: выдуманные проценты, соответствия кодов и счётчики не переносятся в продукт.
