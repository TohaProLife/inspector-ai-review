## Исправления

- Устранена гонка двух первых запросов `open-workspace` и аналогичная гонка публичного посетителя. Уникальность пользователя и существующие серверные ограничения сохранены; два одновременных входа покрыты PostgreSQL regression.
- Дозагрузка и повтор после ошибки продолжают существующий объект. Интерфейс больше не предлагает создать уже сохранённый черновик.
- Данные объекта, запуска, замечаний и протоколов переключаются согласованно. Запоздалый ответ от предыдущего объекта не заменяет текущий экран.
- Разделы «Проверки», «Кандидаты» и «Протоколы» получили собственные пустые состояния. Черновики показываются отдельно с переходом к дозагрузке; выбор объекта с активным запуском сохраняет назначение перехода. Локальная ошибка открытия объекта больше не блокирует всё меню.
- Подсказки и исходные артефакты перечитываются после смены статуса запуска. На время сохранения решения переключение записи блокируется, чтобы ответ не применялся к другой карточке.
- Неактивный экспорт `submission JSON` убран из рабочего экрана: PostgreSQL API пока возвращает `INCOMPLETE_ANALYSIS`. Экспорт выпущенного протокола JSON остаётся доступным.
- Фоновое обновление запущенной проверки продолжается после перехода между экранами. Ошибки polling обрабатываются.
- Нельзя переключить источник или кандидата и потерять комментарий во время сохранения. Убраны две неработавшие кнопки.
- Финализация в UI учитывает готовность запуска и доступные сведения о роли. Для `PARTIAL` требуется подтверждение ограничений даже при нулевом `unsupported`; окончательное объектное разрешение проверяет API.
- Поиск удерживает клавиатурный фокус в диалоге. Кнопка поиска и поле справочника получили доступные имена; справочник показывает число результатов, пустую выдачу и очистку запроса.
- Исправлены мобильные отступы карточки создания объекта и контраст основного действия в шапке.
- Удалён конфликтующий `landing-light.css`: восстановлены синий градиент, белый текст и светлый точечный дом. Палитра сверена с [Hero Antimetal в Mobbin](https://mobbin.com/sites/sections/5aa60e87-1a43-492d-9616-107268d3f5ce). Тёмная тема сохраняет тёплые нейтральные цвета; цвет browser chrome также согласован с ней.
- Python-тесты запускаются переносимым Node runner. Исправлены закрытие SQLite/partial-файлов, восстановление read-only model artifacts и Windows-запуск TypeScript из Python.
- API suites выполняются последовательно. Общие прогоны с четырьмя и двумя workers на этом ноутбуке дали timeout; отдельный повтор двух проблемных suites прошёл (6/6). При timeout Vitest незавершённые операции проверки PDF могут продолжать занимать лимит исполнения и вызвать последующие отказы. Этот механизм установлен по коду; непосредственная трассировка счётчика не выполнялась. Production-лимиты и assertions этих тестов не изменялись.
- Хешируемые JSON/JSONL и shell-файлы закреплены в LF через `.gitattributes`. POSIX locking не заменён небезопасной имитацией на Windows.
- README приведён к текущему запуску без seed-данных, обновлены notices используемых иконок, исключены локальные исследовательские каталоги из Git.

## Что ещё необходимо до отправки

1. Развернуть полный контур на доступном Linux-хосте и повторить загрузку → антивирус → очередь → завершённый анализ → решение → экспорт/финализацию в браузере. Автоматические тесты с fixtures не заменяют этот прогон.
2. Предоставить жюри доступ к закрытому GitHub-репозиторию либо согласованному архиву. Текущая учётная запись не имеет GitHub admin.
3. Получить и анонимно проверить постоянный HTTPS-адрес прототипа. Адреса `localhost` и SSH-туннель для поля конкурса не подходят.
4. Уточнить условия передачи зависимостей и графических исходников по [аудиту доступа и лицензий](RELEASE_ACCESS_AND_LICENSES.md).
