## Metadata корпуса

Manifest описывает 203 TRAIN_PUBLIC и 213 TEST_HIDDEN файлов трёх объектов: 172 ПД, 103 РД, 130 ИД, 10 RD_ID_MIXED и один UNKNOWN. Указаны 366 PDF, также архивы, DOCX, DWG и TXT. Суммарно для PDF указаны 26 103 страницы; размер всех 416 файлов — 8 697 888 218 байт.

На homeserver завершена загрузка `01_ПАКЕТ_УЧАСТНИКАМ_3_ОБЪЕКТА.zip` (8 718 593 068 байт, SHA-256 `79d71bfaa747c704e41e73d059d06a78f74dd34b4264ee9cf8205d6bc7335417`). Размер и ZIP CRC проверены. Встроенный `document_manifest.jsonl` побайтно совпал с копией репозитория по SHA-256 `853225daec1888fbed19bbeb45e958154135f069799cea883dcd3c754c6c4ee7`. В архиве ровно 416 исходных файлов: нет пропусков, лишних путей и расхождений размеров. SHA-256 содержимого каждого из 416 файлов независимо совпал с manifest. Таким образом, оригиналы корпуса доступны на homeserver, хотя в Git они не включены. Для разработки и smoke брать только 203 файла `TRAIN_PUBLIC`; 213 файлов `TEST_HIDDEN` сверены лишь на целостность, без использования их содержимого или ответов для настройки.

35 записей превышают 50 MiB: 33 PDF и два ZIP, максимум около 658 MB. Обычный upload не должен обходить лимит; нужен согласованный batch-import profile (Q-03). Статистика manifest не даёт разрешения использовать hidden answers для настройки модели.

## Что доказывает открытая разметка

Десять открытых checks в репозитории — положительные, относятся к четырём группам одного объекта. Представлены пять IOS4-078, один IOS4-079 и четыре FREE-HEATING-001. Это два матричных кода из 132 и один free-code, около 1,5% каталога. Отрицательные записи из дополнительного архива помечены `ORGANIZER_ONLY` и не считаются открытой оценкой; public locators не обеспечивают bbox-разметку для полной геометрической оценки.

Есть предметное несоответствие IOS4-078/079 между каталогом и демонстрационными интерпретациями. Исходные коды/описания сохраняются; до ответа Q-04 disputed mappings не объявляются исправленными. FREE-HEATING-001 находится вне матрицы и учитывается отдельно.

Public checks полезны для format/regression tests и известных примеров. Они не являются независимым доказательством recall на 132 параметрах, FPR или обобщения на новые объекты. Неизвестный label не равен NO_VIOLATION.

На сессии подтверждено, что итоговый прогон будет выполняться на скрытой выборке, не выданной участникам, и может охватывать не все 132 параметра. Участникам разрешено использовать доступные материалы для разработки; организационные архивные версии не являются частью доказательства готовности. Было сказано, что размеченная часть уже существует и дополнительные negatives могут быть добавлены, но это не означает, что они появились в текущем workspace.

## Submission и методика

Доступный `submission_schema.json` задаёт labels VIOLATION_PRESENT, NO_VIOLATION, MISSING_DOCUMENT, COMPARISON_IMPOSSIBLE, базовый JSON shape и обязательные поля. Matching, FREE scope, NA/unsupported handling и правила location остаются неуточнёнными без официального scorer и регламента. Устно единица проверки описана как атомарная контрольная точка с ключом как минимум из `object_id` и `parameter_code`. До завершения проверки контракта exporter имеет статус BLOCKED_CONTRACT для официальной сдачи; diagnostic predictions JSON разрешён с явной маркировкой.

29 сентября добавлен [локальный scorer и явные правила matching](operations/LOCAL_SCORER_CONTRACT_20260929.md). Побайтовая копия схемы участников включена в проект и архив для проверяющих; локальные правила не объявлены официальными. Пустой публичный baseline проходит независимую SHA-проверку оригинальных PDF и даёт 0/10 положительных checks, не показатель качества продукта.

Сохраняются исходные object_id/file_id/parameter_code/location. Строка отображения «Помещение 012» не заменяет raw location «012». Human review не меняет frozen inference output.

Ранее указанные в документации веса 60/15/15/10 и ограничение 59 баллами **не подтверждены доступным первичным scorer/регламентом**. Они не являются действующим проектным критерием приёмки до Q-01. Не рассчитывать конкурсный балл по предположительной формуле.

Сессия подтверждает только верхний уровень: 75% техническая часть и 25% pitch/demo. В технической оценке названы функциональная полнота, OCR, F1, Precision и Recall; их точные веса не раскрыты. Публикация официального scorer/JSON validator названа вероятной, но инструмент ещё не получен и не должен считаться доступным.

## Целевые метрики ТЗ

| Метрика | Условие |
|---|---|
| OCR Character Accuracy | ≥0,95; отдельно CER/WER/coverage |
| Key-field Exact Match | ≥0,90 по зафиксированной нормализации |
| Document linking | ≥0,95 с верным объектом, стадией и актуальной редакцией |
| Evidence completeness | В ≥0,95 групп полный комплект: правильные file/page и IoU ≥0,5 |
| Detection | Precision ≥0,90; Recall ≥0,80; F1 ≥0,85 — все отдельно |
| FPR | ≤0,10 на экспертно проверенных negatives |
| Отчётность | Counts/denominators, coverage/abstention, 95% CI, срезы объектов/разделов/форматов |

При нулевом знаменателе — NOT_ESTIMABLE, не 0%/100% и не pass. Evaluation использует object-isolated frozen split, one-to-one matching и model/provider/scorer versions. Небольшое число независимых объектов ограничивает выводы CI, даже при большом числе страниц.
