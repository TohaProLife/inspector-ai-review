# Архитектура реализации всех 132 параметров

Версия 1.0. Это проектная декомпозиция исходного каталога, а не готовые правила, нормативное заключение или заявленное покрытие. Каждая строка требует atomic rule specification по [07](07_RULES_AND_EVIDENCE.md), предметного review и fixtures перед статусом IMPLEMENTED.

## Основание и общий контракт

Источник: [parameter_catalog_132.jsonl](../../datasets/reference_methodology/hackathon_gold_20260811/УЧАСТНИКАМ_БЕЗ_ОТВЕТОВ/data/parameter_catalog_132.jsonl). Коды, названия, units, source_pd/source_rd/source_id, trigger, criticality, matrix_row и mapping_status импортируются дословно в immutable matrix version. Таблица ниже добавляет проектное исполнение, не переписывает эти поля.

Каталожные пороги ссылаются на упрощённые описания норм и не универсальны для всех объектов. Q-13/14/15 определяют применимость, исключения, нормативную версию и допуски. Если они неизвестны, соответствующий subrule выдаёт clarification/abstention. Criticality из каталога определяет приоритет review, а не автоматически предписывает юридическое действие.

Профили: **N** — typed numeric/aggregate comparison; **C** — versioned category/property comparison; **P** — presence/set/inventory с полнотой области поиска; **G** — geometry/topology с координатной системой/масштабом; **A** — согласование/контекст/применимость; **E** — версионное подтверждение внешнего реестра. Сочетание профилей разбивается на atomic subrules; UI может показывать одну группу. Во всех строках действуют object/revision/approval/evidence gates из 06–07.

Числовые значения предпочтительно извлекаются из размеров, спецификаций и таблиц; измерение по pixels допустимо только с валидированной калибровкой. Геометрическое отсутствие нельзя доказывать одним неудачным OCR-поиском. Семантическая модель обнаруживает кандидата/тип, но не определяет неизвестный нормативный предел.

Минимальные fixtures каждой строки: корректное совпадение, реальное расхождение, missing source, неподходящая редакция/unknown approval, ошибочная локализация. Дополнительно N — граница/единицы/ноль; C — aliases/несопоставимые категории; P — полный и неполный inventory; G — transform/масштаб/топология; A — действующее и неприменимое согласование; E — отсутствующий/устаревший/конфликтующий registry response. Synthetic fixtures дополняют реальные, не заменяют evaluation.

## Приёмка каталога

Для каждого кода заполнить owner, atomic rule IDs/versions, applicability, required sources из исходной записи, extraction target schema, comparator/tolerance, normative policy, fixtures, implementation state и accepted release. B10 обеспечивает полный ledger, B11 — первый subset, B18 — расширение. До code+fixtures+expert review все строки остаются PLANNED, а runtime без реализации возвращает UNSUPPORTED. Покрытие таблицы 132/132 означает полноту проектной декомпозиции, не готовность движка.
