## Внутренние решения, которые не следует откладывать

Приняты: PostgreSQL как доменная истина; модульный Node API; Python workers; transactional outbox и fencing; immutable manifest/run/protocol; раздельные machine/review/sync; неизвестное approval блокирует вывод; partial coverage видно пользователю; prediction export независим от review; demo изолирован; GOLD только после curation; необоснованный confidence отсутствует. Для них внешнее согласование не требуется, если оно не меняет явный контракт ТЗ.

Перед началом B08 document lead записывает выбранный локальный renderer/OCR/layout/model provider и fallback, pinned version, model hash, license для коммерческого/государственного использования, language/profile, необходимые ресурсы и результаты B03. Внешний AI API не является допустимым fallback. Архитектура намеренно не объявляет случайную библиотеку проверенной на отсутствующем корпусе. Это ограниченный qualification gate, а не бесконечное сравнение инструментов.

## Как закрыть вопрос

Сохранить ответ/артефакт и его hash/version, дату, автора, scope применения и ссылку на официальный источник; изменить status вопроса на RESOLVED; перечислить затронутые docs/contracts/tests; оформить ADR при изменении принятого решения. Устный ответ без записи не меняет machine contract. Секреты и сертификаты в этот реестр не помещать.

## Порядок эскалации

Для старта реального анализа первым закрывать доступ к исходникам Q-06 и выбирать локальный provider profile по закрытой policy Q-05. Параллельно получать Q-01/02/04: они определяют конкурсную совместимость и не исправляются красивым интерфейсом. Q-07 необходим до утверждения протокольного шаблона. Q-10/11/12 относятся к интеграции и эксплуатации; их отсутствие не мешает реализовать локальный immutable snapshot и хакатонные mocks, но ограничивает production-поставку.
