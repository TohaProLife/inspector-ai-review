# Архитектура рабочего места

Версия 1.1. Целевой React-интерфейс; текущие демонстрационные экраны не являются проверкой этих требований. Контракты: [API](04_API_CONTRACTS.md), [review](08_REVIEW_PROTOCOL_EXPORT.md). UX-уточнения сессии — в [разборе Q&A](../HACKATHON_QA_SESSION.md).

## Слои приложения

`app` отвечает за router, session, error boundary и providers. `features` содержит objects, intake, inspection, evidence-review, protocols, catalog, administration и evaluation. `entities` содержит типизированные read models. `shared` — UI primitives, API client, viewer geometry, форматирование. Компонент не реализует правила сравнения, RBAC или финализации.

Серверные данные живут в query cache с ключами, включающими organization, inspection, run и фильтры. URL хранит выбранную проверку, очередь, фильтр, review item и страницу; локальное UI-состояние — zoom, панель и несохранённый комментарий. Session reset очищает весь query cache. Типы API генерируются из опубликованного OpenAPI; ручной второй набор enum не поддерживается.

После mutation обновляются item, inspection summary и blockers из ответа/повторного GET. Подтверждение, split и finalize не имеют оптимистического успешного состояния. Сначала сервер принимает команду; затем интерфейс показывает результат. Сетевой timeout допускает повтор с прежним Idempotency-Key, а не повторное действие с новым ключом.

## Карта экранов и ответственность

| Экран | Данные и действия | Обязательные состояния |
|---|---|---|
| Объекты | Доступные объекты, поиск, адрес, проверки | Empty, loading, access denied, unavailable |
| Новая проверка / файлы | Существующий объект, цикл проверки, формат/стадия, upload sessions | Пофайловый прогресс; AV/validation; rejected; commit pending; duplicate |
| Обработка | Реальные jobs, стадии, числа страниц, retries, gaps | QUEUED/RUNNING/PARTIAL/FAILED/CANCELLED; причины и следующее действие |
| Сводка | Coverage 132, предметные исходы, review, комплектность | Отдельные знаменатели и неполное покрытие |
| Очередь review | Atomic items и группы, риск, параметр, статус | Предварительная read-only выдача; пустая очередь; stale run |
| Evidence workspace | Оригиналы, locator, значения, версии, actions | Missing evidence, плохое OCR, конфликт редакции, третий источник |
| Протоколы | Snapshot versions, render, отзыв, sync | DRAFT/FINAL, revoked, incomplete, render failed, pending sync |
| Справочник | Исходные 132 параметра, правила и implementation status | UNSUPPORTED виден, free search отдельно |
| Администрирование | Пользователи, нормы, матрицы, audit | Draft/published, версия, причины изменения, forbidden |
| Качество / ML | GOLD queue, frozen datasets, evaluation, release approval | Labels и predictions раздельно; insufficient evaluation data |

Дозагрузка открывает intake для текущей inspection. Создание нового объекта — отдельное действие. При FINALIZED кнопка загрузки объясняет, что нужен новый цикл либо разрешённый отзыв; backend всё равно запрещает запись.

## Сводка без ложной полноты

Показывать отдельно: «132 параметра в матрице», «выполнены правила по N параметрам», «частично покрыты M», «не реализованы K», «технические ошибки L». Эти числа не обязаны суммироваться без определения взаимоисключающих групп: API возвращает отдельный partition для headline и детализацию по результатам. Подпись «проверено 132» возможна только при полном выполнении применимого набора правил.

Количество кандидатов/подтверждений относится к atomic review items, а не к параметрам: один параметр может дать много помещений. Число физических файлов, логических документов, листов и сравнений подписываются отдельно. Комплектность определяется требованиями выбранного сценария и manifest; наличие хотя бы одного файла ПД/РД/ИД не означает полный комплект.

Для первой версии сортировка очереди — criticality каталога, затем обязательность review, затем стабильный ID. Непроверенный confidence не заменяет criticality. Уверенность показывается только с названием компонента/калибровки; null отображается «не оценена», без выдуманного процента.

## Evidence viewer

Оригинал и preview связываются hash и renderer version. Для PDF поддерживаются все страницы и большие листы, fit-to-page/width, произвольный zoom, pan, rotation view, thumbnails, page input, original download, текстовый слой и bbox overlay. Изменение view rotation не изменяет сохранённые координаты evidence.

ПД, РД, ИД и согласование — именованные вкладки/панели источников. По умолчанию два источника выбранной пары, третий доступен без потери текущего review item. Синхронный zoom/pan — опциональный режим; нельзя обещать пространственное совмещение разных чертежей без registration transform. Версии, статус утверждения, дата и причина выбора видны рядом с каждым источником. Открытие альтернативной редакции явно помечается «не использована в этом выводе».

API отдаёт canonical geometry из [pipeline](06_DOCUMENT_PIPELINE.md). Клиент преобразует нормализованный bbox в viewport с учётом фактической области страницы и CSS transform. Один набор fixtures используется для backend geometry и frontend overlay: CropBox, Rotate 0/90/180/270, разные aspect ratios, масштабирование. Overlay не рисуется по размеру всей панели с полями вокруг листа.

Отсутствие элемента нельзя иллюстрировать случайным прямоугольником: viewer показывает документ/область поиска и объяснение достаточности поиска. Если locator не подтверждён, действие CONFIRM заблокировано и показан конкретный blocker. XML отображается структурированно с XPath/строками; у DOCX превью связано с версией конвертера и source locator, без выдачи номера rendered page за исходную PDF page.

Preview/tile URLs короткоживущие; обновляются после проверки доступа. Выбор следующего review item отменяет ненужные fetch, чтобы запоздавший ответ не подменял доказательство. В cache key входит source hash и rendering version. Prefetch ограничен соседними страницами, без загрузки всего комплекта в память браузера.

## Действия инспектора

Evidence header показывает параметр, сущность, expected/actual, единицы, delta/допуск, машинный статус и человеческое решение раздельно. Причины утверждения и применённая норма доступны в этом же контексте. «Подтвердить», «Отклонить», «Уточнить» открывают короткую форму обязательной причины; составная находка сначала разделяется.

Batch action допускается только для явно выбранных однородных atomic items и показывает общий reason/comment перед отправкой. Глобальной кнопки «подтвердить/отклонить всё» нет; неоднородные или составные находки обрабатываются отдельно. Backend всё равно создаёт отдельное decision event на каждый item и атомарно возвращает частичный конфликт, если fingerprint/row version изменился.

После ответа 412 сохранять введённый комментарий и показать актуальное решение другого пользователя; повтор требует осознанного обновления. После 409 stale run перейти к текущей версии с объяснением и ссылкой на историческую. Нельзя автоматически перенести неподтверждённую форму на другую evidence fingerprint.

Экран дозагрузки показывает ожидаемое влияние, затем результат нового run: новые, изменённые, сохранённые решения и основания переноса. Старый run доступен read-only. До seal нового run UI не разрешает решение по нему.

Перед finalize показываются snapshot preview, список подтверждённых atomic items, остальные исходы, coverage gaps и blockers. Для PARTIAL отдельное подтверждение перечня gaps; оно не снимает blockers evidence у подтверждённых нарушений. После финализации — номер/время/hash, доступность файлов и отдельный статус ИАИС.

## Обновления, доступность и производительность

Первый транспорт — polling активного run раз в 2 секунды, 5–15 секунд при отсутствии изменений, pause в скрытой вкладке, backoff при ошибках, ETag/304. Это проектный default, проверяемый нагрузочным тестом. SSE можно добавить позже через тот же read model; события не являются единственным способом восстановить состояние.

При 100 активных вкладках polling 2 секунды даёт около 50 запросов/с только на progress. API возвращает компактный read model; очередь и evidence загружаются отдельно с pagination/virtualization. Viewer считается отдельным performance path: тяжёлые байты идут из object storage, не через JSON summary.

Все действия доступны с клавиатуры, focus виден, modal удерживает/возвращает focus, status changes объявляются через live region, цвет дублируется текстом/иконкой. При reduced motion отключаются необязательные анимации. Формы имеют labels и текстовые ошибки; таблицы и viewer имеют доступную альтернативу с extracted values и locator.

## Приёмка

1. Реальный файл нового объекта не показывает чужие seed-находки; все evidence ведут в его manifest.
2. Пять инспекторов проходят согласованный сценарий 132 параметра / 14 отклонений; целевое время ≤30 минут, не более трёх осознанных действий от открытия карточки до сохранённого типового решения. Ввод обязательной причины учитывается отдельно; методика фиксируется до теста.
3. Проверяются два браузерных пользователя, конфликт решения, timeout и повтор, финализация при открытой вкладке второго пользователя, дозагрузка и переход к историческому протоколу.
4. Viewer проверен на всех geometry fixtures, большом листе и более чем двух страницах; совпадение bbox оценивается численно и визуально.
5. Ошибки scan, OCR, render, export и sync дают понятное следующее действие и не отображаются как успешная проверка.

Конкретные HTTP команды остаются в 04, доменные переходы — в 03: UI не создаёт альтернативную модель состояний.
