# Общие факты и первые группы правил

Срез `fact-family-pilot-v1` добавляет один контракт факта, независимую проверку
источника и общий движок сравнения для пяти кодов каталога. Это предложения
для эксперта. Ни один результат этой ветки не создаёт finding и не
подтверждает отсутствие нарушения по всему параметру.

| Группа | Коды | Извлекаемый факт | Сравнение |
| --- | --- | --- | --- |
| ПЗ | PZ-004, PZ-007 | Строительный объём здания; число надземных этажей | Различие ПД/РД |
| КР | KR-055, KR-058, KR-059 | Класс бетона; толщина фундаментной плиты; толщина плиты перекрытия | Снижение для того же элемента |

Политика закреплена в `services/worker/rules/fact-family-pilot-v1.json` и
привязана к SHA каталога из пакета участника. Извлекатели читают только
проверенный `document-text-v2` и возвращают `typed-fact-v1`: объект, стадию,
раздел исходника, SHA файла, страницу, полный исходный текст блока, точный
диапазон значения и координаты. Пустая страница, страница с плохим текстовым
слоем или неразмеченная смешанная стадия не считается доказательством
отсутствия параметра.

Движок сравнивает `Decimal`, приводит м²/м³/мм/целые значения и класс B,
проверяет текущую редакцию, утверждение, одну группу документов и явную
связь двух фактов. При неизвестных решениях, нескольких кандидатах,
неподтверждённой стадии, нулевой базе относительного сравнения или неверном
локаторе возвращается `ABSTAIN`. `REVIEW_REQUIRED` означает лишь
арифметическое предложение для сверки. Контекст из каталога — например
согласованная корректировка ПД, геометрия объёма, зона плиты и метод измерения
толщины — требует отдельного подтверждения экспертом.

Новый opt-in профиль `typed-pz002-pz017-ocr-heat-fact-family-v1` использует
`INSPECTOR_FACT_FAMILY_PROFILE=v1` вместе с
`INSPECTOR_OCR_HEAT_ROW_PROFILE=v1` и OCR layout v3. Worker читает
зафиксированные артефакты текущей попытки; API сверяет результат с теми же
неизменяемыми артефактами независимо от worker. Результат доступен в
`/api/checks/:id/pilot-results` и интерфейсе как review-only. Пять новых строк
coverage остаются `PARTIAL`; остальные коды остаются в своём фактическом
состоянии. Проверенную инспектором связь двух фактов API сохраняет как
неизменяемое решение. Следующий run фиксирует её вместе с решениями по
исходникам и передаёт в durable lease. Без актуальных утверждённых исходников,
общей группы документов и подтверждённого раздела связь отклоняется, а
сравнение остаётся `ABSTAIN`.

`GET/POST /api/checks/:id/fact-links` доступны только в области объекта.
Эксперт выбирает конкретные факты ПД и РД/ИД, открывает исходные страницы и
указывает основание соответствия элемента. POST требует права `REVIEW_DECIDE`,
CSRF и `Idempotency-Key`; повтор команды возвращает прежнее решение. Решение
не меняет завершённый run. `019_fact_entity_link_reviews.sql` хранит журнал
решений и неизменяемый снимок для следующего run. API проверяет снимок на
приёме, завершении и чтении результата независимо от worker. Синтетический
PostgreSQL сценарий проверяет запись, повтор, снимок, lease, результат Python
`REVIEW_REQUIRED` и read API. Он не является предметной валидацией на PDF.

Для воспроизводимого теста на исходных материалах `TRAIN_PUBLIC`:

```bash
uv run --no-project --with 'pdfminer.six==20260107' python \
  scripts/smoke-fact-family-public.py \
  --pdf F0106=/path/to/F0106_raw.pdf \
  --pdf F0140=/path/to/F0140_raw.pdf \
  --pdf F0144=/path/to/F0144_raw.pdf \
  --output output/fact-family-public-20260927
```

Скрипт до чтения PDF сверяет размер и SHA каждого файла с
`document_manifest.jsonl` и принимает только `TRAIN_PUBLIC / INCLUDE /
PUBLIC_TRAIN` одного объекта. Он не читает публичные ответы для формирования
результата. Файлы на homeserver лежат в
`dataset-smoke/probes/kr-slab-public-20260927/`. Результат сохраняется как
`report.json` и `result.json`; значения `ABSTAIN` и ноль findings ожидаемы,
пока редакции, утверждение и связь элементов не проверены.

Проба F0106/F0140/F0144 сверила SHA трёх PDF с открытым манифестом и
обработала 180 страниц. После регрессии на ложные подписи бетонной подготовки
и шага арматуры остались пять предложений: один KR-055 на ПД, один KR-055 и
три KR-058 на РД. Все пять правил дали `ABSTAIN`, findings `0`.
[Машинный отчёт](../../output/fact-family-public-20260927/report.json) и
[факты с локаторами](../../output/fact-family-public-20260927/result.json)
сохраняют исходные строки и причины. ПД B40 из многорядной таблицы не принят:
текущий текстовый артефакт даёт один bbox для всего блока, поэтому строку
нельзя доказуемо связать с заголовком элемента.

Первый полный durable reprocess `CHK-24F6DF14` на F0150/F0201 завершился
`FAILED` на `RULE_EVALUATION`: установленный worker-пакет искал правила в
`site-packages/rules`, тогда как Docker копировал их в `/worker/rules`.
Путь закреплён через `INSPECTOR_RULES_DIR`; новый образ отдельно загрузил
пять правил и 132 записи реестра. Этот ошибочный run остался в истории.

После исправления новый объект `OBJ-7DA53D73` из F0106 (ПД) и F0140 (РД)
создал `CHK-B210F921`: все 10 jobs завершились, check `PARTIAL`, coverage
7 `PARTIAL` и 125 `UNSUPPORTED`, findings `0`. Перед загрузкой оба исходных
PDF сверены по размеру и SHA с открытым manifest. API при чтении повторно
проверил сохранённый fact-family artifact: пять фактов, пять `ABSTAIN`, хеш
`49bedbe751c75a1802a8907f7a563adb16f215a21e9963e8f4f43cf5a9249740`.
[Сохранённый ответ API](../../output/fact-family-public-20260927/durable-pilot-results.json)
содержит точные страницы и диапазоны. В этом наборе ПД KR-055 относится к
лестнице, а РД KR-055 — к фундаменту; KR-058 имеет три значения только в РД.
Пара для положительного сравнения здесь не установлена. Новый selector
раздела исходника виден в
[браузерном smoke](../../output/fact-family-public-20260927/source-section-review-20260927.png).
Отдельный [браузерный снимок результата](../../output/fact-family-public-20260927/durable-fact-family-ui.png)
проверил все пять строк сравнения и пять ссылок на исходные страницы.

Повторить durable проверку на homeserver можно в изолированном checkout:

```bash
python3 scripts/smoke-core.py \
  --credentials-file infra/.smoke-user \
  --pdf dataset-smoke/probes/kr-slab-public-20260927/F0106_raw.pdf \
  --pdf-stage PD \
  --rd-pdf dataset-smoke/probes/kr-slab-public-20260927/F0140_raw.pdf \
  --public-manifest datasets/reference_methodology/hackathon_gold_20260811/УЧАСТНИКАМ_БЕЗ_ОТВЕТОВ/data/document_manifest.jsonl \
  --pdf-source-id F0106 --rd-source-id F0140 \
  --expected-profile FACT_FAMILY_V1 --wait-seconds 1200
```

Каждый запуск создаёт новый объект и immutable check; в smoke не передаются
закрытые ответы или `TEST_HIDDEN`.

Повторный большой run F0150/F0201 `CHK-020A7105` после исправления Docker
завершил 10/10 jobs: `PARTIAL`, 7 `PARTIAL` + 125 `UNSUPPORTED`, находок `0`.
Для новых пяти правил в этих источниках не было извлечено пригодных фактов:
пять сравнений `ABSTAIN/REQUIRED_FACT_MISSING`, хеш результата
`fd0b6ceea44aa624b72b243c73267d424be3629fab1fad42fb4c69eab9bdb270`.
[Сохранённый ответ API](../../output/fact-family-public-20260927/durable-large-pilot-results.json).
Нуль извлечённых значений относится к данному методу и проверенному run;
отсутствие параметров в документах не установлено.

После миграции 019 на изолированном homeserver пересобраны API, worker и web.
Read-only браузерный smoke на `CHK-B210F921` подтвердил пять строк правил,
пять ссылок на исходные страницы и новую форму связи; `GET /fact-links`
вернул 200 и пустой журнал. [Снимок формы](../../output/fact-family-public-20260927/fact-link-review-ui.png).
Исходные решения этого объекта остаются `UNKNOWN`, а его факты KR-055
описывают разные элементы; реальную связь не записывали. Поэтому все пять
сравнений на оригиналах остаются `ABSTAIN`, findings `0`.

Следующие группы для того же контракта перечислены в
`docs/architecture/14_PARAMETER_IMPLEMENTATION_MATRIX.md`: относительное
изменение, направленные числовые величины, упорядоченные категории и состав
обязательного набора. Добавление правила требует собственного извлекателя,
подтверждённой пары ПД/РД или ПД/ИД, независимого теста локатора и
проверенного предметного контекста. Наличие записи среди 132 кодов само по
себе не означает, что правило работает.

## Следующие проверенные наблюдения

Общий comparator теперь проверяет `INCREASE` и `RELATIVE_INCREASE` со строгим
порогом и отказом при нулевой базе. Python и независимый API verifier используют
одинаковое направление разности. Для `APARTMENT_COUNT` допустима единица
`кв.`; для других атрибутов она отвергается. Эти операторы пока не добавлены
в закреплённый набор пяти правил.

Для PZ-010 отдельный извлекатель нашёл в публичном F0101 на PDF-странице 10
итог `92 кв.`. Значение связано с подписью «Количество квартир», единицей и
колонкой «Всего» через четыре точных блока и bbox. В F0104 явного итога нет;
оба документа имеют стадию ПД, поэтому пара ПД/РД не найдена. Наблюдение не
включено в общий pipeline и не повышает coverage.

Для KR-061 отдельный извлекатель сохранил общий перечень толщин монолитных
стен F0141, PDF-страница 4: 250, 300, 400, 500, 550, 600, 700 мм.
Перечень не привязывает каждое число к ядру, шахте или пилону. Он имеет статус
`OBSERVATION_ONLY`; типизированный факт KR-061 и finding не создаются.
Оригиналы этих PDF сверены с открытым manifest по размеру и SHA-256. Для
перехода к правилам нужны точная привязка элемента и независимая пара стадий.

После миграции 019 новый реальный reprocess `CHK-B8ACC123` на F0106/F0140
завершился `PARTIAL`: 7 `PARTIAL`, 125 `UNSUPPORTED`, findings 0, пять фактов
и пять `ABSTAIN`. Хеш fact-family результата остался
`49bedbe751c75a1802a8907f7a563adb16f215a21e9963e8f4f43cf5a9249740`.
[Сохранённый ответ](../../output/fact-family-public-20260927/post-link-reprocess.json).
Это подтверждает повторяемость полного DAG после изменения журнала связей;
решений о реальной связи исходников по-прежнему нет.
