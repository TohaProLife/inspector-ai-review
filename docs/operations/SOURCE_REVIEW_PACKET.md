# Очередь ручной проверки титулов для 47 кандидатов

`source-review-packet-v1` сводит текущую матрицу источников для 47
неисполняемых правил и предложения с первых страниц открытых PDF,
включая адресный OCR титулов F0146 и F0150. Входные файлы проверяются по
закреплённым SHA-256; манифест — по SHA и инвентарю 203 документов.
Содержимое F0194 и TEST_HIDDEN не читается.

```bash
PYTHONPATH=services/worker python3 scripts/build-source-review-packet.py \
  --matrix output/public-index-20260927/candidate-source-matrix-20260927.json \
  --titles output/public-index-20260927/public-title-proposals-v2-20260927.json \
  --output output/public-index-20260927/source-review-packet-v2-20260927.json \
  --target-sources 25
```

Отчёт выбирает 20–30 источников, по умолчанию 25. Сначала идут PDF,
где буквальная марка на титуле совпала с нужной маркой и ролью правила
(`titleAlignedCodeRoleCount`). Затем выбирается по одному источнику
для каждой ещё не представленной комбинации объекта, стадии и категории
манифеста; остаток заполняется следующими по приоритету. Так очередь
не заполняется одинаковыми титулами одной группы.

Для полного обхода всех неоднозначных источников, включая титулы без подсказки,
есть отдельный режим `--all-sources` (несовместим с `--target-sources`):

```bash
PYTHONPATH=services/worker python3 scripts/build-source-review-packet.py \
  --matrix output/public-index-20260927/candidate-source-matrix-20260927.json \
  --titles output/public-index-20260927/public-title-proposals-v2-20260927.json \
  --output output/public-index-20260927/source-review-packet-all-v2-20260927.json \
  --all-sources
```

[Полный пакет](../../output/public-index-20260927/source-review-packet-all-v2-20260927.json)
содержит все 103/103 неоднозначных источника матрицы 47 кодов: 97 с
титульными подсказками и шесть с `NO_TITLE_CUE_REVIEW`. Представлены 20
групп объекта/стадии/категории, семь источников с буквальной маркой и 47
связей «титул–код–роль». SHA-256:
`b1ad972a6c268f36d88665e29a161b9eb614dbe73c8df2e05d5d5ee18fd39328`.
[Визуальный атлас 103 исходных PDF](SOURCE_REVIEW_ATLAS_20260927.md)
позволяет сверить титулы и штампы по изображениям с привязкой к SHA.
Остальные 99 PDF публичного индекса не входят в неоднозначную матрицу
источников этого пакета. Статусы всех 103 остаются `UNVERIFIED_REVIEW_ONLY`.
У шести без титульной подсказки пусты `titleLocators` и явно указана
причина отдельного просмотра: F0153, F0186, F0197–F0200.
[Визуальная проверка F0198](F0198_MIXED_STAGE_VISUAL_REVIEW_20260927.md)
показала РД-штамп и исполнительную отметку на одном листе; для этого PDF
простого выбора одной стадии на всю страницу недостаточно.
[Адресный OCR F0197–F0200](MIXED_STAGE_REGION_OCR_BATCH_20260927.md)
дал буквальные подсказки в штампах четырёх смешанных листов, но их роли
в очереди не повышены: региональное чтение остаётся отдельным заданием
для проверки. Регионы всех четырёх затем сверены с исходными изображениями;
пакет очереди остаётся прежним, без повышения source gates.

Для ручного обхода создана [таблица 103 заданий](../../output/public-index-20260927/source-review-worksheet-20260927.csv)
из закреплённого полного пакета и четырёх региональных OCR-подсказок.
Каждая строка содержит исходный SHA, путь, маркеры титула и конфликты;
четыре F0197–F0200 содержат обе региональные подсказки. Колонки
`reviewedRevision`, `reviewedApproval`, `reviewedSection` и
`evidenceReference` оставлены пустыми: таблица не является решением
инспектора и не импортируется в систему как подтверждение. Скрипт
[сборки](../../scripts/build-source-review-worksheet.py) принимает только
SHA-закреплённые отчёты. SHA-256 CSV:
`a11bbc73be71db80c78815f1d4f8b4cf4dd5b9f5dac90e369e108bbc30b7e591`.
Та же таблица скопирована в
`/home/freetok/Projects/inspector-ai-homeserver-smoke/output/public-index-20260927/`
на homeserver; повторная SHA-сверка совпала.

`codeList` перечисляет **неоднозначные связи** источника с правилами
матрицы. При `UNKNOWN_ABSTAIN` они могут быть очень широкими: например,
один PDF `PD/OTHER` входит в предварительный поиск по 47 кодам.
Это не значит, что его титул подходит всем 47. Отдельные
`titleAlignedCodeList` и `titleAlignedCodeRoleCount` считают только
буквальные марки титула, совпавшие с `requiredDrawingSections` и стадией
роли. Источники с одной лишь фразой «ПРОЕКТНАЯ ДОКУМЕНТАЦИЯ» имеют
нулевое подтверждение раздела в отчёте и остаются заданиями на просмотр.

Для каждого источника выданы роль и код, матричная группа
неоднозначности, категория и стадия манифеста, буквальные метки титула,
конфликты, текст строк и точные локаторы. У PDF-строк — страница,
блок/строка, `bboxMilliPoints` и SHA артефакта страницы. У OCR —
`bboxPx`, SHA OCR-артефакта, evidence SHA, SHA индексной страницы и
точные профили рендера/OCR.
Координаты OCR и PDF не смешиваются. Повторяющиеся строки ограничены
шестью локаторами на источник; счётчик `titleLocatorsOmitted` показывает
сокращение списка. Полный исходный титульный отчёт закреплён его SHA.

`conflictingTitleLabels` показывает, например, `RD_ID_MIXED` против
шифра `РД`, `OTHER` против `PZ`, а также ссылку «Исполнительные чертежи»
рядом с шифром `РД`. Ссылка сама по себе не определяет стадию документа.
Марка `ВВ` остаётся `VV`; пакет не приравнивает её к `ВК`.

Статус пакета — `HUMAN_REVIEW_ONLY_ABSTAIN`. Он не ставит
`SOURCE_STAGE_VERIFIED` или `DRAWING_SECTION_VERIFIED`, не создаёт
факты, пары, findings и coverage. Ручная проверка должна отдельно
установить лист, раздел, стадию, редакцию, согласование и применимость
к конкретному коду.
