# Кандидаты на замечания — демонстрация 28.09.2026

## Граница результата

`REVIEW_CANDIDATE` хранится в `RULE_EVALUATION` артефакте конкретного immutable run. Он не попадает в `findings`, не меняет `parameter_coverage` и не утверждает наличие нарушения. Официальные `ABSTAIN` и старые профили сохранены. Подсказки доступны в отдельной панели web; инспектор открывает исходный лист, оставляет подсказку для проверки либо отклоняет её. Решение имеет отдельную запись, хэш и audit event. Экспорт подсказок и решений — отдельный JSON с `officialFindingsIncluded: false`; официальный протокол открывается отдельной кнопкой.

Кандидат содержит код или семейство, точную строку, значение из строки, SHA исходного PDF и текстового артефакта, номер страницы, индекс блока и строки, координаты строки, связанную строку другого документа при наличии, неопределённости. OCR для перечисленных ниже сигналов не применялся: происхождение указано как `PDF_TEXT_LAYER`. Предполагаемая пара и возможное расхождение требуют совпадающего кода/атрибута и противоположных объявленных стадий; документы с известными противоречащими разделами или группами связи не объединяются. Общий элемент всё равно остаётся неподтверждённым. Дубли на одной странице группируются, список ограничен 12 на PDF и 96 на run.

На записи, seal и чтении API независимо пересчитывает хэши, проверяет источник в manifest, точную строку и её locator в сохранённом `document-text-v2`, допустимость семейства/метки, связанные документы, сортировку и лимиты. Старый `document-text-v2` без `lineBboxesMilliPoints` читается; новый блок может хранить точные прямоугольники строк. PDF preview ещё раз проверяет байты по SHA до рендера.

2. Открыть лист PDF и фрагмент; сверить строку и SHA источника.
