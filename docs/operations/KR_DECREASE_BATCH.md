# Пакет наблюдений КР-061/062

`scripts/evaluate-public-kr-decrease-batch.py` читает готовый индекс разрешённых
`TRAIN_PUBLIC / INCLUDE / PUBLIC_TRAIN` документов. Перед запуском требуется
JSON из `audit-public-document-index.py` со статусом `PASS`. Команда сверяет
SHA всего манифеста, версию индекса, все 203 источника, 202 завершённых PDF,
10 142 проиндексированные страницы, один пропущенный `F0194` TXT-инвентарь,
10 142 артефакта страниц и адреса FTS. В CLI эти числа изменить нельзя.

```bash
python3 scripts/audit-public-document-index.py \
  --manifest datasets/reference_methodology/hackathon_gold_20260811/УЧАСТНИКАМ_БЕЗ_ОТВЕТОВ/data/document_manifest.jsonl \
  --output /data/index > /data/index-audit.json

python3 scripts/evaluate-public-kr-decrease-batch.py \
  --manifest datasets/reference_methodology/hackathon_gold_20260811/УЧАСТНИКАМ_БЕЗ_ОТВЕТОВ/data/document_manifest.jsonl \
  --index /data/index --audit /data/index-audit.json \
  --output /data/kr-decrease-review.json
```

По умолчанию поиск ограничен десятью публичными кандидатами КР:
ПД `F0105–F0107`, РД `F0136, F0139–F0144`. Страницы выбираются через
`public_family_batch`: FTS служит только поиском, затем точные блоки
сверяются с SHA страницы и манифестом. Извлекатель принимает лишь строку,
где вместе указаны зона, этаж, однозначный элемент, роль измерения и значение
в мм. Две конкурирующие величины, неполный контекст и ложный текстовый
совпадение дают `ABSTAIN`. Ни ячейки таблицы, ни разнесённые строки
автоматически не склеиваются.

Отчёт содержит по каждой выбранной странице результаты для `KR-061` и
`KR-062`, точные SHA источника, артефакта и evidence, версию и парсер,
номера блоков, локаторы кандидатных фактов. Счётчики `candidatePages` и
`abstainPages` агрегируются по файлу, стадии и всей пачке. `ocrQueue`
указывает страницы, требующие адресного OCR. `truncated` и
`omittedTextPages` показывают пропуски из-за лимитов. По умолчанию
`maxPages=40`, `maxBlocksPerPage=4`, `maxOcrPages=100`.

Этот результат предназначен **только для проверки**. `findingCount` и
`parameterCoverage` равны `null`. Даже кандидат на странице не означает
совпадение элементов ПД и РД: проверка редакции, раздела на чертеже,
согласования и связи элементов ещё не выполнена. `ABSTAIN` не доказывает
отсутствие значения: поиск и OCR могут быть неполными. Перед подключением
сквозного правила нужна проверка этих наблюдений на исходных публичных PDF.

Локальный тест строит синтетические PDF, индекс и полный `PASS`-аудит,
проверяет положительные строки, ложное совпадение, усечение и отказ при
неполном аудите либо изменённом манифесте:

```bash
PYTHONPATH=services/worker uv run --no-project \
  --with 'pdfminer.six==20260107' --with 'PyMuPDF==1.27.2.2' \
  python -m unittest services.worker.tests.test_kr_decrease_batch -v
```

## Реальная пачка, 27 сентября 2026

После `PASS`-аудита выполнен запуск на десяти исходных PDF с лимитами
`maxPages=100`, `maxBlocksPerPage=8`, `maxOcrPages=500`. Для обоих кодов:
0 страниц с квалифицированным кандидатом, 100 `ABSTAIN`. Из-за лимита
пропущена часть текстовых страниц и совпадающих блоков; очередь OCR —
44 страницы. [Постраничный отчёт](../../output/public-index-20260927/kr-decrease-batch.json)
имеет SHA-256
`d37c5393d8e93359aa4f734ed5b7563df8270028d588eaf20ebfc693f9374139`.

Причина воздержания видна на оригиналах: ПД F0106 p.52 перечисляет четыре
толщины стен надземных частей корпусов без однозначного элемента; РД F0141
p.4 перечисляет семь толщин монолитных стен без соответствия конкретному
элементу ПД. Эти перечни нельзя попарно сравнить по KR-061. Отсутствие
кандидата в этой ограниченной пачке не является отрицательным результатом.

Дополнительно разделение запуска на ПД и РД устранило лимит страниц поиска:
проверены все 93 текстовые страницы с совпадениями ПД и 88 РД. На каждой
стадии оба кода остались `ABSTAIN`; лимит восьми блоков на странице ещё
оставляет усечение. Отчёты: [ПД](../../output/public-index-20260927/kr-decrease-pd.json)
и [РД](../../output/public-index-20260927/kr-decrease-rd.json).
Отдельная [проверка всех 521 страниц](KR_DECREASE_FAMILY.md) просмотрела
исходные строки десяти PDF после сверки SHA каждого артефакта: 44 страницы
требуют OCR, а остальные не содержат однозначной связки элемента, зоны,
этажа и размера для KR-061/062.
