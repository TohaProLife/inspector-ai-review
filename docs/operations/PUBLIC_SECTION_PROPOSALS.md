# Предложения разделов по открытому индексу

Отчёт `public-section-proposals-v1` ищет **явные** обозначения разделов и
марок (`АР`, `КР`, `КЖ`, `ОВ`, `ВК` и другие обозначения из пакета 47
кандидатов) в `sectionCandidates` готового индекса. Он предназначен для 44
кодов, у которых в текущем открытом манифесте нет пары ПД/РД с точными
категориями разделов внутри одного объекта. Три кода KR-061/062/067 уже
имеют такую предварительную пару и идут отдельными пакетами.
Обозначение должно быть отдельным токеном в верхнем регистре: подписи
элементов вроде `Кр-10` не считаются разделом `КР`.

Запуск требует JSON-отчёт полного аудита со статусом `PASS`, нулём ошибок,
совпадающими SHA-256 открытого манифеста и версией индекса, 203 источниками,
202 завершёнными PDF и 10 142 проверенными страницами. Манифест закреплён
SHA-256. Скрипт открывает только PDF-страницы со стадией `PD`, `RD` или
`RD_ID_MIXED` и уже найденными кандидатами разделов. F0194 остаётся
метаданными; содержимое TXT и TEST_HIDDEN не читается.

```bash
PYTHONPATH=services/worker python3 scripts/build-public-section-proposals.py \
  --index /path/to/public-index \
  --audit /path/to/index-audit.json \
  --output output/public-section-proposals.json \
  --max-pages 300 --max-proposals 500
```

Каждое предложение содержит ID и SHA документа, номер страницы, SHA
артефакта страницы, исходную строку до 200 символов, bbox, явные марки и
возможные коды кандидатов. `possibleParameterCodes` означает только
совпадение роли источника и обозначения на строке, а не извлечённое значение.
Отчёт отмечает несколько марок в строке, конфликт с категорией манифеста,
`OTHER`, смешанную стадию и страницы `OCR_REQUIRED`.

Лимиты: максимум 500 страниц с кандидатами и 1000 предложений за запуск.
Обычный запуск ограничен 300 страницами и 500 предложениями. Поля
`candidatePagesOmitted` и `proposalsOmittedWithinScannedPages` показывают
урезание; отсутствие предложения при урезании или низком качестве текста не
означает отсутствие раздела. Для следующего шага нужны проверка человеком
обозначения и стадии листа, адресный OCR при необходимости, затем извлечение
фактов и сопоставление по семейству.

Отчёт всегда `REVIEW_ONLY_ABSTAIN`: он не меняет манифест, индекс,
классификацию источника, findings или coverage. При несоответствии аудита,
манифеста, индекса либо артефакта выбранной страницы работа прекращается.

## Реальный прогон 27.09.2026

На homeserver полный аудит индекса имел `PASS`; отчёт сохранён в
`/mnt/edberries-backup-disk/inspector-ai-dataset-20260924/family-batches/public-section-proposals-20260927.json`
с SHA-256
`07926b4ef7ed92fedae8d08c1901f0648d7d993b0d3549ad03d36b12f5d18b37`.
Проверены все 344 страницы с `sectionCandidates` из ПД, РД и смешанной
стадии, без обрезания. Получено 80 предложений из 76 источников: 79 в ПД,
1 в `RD_ID_MIXED`, 0 в подтверждённой РД. Из 44 целевых кодов явные строки
указывают на 21 код, но ни для одного пока нет предложений на обеих сторонах
ПД/РД. 53 предложения имеют несколько обозначений в строке, 48 конфликтуют
с грубой категорией манифеста; они требуют ручной проверки. Пример повторной
строки `ЭОМ СС СССС` показывает, почему её нельзя автоматически принять за
раздел документа. Нулевое число предложений в РД относится только к
`sectionCandidates` текстового индекса; оно не доказывает отсутствия
разделов или нужных фактов на листах.

Проверка на синтетических PDF:

```bash
PYTHONPATH=services/worker uv run --no-project \
  --with 'pdfminer.six==20260107' --with 'PyMuPDF==1.27.2.2' \
  python -m unittest services.worker.tests.test_public_section_proposals -v
```
