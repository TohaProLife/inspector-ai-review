# Три публичных примера без входа

**Текущий Compose:** `INSPECTOR_OPEN_WORKSPACE=1` открывает рабочее место без логина и пароля. Просмотр, загрузка и решения доступны в одном браузерном контуре. Три исходных PDF не добавляются автоматически: выполните подготовку ниже. Старый маршрут `/api/auth/public-visitor` оставлен для прежних изолированных стендов; текущий web вызывает `/api/auth/open-workspace`.

## Исходные PDF

Скрипт [`prepare-public-review-examples.py`](../../scripts/prepare-public-review-examples.py) сверяет статус каждого PDF с открытым manifest (`TRAIN_PUBLIC/INCLUDE/PUBLIC_TRAIN`), размер и SHA-256 байтов перед загрузкой. Оригиналы не включены в публичный репозиторий. Получите F0101.pdf, F0142.pdf и F0147.pdf из конкурсного пакета и положите их в отдельную папку, указанную через `--pdf-dir`.

| F0101 | ПД | `01db90e015c39a9502b99969ce04f27825265203bc8728da6141d7b6d2b1ef54` | 6 |
| F0142 | РД | `43b1595f8cf21e5d5e5af5d31aa42314c3c889e873a67a549d343597d74ab6cb` | 3 |

Подсказки показывают сигналы в отдельных документах. Они не объявляют сопоставимость ПД/РД, подтверждённое расхождение или нарушение. Число кандидатов зависит от запущенного профиля и может отличаться на другом стенде.

## Подготовка после первого запуска Compose

В корне проекта после запуска Compose:

```bash
python3 scripts/prepare-public-review-examples.py \
  --base-url http://127.0.0.1:4100 \
  --pdf-dir /path/to/approved-pdf \
  --env-file infra/.env.server \
  --receipt output/public-review-examples.json
./infra/stack.sh server up -d --no-deps api
curl -fsS http://127.0.0.1:4100/api/health
```

Если у стенда другие `API_PORT` или `INSPECTOR_ENV_FILE`, укажите фактический loopback URL и тот же env-файл в обеих командах. Скрипт идемпотентно использует объект с точным именем, исходным SHA и стадией; не добавляет документы в неверный объект. Переменная с тремя ID записывается атомарно только после проверки всех трёх immutable runs. Повторный `up` переносит разрешённый список в API; объекты и артефакты остаются в PostgreSQL/MinIO volume. На новом стенде с пустыми volume шаг подготовки надо выполнить снова. На H100 перед этим пройти [конкурсный профиль и runtime smoke](COMPETITION_H100_LAUNCH.md); результаты homeserver не заменяют H100 проверку.

## Фактическая репетиция на homeserver, 29.09.2026

В изолированном Compose `inspector-ai-review-candidates` скрипт создал/проверил объекты `OBJ-EFE63E3C`, `OBJ-1B808CFB`, `OBJ-F83AAEE2` и immutable runs `CHK-9C3B400C`, `CHK-780DA47E`, `CHK-8956A495`. Проверка гостевой сессией подтвердила: в `/api/objects` ровно эти три объекта; артефакты содержат 6, 3 и 2 кандидата с исходными SHA; PNG исходной страницы читается; `canReview=false`; POST создания объекта даёт 403; чужой объект `OBJ-587AD33E` не доступен (404). Receipt сохранены на стенде в `output/public-review-examples-20260929.json` и `output/public-review-visitor-smoke-20260929.json`.

Браузерная репетиция: обновление страницы → «Открыть кабинет» → три публичных примера без ввода пароля → открыть проверку → кандидата → исходный лист. После обновления страницы список остаётся доступным. На экране с 17 кандидатами отдельный левый внутренний скролл удалён: у списка `overflow-y: visible`, все 17 карточек в высоте страницы, последняя карточка выбирается.

Для рабочего просмотра через SSH-туннель: `ssh -N -L 28081:127.0.0.1:28081 homeserver`, затем открыть `http://127.0.0.1:28081/`. На обновлённом Compose просмотр и редактирование доступны без логина. Описанная выше репетиция гостевой сессии относится к предыдущему состоянию стенда.
