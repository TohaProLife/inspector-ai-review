# Пакетная реализация семейств параметров

Основа: реестр `parameter-family-registry-v1.json` сверяет все 132 кода с
каталогом. Среди них 47 `GENERIC_CANDIDATE` относятся к девяти семействам.
Этот статус означает проектный кандидат, а не исполняемое правило или
подтверждённое покрытие. В открытых `public_train_checks.jsonl` нет ни одной
метки для этих 47 кодов.

## Порядок

1. Построить один возобновляемый индекс 203 разрешённых файлов: 202 PDF на
   10 142 страницах и один TXT только как метаданные. Каждая страница хранит
   исходные блоки, координаты, качество чтения и кандидаты таблиц/разделов.
   Текстовый артефакт production не расширять: его лимит 8 MiB и контракт
   остаются отдельными. OCR вызывать лишь для выбранных страниц и кешировать
   по SHA документа, странице, DPI и точным профилям рендера и модели.
2. Первой пачкой проверить `DECREASE`: KR-061 и KR-062 для объекта
   `OBJ-NOVOSLOBODSKAYA`. Кандидаты исходников по открытому manifest:
   ПД/КР F0105–F0107, РД/КР F0136 и F0139–F0144. Из индекса найти страницы,
   извлечь значения с точным локатором и проверить каждый исходник по SHA.
   Сопоставление допустимо только для того же элемента, зоны, этажа и типа
   измерения при проверенных редакции, согласовании и связи фактов.
3. Следом проверить `RELATIVE_DELTA` для KR-067, разделив объём бетона и массу
   стали на два атомарных атрибута; потом расширять остальные коды семейства.
   Для каждой пачки сохранять список исходников, страниц, извлечённых
   наблюдений, `ABSTAIN` и ложных совпадений. Сквозной профиль расширять лишь
   после проверки семьи на исходных PDF.

Действующий scalar comparator поддерживает `DIFFERENT`, `DECREASE`,
`CLASS_DECREASE` только для класса бетона, `INCREASE`, `RELATIVE_DELTA` и
`RELATIVE_INCREASE`; единицы пока ограничены m², m³, мм, целыми и B_CLASS.
Остальные порядки классов требуют версионированных шкал. Например,
PPM-103 требует разбор EI/E/I, а не числовой порядок B_CLASS.
`LOWER_BOUND`/`UPPER_BOUND` требуют проверки применимой нормы и геометрии;
`PRESENCE_SET` требует доказанной полноты перечня и области поиска.
Наличие текста или одинаковой метки в двух файлах само по себе не образует
пару. При недоказанной стадии смешанного РД/ИД, редакции, связи элемента или
качестве чтения результат остаётся `ABSTAIN`.
