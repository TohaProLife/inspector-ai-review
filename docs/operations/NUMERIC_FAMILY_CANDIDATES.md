# Числовые кандидаты из публичного индекса

`numeric_family_candidates.py` обрабатывает **31 числовой код и 35 атомарных
атрибутов** из 47 правил-кандидатов. Список буквальных подписей и единиц:
`services/worker/rules/numeric-family-labels-v1.json`. Файл сверяется с SHA
каталога, SHA пакета правил, именами параметров, семействами, полным набором
кодов и атрибутов. Пропуск, лишний код или неверная единица останавливают
извлечение.

После полного прохода публичного корпуса в словарь добавлены три форматных
алиаса. `verifiedAliasEvidence` фиксирует четыре исходные строки, адреса,
SHA источников и страниц: площадь с `S=`/`кв.м` (F0201/F0202, стр. 14),
высота с `h=` (F0106, стр. 63), объём выемки с уточнением «геометрический»
(F0145, стр. 4). У этих файлов стадия или конкретный раздел для данного
кода не подтверждены. Алиасы помогают распознать форму строки, но не делают
эти четыре строки допустимыми фактами ПД/РД.
Адресный повторный прогон четырёх страниц подтвердил 4 точных разбора и
4 SHA-адреса строк; полный отчёт и SHA приведены в
`docs/operations/NUMERIC_LABEL_PROBE.md`.

Вход `extract_indexed_numeric_family_candidates(...)` адресует один PDF и
одну страницу по публичному манифесту. `load_indexed_page_evidence` проверяет
`TRAIN_PUBLIC/INCLUDE/PUBLIC_TRAIN`, SHA источника и артефакта страницы,
полноту индекса, качество текстового слоя и координаты выбранных блоков.
Страницы `OCR_REQUIRED` идут по отдельному адресному OCR-маршруту.

Извлечение допускает только отдельную физическую строку вида
`<точная подпись>: <одно неотрицательное число> <разрешённая единица>`.
Подпись берётся из JSON буквально; свободный поиск по похожему тексту и
догадка о единице отсутствуют. Несколько чисел в одной строке, иная единица
или две строки с одним атрибутом на выбранной странице дают пустой результат
для атрибута. Отдельный адресный разборщик таблиц проверяет точные подпись,
единицу и число в соседних колонках; он возвращает только review-only
наблюдение. Его полный FTS-проход и ограничения описаны в
`NUMERIC_TABLE_ROW_CANDIDATES.md`. Многоэлементные ведомости и графические
размеры не превращаются в значения автоматически.

Стадия, раздел манифеста и марка чертежа проверяются по конкретному правилу.
Если марка отличается от категории манифеста (например, `KJ` внутри `KR`),
нужно отдельное подтверждение марки, привязанное к SHA источника и
манифеста.
Для категории манифеста `UNKNOWN_ABSTAIN` требуется отдельное подтверждение
раздела с `sourceFileId`, SHA источника и манифеста, стадией, категорией,
маркой и ссылкой на проверку. Передать произвольный `OTHER` как конкретный
раздел нельзя.

Выход содержит исходные число и единицу, текст строки, координаты, SHA
источника/страницы/доказательства, код, семейство, атрибут и SHA пакетов.
Статус всегда `CANDIDATE`, политика `NON_EXECUTING_ABSTAIN`. Этот слой не
устанавливает элемент, редакцию, связь ПД/РД, применимость нормы, итоговое
расхождение, finding или coverage. `POS-086` требует особой базы сравнения
(вместимость бытового городка); наличие числа персонала этого не доказывает.
Композиты `KR-067`, `SPZU-024`, `POS-088` остаются набором отдельных
кандидатов, без автоматического суммирования.

Тесты проверяют полноту всех 35 атрибутов, буквальное извлечение, неверные
единицы, многозначность, стадии/разделы, SHA доказательства, отказ при
изменении политики и проход через реальный публичный индекс на PDF:

```bash
PYTHONPATH=services/worker uv run --no-project \
  --with 'pdfminer.six==20260107' --with 'PyMuPDF==1.27.2.2' \
  python -m unittest services.worker.tests.test_numeric_family_candidates -q
```

Полный проход первого словаря дал 0 точных строк на 8668 читаемых страницах;
адресные примеры выше выявили непокрытые варианты записи. Повторный полный
проход после добавления проверенных алиасов дал 4 точных строки. Нулевой
выход или пропущенная табличная строка означает непокрытый формат, а не
отсутствие параметра. Дальнейшее продвижение требует адресного OCR,
проверки определения величины и пригодности источника для конкретного кода.
