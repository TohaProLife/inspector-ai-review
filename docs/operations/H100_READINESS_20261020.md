# H100: подготовка по замечаниям проверяющих, 20.10.2026

H100 недоступен по сообщению пользователя; homeserver — другой стенд. GPU-контейнеры и модельные веса на H100 не запускались. Локально проверены настоящий Compose, исходники, модельные lock-файлы, контексты сборки, HTTP-ответчик и собранные CPU-контейнеры API/worker/web. Полный переносимый тестовый набор прошёл; аппаратная CUDA-приёмка остаётся отдельной.

Исходные замечания: полное извлечение `output/matrix-t45-20261018/research-feedback-original.txt` из «ИИ Друны», 11 страниц. Исходный файл по ранее указанному пути Downloads сейчас отсутствует. Сводка прежней приёмки: [CASE_FEEDBACK_20261017.md](CASE_FEEDBACK_20261017.md); её фраза «H100 не используется» описывает прежний стенд, а не нынешнее требование.

## Что исправлено для H100

Старый `stack.sh server` включает только base+server; `server.env.example` по умолчанию выбирает SCAFFOLD/V4, а старый competition guard требует V6. Эти команды сами по себе не включают актуальный инженерный и визуальный профиль.

Простой выбор V8 на H100 тоже ошибочен: immutable V8 закреплён за 4B-моделью и `visual-vlm:8080`, тогда как server обслуживает другую, закреплённую 8B FP8-модель через `vlm:8000`. Добавлен отдельный immutable V9, сохраняющий V6 provenance/неотрицательную семантику и V8 context-v2/display-crop2048. V1–V8 и их hashes сохранены.

## Исходники и контексты сборки

Актуальный Git source ZIP содержит `package.json`, `infra/` и `services/` прямо в корне. Все команды этого документа выполнять из этого корня. Проверить `SOURCE_REVISION.txt` и `sha256sum -c SHA256SUMS`. Дополнительные карты старого рабочего места или API overlays не требуются. [Текущая передача](FINAL_HANDOFF_20261020.md). Для полного source audit V4 добавьте последним `infra/docker-compose.source-audit-v4.yml`: он меняет ресурсы API/document-worker, сохраняя V9 и модели.

Git-пакет уже включает API/web/worker, миграции и V9 в обычных `apps/`, `services/`, `infra/`. Имена финальных архивов не меняют immutable инженерный V13. Новый PPM-113 atom не включён. Старый V9 review ZIP с каталогом `source/`, `source-map1095.json` и отдельными overlay-картами сохранён как историческая квитанция; его инструкции материализации к актуальному source ZIP не применять.

Контексты model-store, document-ai, text-inference и gpu-admission включают Dockerfile, `.dockerignore`, все COPY-исходники, `locks/server.json` и `profiles/server.json`; embedding строится target `cpu`. Root `.dockerignore` исключает `output/`; production build использует уже включённые `apps/...`. Старый `audit-source-context.py` с картой1095 проверяет исторический пакет; целостность актуального архива задают его собственные SHA256SUMS и SOURCE_REVISION.

API выбирает MATRIX/visual release; worker получает immutable профиль из lease. Endpoint каждого worker зависит от роли: document/extract — локальный document-ai, extract — `http://vlm:8000/v1` и 8B alias, link — CPU embedding. API-only selectors не дублируются во всех worker.

MATRIX branch сохраняет собственный bounded OCR V2; env `INSPECTOR_OCR_LAYOUT_SELECTION_PROFILE=v4` не превращает его в полный OCR. V9 FULL относится к визуальному детектору, а не к OCR-покрытию всех страниц.

## Проверить локально без H100

Из корня актуального source ZIP. Для полного тестового набора нужны Node/npm, Python 3.12 или 3.13 и тестовые библиотеки. Изолированная подготовка:

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -e ./services/worker \
  -r scripts/requirements-tests.txt -r scripts/requirements-local-scorer.txt
export PYTHON_BIN="$PWD/.venv/bin/python"
export PATH="$PWD/.venv/bin:$PATH"
npm ci --ignore-scripts
npm run typecheck
npm run test -w @inspector-ai/api -- --testTimeout=30000
npm run test -w @inspector-ai/web
npm run test:python
npm run build
```

`pdfminer.six` закреплён в worker pyproject на `20260107`; другие версии не соответствуют immutable профилю. Исторические тесты настоящих PDF/архивных runtime требуют внешних оригиналов и явно пропускаются только при отсутствии prerequisite. Тест настоящего wheel/sdist временно устанавливает hatchling через pip; нужен доступ к Python package index либо предварительно подготовленный pip wheel cache. Он не запускает CUDA.

Быстрые отдельные проверки без H100:

```bash
python3 -m unittest discover -s infra/tests -v
PYTHONPATH=services/worker:services/worker/tests python3 -m unittest \
  test_visual_proposal_v9_h100 test_visual_proposal_adapter \
  test_visual_vlm test_feedback_modes test_visual_crop_v8 -v
PYTHONPATH=services/model-store python3 -m unittest discover -s services/model-store/tests -v
PYTHONPATH=services/document-ai python3 -m unittest discover -s services/document-ai/tests -v
python3 -m unittest discover -s services/gpu-admission/tests -v
python3 -m unittest discover -s services/text-inference/tests -v
```

В комплект входит переносимый `scripts/check-h100-offline-compose.py`. Он создаёт временный env0600, разрешает настоящий Compose для SAMPLE/FULL, проверяет отказ для SCAFFOLD, V6 и несовпадения режима, сверяет native RabbitMQ healthcheck. Секреты и полный resolved env не сохраняет; контейнеры не запускает:

```bash
python3 scripts/check-h100-offline-compose.py --output-dir output/h100-offline-compose
```

Целостность source ZIP проверять `sha256sum -c SHA256SUMS` рядом с `package.json`. Реальные PDF и сохранённые OCR bundles находятся в отдельном companion; для поднятия сервисов исторические `output/` автора не нужны. SHA архива и точная версия кода находятся во внешнем manifest комплекта.

## Подготовить env и явный запуск проверяющими

Следующие действия на H100 здесь **не выполнялись**. Выполнять в согласованном стенде из принятого пакета. `init` создаёт отдельный env со случайными секретами и не запускает контейнеры:

```bash
export INSPECTOR_ENV_FILE="$PWD/infra/.env.h100"
./infra/stack.sh server init
python3 - "$INSPECTOR_ENV_FILE" <<'PY'
from pathlib import Path
import sys
p = Path(sys.argv[1])
settings = {
    'INSPECTOR_ANALYSIS_PROFILE': 'MATRIX_V1',
    'INSPECTOR_VISUAL_PROFILE': 'V9_SAMPLE',
    'INSPECTOR_OCR_LAYOUT_SELECTION_PROFILE': 'v4',
    'INSPECTOR_OCR_HEAT_ROW_PROFILE': 'v1',
    'INSPECTOR_FACT_FAMILY_PROFILE': 'v1',
    'INSPECTOR_CANDIDATE_FAMILY_PREVIEW_PROFILE': 'v1',
    'INSPECTOR_CANDIDATE_FAMILY_OBSERVATIONS_PROFILE': 'v1',
    'SERVER_GPU_DEVICE': '0',
}
lines = [line for line in p.read_text().splitlines() if line.partition('=')[0] not in settings]
p.write_text('\n'.join(lines + [f'{k}={v}' for k,v in settings.items()]) + '\n')
p.chmod(0o600)
PY
python3 infra/h100-readiness.py --matrix-v13 --visual-mode SAMPLE \
  --env-file "$INSPECTOR_ENV_FILE" --receipt h100-config.json
```

Не использовать одиночный `stack.sh server up`: он не добавляет новые overlays. Сначала обычный аппаратный preflight, затем тот же набор Compose для config/build/up/ps/exec:

```bash
INSPECTOR_PREFLIGHT_GPU_DEVICE=0 ./infra/preflight.sh server
docker compose --project-name inspector-ai-server --env-file "$INSPECTOR_ENV_FILE" \
  -f infra/docker-compose.yml -f infra/docker-compose.server.yml \
  -f infra/docker-compose.matrix-v13.yml -f infra/docker-compose.h100-feedback.yml \
  --profile server config --quiet
```

После проверки package/source manifest и выделенного GPU проверяющие запускают тот же префикс с `up -d --build`. Это может скачать container images, Qwen веса из lock и Paddle модели через отдельную provisioning network; такая загрузка не выполнялась при подготовке. Cache следует заранее перенести/проверить, если стенд не имеет разрешённого download-доступа. Повторный runtime не должен требовать внешнего model provider.

FULL включается явным выбором анализа в рабочем месте или запросом `POST /api/objects/<objectId>/checks` с `{"analysisMode":"FULL"}` в аутентифицированной сессии с CSRF. SAMPLE использует `{"analysisMode":"SAMPLE"}`. После запуска проверить `mode=NORMAL` и сохранённый release slot `red-vector-proposals-v9-full`/`...-sample`, adapter9 и точный config hash. Название env и HTTP200 сами по себе этого не доказывают. Для отдельной проверки FULL-конфигурации задать в env `INSPECTOR_VISUAL_PROFILE=V9_FULL` и вызвать guard с `--visual-mode FULL`; тихий V6/SCAFFOLD fallback отклоняется.

## Аппаратная и provider-приёмка на целевом H100

`h100-readiness.py --mode runtime` требует точный hostname, назначенный физический GPU UUID и заранее согласованный SHA256 Paddle cache manifest. Без них завершается до Docker/HTTP. Он проверяет обе GPU-службы: NVIDIA H100, не менее 78000 MiB, compute9.0, тот же UUID; затем torch CUDA count1/BF16 и Paddle CUDA/FP32 умножение16×16. Проверка памяти без модели GPU недостаточна. Driver version сохранять в диагностике; универсальный минимум по неизвестному CUDA внутри pinned vLLM здесь не выдуман.

```bash
python3 infra/h100-readiness.py --matrix-v13 --visual-mode SAMPLE \
  --mode runtime --env-file "$INSPECTOR_ENV_FILE" \
  --expected-hostname '<assigned-hostname>' --expected-gpu-uuid '<GPU-uuid>' \
  --paddle-manifest-sha256 '<approved-64-hex-sha256>' --receipt h100-runtime.json
```

Runtime проверяет весь Qwen inventory/размеры/SHA, согласованный Paddle manifest и его файлы, read-only caches, offline env, один internal network у каждого provider, фактические VLM model args, `/health`, VLM model alias, API/web health, RabbitMQ ping и consumers у `rules.evaluate`, `documents.render`, `documents.extract`, `documents.link`. Задания в очередь не публикует.

`--mode inference` добавляет одностраничный синтетический PDF SMOKE123, render150dpi, OCR eslav/latin, один image VLM запрос с max_tokens16 и embedding1024. Проверяются schema/profile/model aliases, непустой OCR, конечные числа embedding. Это проверка работоспособности provider; правильность реальной инженерной пары и reviewer UI проверяются отдельно. Порты по умолчанию API4100/web8080/document8090/VLM8101/embedding8102; при изменении env передать соответствующие `--*-port`.

## Весовые артефакты, ресурсы, ограничения

Qwen lock SHA `e2586e16f45deee017935d4c60b550e48059fdc02cbc9c9114053f2f1fe4d879`: Apache-2.0, Qwen3-VL-8B-Instruct-FP8 revision `9cdc6310a8cb770ce18efaf4e9935334512aee45`; embedding0.6B revision `97b0c614be4d77ee51c0cef4e5f07c00f9eb65b3`. Lock содержит точные artifact sizes/SHA. Paddle cache manifest сейчас first-download trust, а не опубликованные upstream SHA каждого веса: нужен внешний approval его фактического SHA, иначе runtime gate закрыт.

VLM: max_model_len8192, max_num_seqs2, GPU fraction0.35, host memory48g. Paddle: fraction0.10, max one loaded pipeline, memory32g/shm8g. CPU embedding: batch8/maxitems32, memory8g/shm1g. GPU admission: budget30GiB+10GiB при fraction0.85. Существующий server preflight требует Linuxx86_64, Docker24+, Compose2.30+, NVIDIA runtime, RAM240GiB и свободный диск150GiB. Limits не являются измеренным пиком H100; CPU quotas отдельно не заданы.

Зависимости startup не образуют cycle: model/cache admission и provisioning предшествуют VLM; document-ai ждёт healthy VLM; embedding — healthy document-ai. Первое выполнение Paddle provisioning всё равно требует реальной проверки на стенде.

Официальные опоры: [vLLM FP8/Hopper](https://docs.vllm.ai/en/latest/features/quantization/fp8/), [CUDA12.6 release notes](https://docs.nvidia.com/cuda/archive/12.6.0/cuda-toolkit-release-notes/index.html), [закреплённый Paddle CUDA12.6 image](https://hub.docker.com/layers/paddlepaddle/paddle/3.2.1-gpu-cuda12.6-cudnn9.5/images/sha256-04faf6b3573cd166e2a345eae072d3e58a4d257db6900eb2b428ab9389e56e72). Наличие поддержки FP8 не заменяет запуск pinned образов и маленький CUDA kernel.

Что проверить на H100: package hashes, V9 saved release, health/queue receipt, provider inference receipt, полный рабочий сценарий карточки с исходниками и историей. Сейчас эти аппаратные/сквозные пункты не приняты.
