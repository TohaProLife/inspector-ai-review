# Пачка восьми неразрешённых параметров КР

`KR-054`, `KR-056`, `KR-057`, `KR-060`, `KR-063`, `KR-064`, `KR-065`,
`KR-066` получили общий **диагностический** проход по открытым источникам.
Этот проход не меняет их статус `UNRESOLVED`, не создаёт факты, finding или
coverage. Определения семейств взяты из
[`unresolved-parameter-strategy-v1.json`](unresolved-parameter-strategy-v1.json)
с проверкой SHA каталога и реестра правил.

## Вход и метод

- Только десять PDF объекта `OBJ-NOVOSLOBODSKAYA` с признаками
  `TRAIN_PUBLIC / INCLUDE / PUBLIC_TRAIN`: ПД/КР `F0105–F0107` и РД/КР
  `F0136, F0139–F0144`. Источник F0194 — лишь TXT-инвентарь, его содержимое
  не читается. В выбранной пачке нет источника ИД, поэтому доказать
  соответствие исполнительной документации нельзя.
- Требуется полный `PASS`-аудит открытого индекса: 203 источника, 202 PDF,
  10 142 страницы и совпадение SHA манифеста/версии индекса. Для выбранных
  десяти PDF дополнительно сверяются объект, стадия, раздел, SHA, размер,
  полный набор страниц. Каждая страница читается из кеша с повторной
  проверкой SHA артефакта и FTS.
- Все текстовые строки проходят восемь узких поисковых шаблонов.
  `CO_LOCATED_TERMS` означает только два разных термина в **одной строке**;
  `ANCHOR_ONLY` — один термин. Счётчики сохраняются полностью, а в отчёте
  показано максимум 40 примеров на код с приоритетом точных сочетаний и
  разнообразия источников/страниц. `omittedLeads` явно показывает усечение
  примеров. Отсутствие поискового совпадения не означает отсутствия элемента.
- `OCR_REQUIRED` не сканируется как текст: адрес, SHA файла и страницы
  записываются в отдельную очередь со статусом `UNKNOWN`. Ранее сделанный
  OCR другого семейства не превращается здесь в отрицательный результат.

Воспроизведение при доступном индексе:

```bash
PYTHONPATH=services/worker python3 scripts/batch-kr-unresolved-public.py \
  --index /data/index \
  --audit output/public-index-20260927/index-audit.json \
  --output output/kr-unresolved-20260927/kr-unresolved-public-batch-v3.json
```

Файл результата должен отсутствовать до запуска; CLI не перезаписывает
существующий отчёт. На homeserver проверка проведена в отдельном worker
контейнере с `--network none`, лимитами 2 CPU / 3 GiB RAM и read-only
подключением индекса и checkout. Результат скопирован в
[`kr-unresolved-public-batch-v3.json`](../../output/kr-unresolved-20260927/kr-unresolved-public-batch-v3.json),
SHA-256 `92b1d5386a116a791b2e5ecd5891942487a37972bb4ecbc004afda20db98ddf5`.

Каждый показанный пример в JSON содержит `sourceFileId`, `pageNumber`,
`sourceSha256`, `pageArtifactSha256`, координаты строки, `lineSha256`,
стадию, раздел и статус `ABSTAIN`. Нормативная применимость, редакция и
согласование, роль листа, связь элемента и попарное сопоставление ПД/РД
остаются `UNPROVEN`. Даже точное буквальное совпадение «А500С» не
разрешает сравнить разные конструкции. Итог: `overallStatus=ABSTAIN`,
`findingCount=null`, `parameterCoverage=null`.

## Проверка кода

```bash
PYTHONPATH=services/worker uv run --no-project \
  --with 'pdfminer.six==20260107' --with 'PyMuPDF==1.27.2.2' \
  python -m unittest services.worker.tests.test_kr_unresolved_batch -v
```

Четыре теста прошли: классификация независимых терминов, разнообразие
выборки, отказ при изменённом SHA стратегии и полный синтетический PDF
index/audit с одной страницей `OCR_REQUIRED`. Следующий предметный шаг для
этих восьми кодов — связать конкретные листы/редакции и элементы, затем
адресно проверить нужные OCR-страницы и геометрию/спецификации. До этого
семейство остаётся диагностическим.
