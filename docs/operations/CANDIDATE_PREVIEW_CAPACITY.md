# Ёмкость просмотра 47 кодов в одном запуске

Проверка 27.09.2026. [Скрипт](../../scripts/benchmark-candidate-preview.py)
создаёт только синтетические `document-text-v2` артефакты и вызывает
`evaluate_run_candidate_family_preview` локально. Ни homeserver, ни GPU, ни
OCR, ни PostgreSQL не использовались. Время ниже — один прогон на текущей
локальной машине, не норматив стенда.

## Действующие границы

| Узел | Предел | Где применяется |
| --- | ---: | --- |
| Загрузка | 1 000 файлов, 100 МиБ на файл, 200 МиБ на один upload | `uploadPolicy` в `packages/contracts/src/index.ts` |
| Один `document-text-v2` | 8 МиБ | worker `text_layer.py`, `durable_text.py`; API `validateDocumentTextArtifact` |
| Весь результат `DOCUMENT_TEXT_LAYER` с оболочкой источников | 8 МиБ | worker `process_document_text_layer` |
| Все текстовые артефакты этапа вместе | 8 МиБ | API `validateDocumentTextResult` |
| Просмотр 47 кодов | 47 строк, до 16 лидов на код (до 752); текст строки до 500 символов | worker `run_candidate_family_preview.py`; API verifier |
| JSON самого просмотра | 1 МиБ = 1 048 576 байт | API `verifyCandidateFamilyPreview` |
| Просмотр и проверенные наблюдения нового opt-in профиля вместе | 2 МиБ | worker `durable_candidate_family_observations.py`; обрезка последних лидов с повторным извлечением и пересчётом SHA |
| Весь результат `RULE_EVALUATION` | 6 МиБ = 6 291 456 байт | worker `PilotPz002RuleAdapter.execute` |
| Артефакт результата в API | 8 МиБ = 8 388 608 байт | API `validatePilotPz002StageResult` |

Worker теперь детерминированно сокращает подсказки до **1 МиБ**, а в новом
профиле просмотр и наблюдения вместе — до **2 МиБ**. Затронутые коды получают
`PREVIEW_BYTE_BUDGET_REACHED`; наблюдения пересоздаются из уже усечённого
просмотра. Счётчики прочитанных страниц остаются исходными; скрытые подсказки
не означают отсутствие элемента. `NO_EXACT_LABEL_LEAD` появляется только когда
хотя бы одна страница реально просканирована и ни одной точной метки не найдено.
Проверка 6 МиБ включает также PZ-002, PZ-017, OCR-строки и `factFamily`.
Допустимые 1 МиБ просмотра сами по себе не гарантируют, что совокупный
результат влезет в 6 МиБ.

Публичный индекс содержит 203 источника: 202 PDF на 10 142 страницах и один
TXT. В реальном манифесте источники принадлежат двум объектам (145 и 58), а
запуск привязан к одному объекту. Сценарий со всеми 202 PDF в одном запуске
ниже — нагрузочная модель, не описание существующего check. Лимит на число
файлов пропустил бы 203; лимит **суммарных 8 МиБ текстовых артефактов** может
остановить такой запуск раньше этапа просмотра.

## Измерения

Все источники в синтетическом корпусе получили `CURRENT`, `APPROVED`, `RD`,
`AR`; страницы содержали нейтральный текст без совпадений. Для AR/RD 22 из
47 правил допускают поиск, поэтому сценарий нагружает сканирование, а не
генерацию лидов. У `saturation` каждый из 47 кодов получил 16 отдельных
положительных строк на допустимой странице с проверенным синтетическим
разделом; строки остаются только review leads.

## Оценка алгоритма и действия

Worker проверяет и хеширует каждый артефакт один раз, затем перебирает 47
правил и подходящие источники. Основная стоимость близка к сумме строк на
страницах, умноженной на число правил для стадии и раздела. Для RD/AR это
22 правила; абсолютная верхняя граница без учёта разделов — 47 проходов.
Regex чисел и классов кешируются. Вывод ограничен 16 лидами на код, но
**сканирование не останавливается после достижения лимита**, чтобы отметить
переполнение и сохранить детерминированный порядок.

`RULE_EVALUATION` отдельно вызывает `execute_durable_fact_family` и
новый wrapper preview+observations; каждый читает и проверяет
`document-text-v2`. Для N PDF это минимум 2N запросов текстового артефакта
в этих компонентах; preview и observations внутри wrapper используют один
набор. Измеренное время `evaluate` не включает
эти запросы, разбор JSON, остальные правила этапа, API verifier и запись в
PostgreSQL.

До включения профиля на большом check нужен совместный замер полного этапа
и его 6-МиБ JSON. Детерминированный бюджет preview в примере с длинными
строками скрыл 101 лид и сохранил ранние подсказки по каждому коду.
Для 203 исходников требуется разбиение по объекту и, вероятно, дальнейшее
ограничение суммарного текста или постраничные артефакты: текущий лимит 8 МиБ
не обеспечивает приём всего корпуса одним этапом. Текущий постраничный
публичный индекс решает именно повторное чтение корпуса вне одного run.

Повторить локально:

```bash
python3 scripts/benchmark-candidate-preview.py --scenario corpus --sources 202 --pages 10142 --blocks-per-page 3
python3 scripts/benchmark-candidate-preview.py --scenario saturation --line-width 480
```
