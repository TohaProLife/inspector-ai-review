# KR-056/KR-057: открытые наблюдения по маркам стали и классам арматуры

Версия извлекателя: `kr-material-review-v1`. Это отдельный read-only срез для
экспертной проверки. Он не создаёт факт о сопоставимом элементе, нарушение или
покрытие параметра. Статус обоих кодов остаётся `ABSTAIN`.

## Источник и границы

Использованы только десять PDF КР объекта `OBJ-NOVOSLOBODSKAYA` с метками
`TRAIN_PUBLIC / INCLUDE / PUBLIC_TRAIN`: ПД `F0105–F0107`, РД `F0136,
F0139–F0144`. Манифест SHA-256
`853225daec1888fbed19bbeb45e958154135f069799cea883dcd3c754c6c4ee7`.
Независимый `PASS`-аудит индекса v4 SHA-256
`69ef56fc23e779dfed25aa60c5615be3ee58f244200c6620c2b1ddaec335f49a`;
`indexVersionHash=7d7dfa2f3e0279a91095`. Исходные PDF прочитаны из
`01_ПАКЕТ_УЧАСТНИКАМ_3_ОБЪЕКТА.zip` на homeserver: перед извлечением
каждый из десяти повторно сверен с публичным манифестом по размеру и SHA-256.
Для каждой страницы сверены source SHA, SHA сжатого артефакта, версия индекса,
номер и disposition. Запуск не читал `TEST_HIDDEN`, закрытые ответы или TXT
F0194. Удалённый запуск использовал stdin, не записывал данные на homeserver.

В пакете **521 физическая страница**: 471 `TEXT_LAYER_CANDIDATE`, 50
`OCR_REQUIRED`. Последние не извлекались как текст. В частности, F0106
с. 17, 100 и 101 имеют в v4 статус `OCR_REQUIRED_UNKNOWN`; строки прежнего
v3 не считаются доказательством. Отсутствие `C345` среди принятых текстовых
строк не доказывает отсутствия этой марки в PDF.

Для проверенных ключевых строк содержательное расхождение между text layer и
пикселями **не обнаружено**. Отдельные строки индекса делят предложение на
несколько строк; это не меняет прочитанные термины. По пикселям нельзя
различить латинскую `C` и кириллическую `С`, поэтому JSON сохраняет исходное
написание `rawTerm` и отдельный нормализованный `term`. Номер физической
страницы PDF отличается от номера в штампе: F0105 с. 13/14 напечатаны как
листы 11/12; F0139 и F0140 с. 3 — как лист 1. Локаторы отчёта используют
физическую страницу PDF. Визуальная сверка не подтверждает применимость
редакции, утверждение или соответствие элементов ПД/РД.

В полном JSON перечислены все точные вхождения. Число **токенов** и число
уникальных адресов `(source, page, line)` различаются: одна строка содержит
два токена A500C.

| Термин | Токенов | Уникальных строк | Страниц с токеном |
| --- | ---: | ---: | ---: |
| A400 | 1 | 1 | 1 |
| A500C | 4 712 | 4 711 | 109 |
| C245 | 20 | 20 | 11 |
| C345 | 0 | 0 | 0 |

Для A500C максимум на одной странице — 182 токена (F0140 с. 27).
Чертёжные спецификации многократно повторяют эту маркировку. Эти числа не
равны числу конструкций, сопоставлений или проверенных фактов. Машинное
состояние каждого наблюдения — `REVIEW_ONLY_ABSTAIN`;
`elementContextStatus=UNVERIFIED`. Поле `contextClass` различает только
закреплённые строки предметного абзаца ПД (`ELEMENT_PARAGRAPH_HINT`),
общую заметку (`GENERAL_NOTE_UNLINKED`), заголовок таблицы
(`TABLE_HEADING_UNLINKED`), справочную строку стандарта
(`STANDARD_REFERENCE_UNLINKED`) и прочие упоминания
(`UNCLASSIFIED_TEXT_MENTION`). Даже первый класс не связывает элемент ПД с
РД. Классификация закреплена SHA строки и применяется только к просмотренным
контекстам четырёх страниц; остальные строки не классифицируются по смыслу.

## Почему сравнение не выполнено

F0105 с. 13 и с. 14 описывают разные контексты ПД. Совпадение A500C в
ПД F0105 и РД F0140 не подтверждает тот же элемент. F0139 с. 3 и F0140
с. 3 содержат также общие ссылки на материал и заголовки таблиц, которые
нельзя считать материалом конкретной конструкции без проверки строки, осей,
марки и листа. Редакции и утверждение применимых комплектов не проверены.
Поэтому результат содержит `comparableFacts=[]`, `finding=null`,
`findingCount=null`, `parameterCoverage=null`. Для KR-056 нельзя строить
сравнение C245/C345 на основании старого OCR_REQUIRED-лида F0106.

## Повторение и проверка

Извлекатель:
[`kr_material_review.py`](../../services/worker/inspector_worker/kr_material_review.py).
Он принимает `--manifest`, `--index` (только v4), `--audit`, `--archive` с
исходным открытым ZIP и печатает JSON. `--source-id` ограничивает прогон
одним или несколькими из десяти закреплённых PDF. Проверенные выводы:
[`material-review-v1.json`](../../output/kr-material-review-20260928/material-review-v1.json)
(SHA-256 `cf406cc3b364f19ba3c1d612b0dacfa79bb771960b369e59cfee83c00c187c99`).

Локальные тесты: `PYTHONPATH=services/worker python3 -m unittest
services.worker.tests.test_kr_material_review -v` — 2/2. Они проверяют точные
буквальные классы, консервативный `ABSTAIN`, соседний контекст и отказ при
изменении SHA оригинала или страницы. Реальный полный прогон проверяет 10 оригиналов и 521
страницу; тесты сами по себе не подтверждают правильность интерпретации
чертежа.

### Что проверить

- На исходных листах подтвердить, к какому именно элементу относятся
  процитированные строки и табличные колонки.
- Установить действующие редакции и статус утверждения ПД и РД.
- При необходимости отдельно распознать F0106 с. 17, 100 и 101 по оригиналу,
  затем проверить OCR глазами; до этого их значение неизвестно.
