# Кеш текстового слоя в durable стадии

`DOCUMENT_TEXT_LAYER` повторно извлекает текст из PDF при каждом immutable
run. Для повторной проверки тех же байтов `document-worker` теперь хранит
проверенный `document-text-v2` в Compose volume `text-layer-cache`.
Источник **каждый раз скачивается через текущий fenced lease** и сверяется
по размеру и SHA-256; кеш исключает повторную работу PDFMiner, а не проверку
прав на источник. В остальных стадиях по-прежнему читается committed
артефакт текущего run через API.

Ключ включает SHA-256 PDF, `sourceFileId`, SHA-256 текущего исходника
`text_layer.py`, установленную версию `pdfminer.six` и версию политики
качества. Поэтому изменение байтов, кода извлечения или версии парсера
создаёт новую запись. `sourceFileId` входит в ключ, поскольку он записан в
самом артефакте. Кеш не переносит факт между разными загруженными файлами.

Перед HIT проверяются схема, полный content hash и валидатор
`document-text-v2`: последовательность страниц, координаты блоков,
качество чтения, итоговые счётчики и происхождение. Повреждённая запись
останавливает job и не заменяется молча. Запись ограничена 8 MiB, защищена
file lock и создаётся атомарным переименованием после записи на диск.

Кеш включается только при `INSPECTOR_DURABLE_TEXT_CACHE_ROOT`; базовый
Compose задаёт `/text-layer-cache`. Он локален для Compose-проекта и не
использует отдельный публичный SQLite-индекс 203 документов: индекс
служит исследовательской выборке `TRAIN_PUBLIC`, а durable job обязан
обработать именно загруженные байты текущей проверки.

Тест `test_durable_text_cache.py` проверяет HIT, инвалидацию по профилю,
повреждённую запись, изменение PDF и интеграцию с job: файл скачивается
дважды, PDFMiner вызывается один раз. [Четыре реальных durable run](DURABLE_CACHE_E2E_20260927.md)
подтвердили на F0150/F0201 снижение времени текстовой стадии с 460 до
3 секунд при сохранении тех же хешей текстовых, OCR и rule артефактов.
