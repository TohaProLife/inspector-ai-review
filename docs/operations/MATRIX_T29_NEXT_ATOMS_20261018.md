# T29: следующий атом по реальным открытым ПД/РД

Дата: 2026-10-18. Статус: read-only feasibility, **не реализация и не выпуск**. Владение этого пакета: данный документ и `output/matrix-t29-20261018/`. Существующие runtime, тесты, registry, стенд не изменялись. Применён проектный skill `inspector-ai-functional-development`.

## Решение

Первый кандидат — **PZ-009, ограниченная проверка согласованности явно принятой абсолютной отметки проектного нуля**. Найдена реальная пара того же объекта Новослободская: ПД F0101, стр.13, и РД F0139, стр.4. Обе явно задают 159,95 м; в данной паре расхождения нет. Это достаточная основа для узкого извлечения и сравнения после доказанного соответствия проектных нулей и утверждённого источника ПД. Независимую реальную геопривязку, фактическое положение построенного объекта и правильность внешней геоподосновы эта пара не доказывает.

Второй кандидат — **KR-060, площадь сечения колонны/пилона** — имеет реальные числа на обеих стадиях, но **исполняемый атом пока не обоснован**. ПД перечисляет типоразмеры колонн без соответствия конкретным элементам, РД перечисляет пилоны. Нельзя образовать пары по порядку, площади, близости величин или принадлежности одному объекту. Следующий нужный источник: ведомость либо опалубочный план ПД с ID элемента, осями, этажом и размерным сечением; затем соответствующий элемент РД.

Фактически: **7 FTS-запросов, 62 возвращённые строки**, лимит 10 запросов / 100 строк; каждый запрос LIMIT10. Проверено восемь canonical page artifacts; compressed SHA совпал с индексом, JSON inputSha256 — с source SHA, pageNumber — с запрошенной страницей. Полные PDF повторно не хешировались, новых extraction/model/cache jobs нет. Ограниченная выдача не доказывает отсутствие иных пар в корпусе.

Подробности: `output/matrix-t29-20261018/fts-research.json`, `canonical-page-receipts.json`, `read-only-research.json`. ## PZ-009: факты и область

Точный catalog trigger: «Несоответствие абсолютной отметки нуля на чертежах РД геоподоснове ПД.» Registry сейчас `family:null`, gap `GEOMETRY_OR_TOPOLOGY`, атомов нет. Пара ниже подтверждает **проектные декларации нуля**. Превращение ПЗ в источник утверждённого datum требует явной проверки полномочий/привязки; автоматически выдавать текст за независимую геодезическую съёмку нельзя.

ПД **F0101 / OTHER**, `НВС-2025.03-1.2-ПЗ.pdf`, исходная стр.13, размер `[595220,842000]` milli-points. Source SHA `01db90e015c39a9502b99969ce04f27825265203bc8728da6141d7b6d2b1ef54`; compressed canonical SHA `411f0ca0315f25702dc19f095b283a63070d506f48f601f13575152aba4356f3`.

Две последовательные строки одного оригинального блока0:

- line8 `[85138,677046,515421,687066]`: «За относительную отметку 0,000 принята абсолютная отметка 159,95 м., что соответствует».
- line9 `[85135,664986,351559,675006]`: «отметке чистого пола входного вестибюля на 1-м этаже.»

Это точное принятое значение, не минимум, диапазон, типовая норма либо расчётный порог. Межстрочный gap2040 mpt, разница левого края3 mpt, высота10020 mpt обеих строк. Правые края различаются из-за короткой последней строки; требовать одинаковую ширину здесь неверно.

РД **F0139 / KR**, `НСЛ-12-02.2026-1_2-КЖ1.1.8_Изм.1.pdf`, исходная стр.4, размер `[1684000,1191000]`. Source SHA `d59c225e75d1e0227f08869b31165bd93bf85ed4b1da005c3e86ebc27023b73f`; compressed canonical SHA `b419343d8bf4eebfd6407ab996a58f0973db9847cd6f3a1758a48f4529ce02e5`.

Оригинальный block40 line0 `[97800,606951,559015,618830]` целиком: «За относительную отметку ±0.000 принята отметка чистого пола первого этажа, соответствующая абсолютной отметке  159.95.»

В самой фразе РД единица отсутствует. Она **явно определена** в general notes на той же странице: block32 line18 `[71940,433911,832182,445790]` заканчивается «Все размеры даны в миллиметрах,», line19 `[72300,416811,141824,428690]` целиком «отметки - в метрах.». Это отдельное доказательство единицы; без него либо явного `м`/`m` извлечение должно воздержаться. Нельзя назначать метры по правдоподобию числа159.95.

Подтверждающие источники: ПД F0106/KR стр.17, blocks5–6, тоже159,95 м и входной вестибюль первого этажа; РД F0144/KR стр.3, block15 line0 + block6 line3, тоже159.95 м и тот же вестибюль. Они подтверждают семантику, но не являются независимыми геодезическими измерениями. F0141/KR стр.3 содержит159.95 в blocks121/127 с разорванным порядком чтения; F0142/KR стр.3 — в blocks24/30. Для первого grammar их лучше не включать: cross-block joins нуждаются в самостоятельном адаптере, проверяющем original geometry и column-local adjacency. Join всего page text небезопасен.

ПЗ уточняет «входного вестибюля», РД F0139 говорит только «чистого пола первого этажа». Простого равенства чисел недостаточно для автоматического entity match: общий project datum и его authority должны быть явно связаны проверенным context. Нельзя дописать отсутствующий в РД вестибюль или название высотной системы.

## Минимальный будущий контракт PZ-009

Предлагаемый ограниченный атом `matrix-pz-009-declared_project_zero_absolute_elevation`, version1, attribute `PROJECT_ZERO_ABSOLUTE_ELEVATION`, decimal/m, comparison `DIFFERENT`, threshold null, PD_RD only. Включать только после отдельной реализации и проверки; этот пакет registry не меняет. Пока ПД не подтверждена как утверждённый источник соответствующего datum, результат только EVIDENCE_ONLY/кандидат.

Область атома `DECLARED_APPROVED_PROJECT_ZERO_ABSOLUTE_ELEVATION`; parent parameter остаётся partial. Обязательная reviewed identity: объект/строительный объём, общий local-zero reference, высотный datum, полномочия источника ПД и статус согласованного изменения. Содержание полей фиксируется явными proofs на обеих сторонах, hash-bound к exact source SHA, полному textArtifactHash, fact IDs, версии атома и scope. Отсутствующую высотную систему нельзя автоматически назвать Балтийской. Источник с несколькими корпусами и разными нулями должен воздержаться без отдельной области каждого нуля.

Первая source grammar:

1. ПД: только указанные две полные строки одного оригинального блока, последовательные line indices с точными valid line boxes. В первой `0,000`/`0.000` и один decimal absolute elevation с явной единицей `м`/`m`; во второй полное уточнение принятого пола. Разрешение whitespace не разрешает альтернативную пунктуацию, отрицание или дополнительные условия.
2. РД: полная одна оригинальная строка принятого нуля и пола первого этажа. `±0.000` — marker принятого локального нуля, не uncertainty interval для абсолютной отметки. Один decimal absolute elevation. Если единица в этой строке отсутствует, отдельный unit proof допускается только по явной same-page фразе «отметки - в метрах.» в рамках оригинальных general notes с исходными fragments; отсутствие/конфликт/другая область unit proof даёт abstain.
3. Для geometry ПД как начальные консервативные guards: обе высоты9000..14000 mpt, разница<=1000; gap0..6000; разница left<=1000; continuation внутри первой колонки. Никаких равных right edges для короткого окончания. Это guards по конкретным observed boxes, не универсальная PDF-геометрия. Другие масштабы пока abstain. Same-block consecutive lines, уникальный governing anchor и отсутствие вмешавшейся непустой строки обязательны. РД одна точная line box, generic coarse multi-line block недостаточен.
4. Числа signed single decimal, canonical decimal без float/thousands/range, входные bounding boxes safe integer. Полные raw fragments, Unicode code-point usedTextRange, source+artifact hashes сохраняются; normalized UI box вычисляется отдельно. Unit proof и reference wording входят в fact identity.
5. Ни matching одинаковых чисел, ни отсутствие расхождения не подтверждают внешний datum или весь PZ-009. `NO_VIOLATION` допустим только в явно принятой полной области **этого атома** при закрытых required proofs; общий геодезический статус не повышается. Более безопасный промежуточный выпуск — отдельные typed datum facts до принятия источника/контекста.

Meaningful tests: настоящая полная пара с159.95/159.95; контролируемая замена только РД на159.96 с сохранением правдивой новой identity; zero marker ± отдельно от знака absolute elevation; отсутствие/конфликт единицы; datum identity mismatch; другой корпус/этаж/пол/vestibule ambiguity; approved change; несколько competing anchors; range/не менее/отрицание/цитата/другие absolute elevations геологии; malformed/coarse boxes; чужая колонка; extra line; source stage/SHA/artifact mismatch; независимая Python/TS реконструкция факта; PG durable round-trip с мутациями scope; UI отдельный смысл «проектная согласованность» и сохранение общей геопривязки unverified. Ни confidence percentage, ни утверждённые доказательства не генерируются автоматически.

## KR-060: почему пока abstain

ПД F0106/KR стр.53, source SHA `ae8b16439650526a5ef6e1975c852fa38c2ab4466cd73ab725a47bcb32a6b655`, block12 lines0..3. В подземной части перечислены сечения колонн:550×1200,600×1300,600×1500,600×1600,600×1700,600×1750,1000×1500 мм. Это реальный набор проектных размеров, но без member ID/координатной оси/этажа каждого элемента. Фраза «отношение сторон не менее1:4» описывает классификацию, её нельзя превращать в измеренное сечение.

РД F0141/KR стр.4, source SHA `421a34429325f424d3e29086810b1283e805d9bb3c75646508e5434b248e5d5f`, block13 line0 + block17 line0: перечислены пилоны500×1700,500×1500,600×1500 мм, рядом указаны разные толщины стен. Это ещё одна коллекция, не таблица соответствия конкретным колоннам ПД. Вторая строка заканчивается классом бетона и другим текстом — mixed attributes требуют точных usedTextRange.

ПД600×1500 и РД600×1500 дают одинаковую площадь900000 мм²; это не доказывает одинаковый элемент. ПД550×1200 и РД500×1500 дают разные площади660000/750000 мм²; это тоже не пара. Даже простое сортирование площадей создаст вымышленные изменения. Различие «колонны»/«пилоны», разные уровни и пересмотренные решения сохраняются как blockers.

Контракт на будущее только после member mapping: формаRECTANGLE либоCIRCLE с отдельной строгой grammar; exact dimensions с единицами и оригинальными размерными цепями; source-derived member mark+axis intersection+level+building; одинаковые measurement basis и approved change proofs. Для rectangle площадь как exact integer product вмм², для circle отдельный определённый decimal policy, без подмены диаметра стороной. Ни отсутствие члена в списке, ни меньшая минимальная площадь списка не являются trigger. Новый массовый парсер чертежей в пределах этого пакета не предлагается.
