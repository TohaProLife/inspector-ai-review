# Парный просмотр ПД/РД, 20 октября 2026

## Что изменилось

Общий viewer показывает два исходных PDF рядом: независимые страницы, масштаб и прокрутка; Alt+←/→ в выбранном документе; переход к исходной области с автоматическим центрированием; рамки и буквальные текстовые различия; полноэкранный режим пары либо одной стороны. Связь масштаба/прокрутки включается отдельно. При связанной прокрутке переданная позиция имеет приоритет перед центрированием рамки после изменения размеров. На375px документы идут друг под другом. Смена темы и размеров сохраняет видимость выбранной рамки, включая завершение анимации темы.

Сравнение открывается и для сохранённого NORMAL-замечания, и для review candidates. Предыдущий/следующий кандидат сохраняет исходные ID/SHA/страницы. Для реальных F0171/F0201 доступны147/198, вместимость PZ-013 и П17 IOS4-079. Пресеты появляются только при уникальном совпадении SHA загруженных исходников; чужие или дублированные файлы автоматически не выбираются. На странице без доказательства рамка скрыта. Переключение источника не переносит рамку прежнего файла.

Поиск использует сохранённый текст проверяемого запуска. Для PDF больше512 страниц выбирается отдельный полный V4-аудит; история сравнения не изменяется. Все676 страниц загружаются шестью пакетами одного SHA-pinned артефакта перед публикацией результатов. Результат поиска открывает оригинальную страницу и её bbox. Графические надписи и OCR не становятся native text автоматически.

Все authenticated PNG-миниатюры и общие viewers используют одну очередь максимум из двух запросов на вкладку. React StrictMode cleanup до I/O отменяет устаревший запрос; начатый запрос удерживает слот до получения ответа, поскольку отмена fetch сама не останавливает серверный PDF render. Завершённые ответы не кэшируются и не передаются другому потребителю. Старые blob URL освобождаются. При перегрузке другого клиента остаются ограниченные retries и видимая ошибка с повтором.

READ-only пользователь видит исходники; textarea и три кнопки решений старого экрана отключены. Backend authorisation/CSRF/optimistic concurrency сохранены.

## Как открыть

1. Запустить обычный CPU-профиль по [CPU_LOCAL_QUICKSTART.md](CPU_LOCAL_QUICKSTART.md), открыть объект с загруженными исходными PDF.
2. Раздел «Кандидаты»: блок «ПД и РД рядом». Выбрать пару либо два файла вручную. Для конкретного кандидата открыть его карточку.
3. Нажать цитату, «К расхождению» или общий переход; листать страницы каждой стороны независимо. «Развернуть сравнение» закрывается Escape.
4. Для поиска после512 сначала подготовить полный аудит V4 в «Источниках», затем раскрыть «Найти текст в этом документе» и загрузить сохранённый текст. Отсутствие текста не доказывает отсутствие сведений в графике.

## Воспроизводимые браузерные проверки

Потребуется установленный Playwright и Chrome. Скрипты не устанавливают браузер/пакеты. QA запускает только собственный loopback Vite/Fastify, использует отдельную in-memory repository с READ-сессией и реальные authenticated API/render routes. Реальные PDF и V4 сверяются целиком по SHA. Объект/репозиторий в QA синтетические; страницы и цитаты настоящие. Никаких изменений reviewer history, БД, очередей, моделей или внешнего стенда.

```sh
INSPECTOR_PLAYWRIGHT_PATH=/absolute/node_modules/playwright \
node --import tsx scripts/smoke-document-pair-ui.mjs \
  --sources /absolute/companion/inputs \
  --artifact /absolute/companion/audits/F0201-native-v4.json \
  --output output/pair-components-new --port 28188

INSPECTOR_PLAYWRIGHT_PATH=/absolute/node_modules/playwright \
node --import tsx scripts/smoke-document-pair-app.mjs \
  --sources /absolute/companion/inputs \
  --artifact /absolute/companion/audits/F0201-native-v4.json \
  --output output/pair-app-new
```

По умолчанию Chrome находится в `/opt/google/chrome/chrome`. Для своей среды скорректировать явный executablePath в QA-скриптах. Не запускать два PDF-render harness одновременно: server guard общий в одном процессе каждого harness, а нагрузка на host складывается. Собственные браузеры/HTTP listeners закрываются в finally.
