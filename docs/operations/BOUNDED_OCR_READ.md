# Просмотр сохранённого bounded OCR

Экран «Проверка источников» показывает OCR только для **активного** run. После
выбора исходного файла инспектор видит обработанные и отложенные страницы,
открывает исходный лист и просматривает сохранённые строки с координатами и
оценкой OCR. Это вспомогательный просмотр. Строки не проверены человеком,
оценка OCR не равна подтверждённой точности, а пустой или отсутствующий
результат не доказывает отсутствия текста либо элементов.

Два GET-маршрута доступны только аутентифицированному пользователю с правом
`READ` на объект текущей проверки:

- `/api/checks/{checkId}/ocr-layout` возвращает профиль v1/v2/v3, SHA-256
  immutable артефакта и manifest, список источников, счётчики и метаданные
  сохранённых страниц. Сырые OCR-строки сюда не входят.
- `/api/checks/{checkId}/ocr-layout/pages/{sourceFileId}/{pageNumber}?offset=0`
  возвращает не более 50 строк одного сохранённого листа. `nextOffset` даёт
  следующую порцию, `null` означает конец. Смещение ограничено диапазоном
  0–5000. В ответе есть хеш страницы и PNG-рендера, профиль OCR/PDFium,
  оценка и bbox каждой строки.

Оба маршрута отдают `404` для устаревшего run, отсутствующего артефакта,
чужого объекта и несуществующего OCR-листа; `401` — без входа. Ответы имеют
`Cache-Control: private, no-store`. Сервер заново сверяет канонический хеш и
размер сохранённого stage artifact, хеш страницы и идентичность release/manifest
до проекции. Сохранение и проверка результата стадии остаются в
`DOCUMENT_OCR_LAYOUT`; чтение не меняет immutable артефакт или coverage.

В браузере выбор строки OCR выделяет её bbox на полном исходном листе и
показывает рядом увеличенный фрагмент того же PDF. Выделение сбрасывается при
смене файла, страницы, порции строк или активного run. Превью повторяет
временные ответы `429`/`503` ограниченное число раз; после неудачи инспектор
видит кнопку повторной загрузки. Это помогает при одновременном просмотре
листов, но не подтверждает правильность распознанной строки.

Локально: `npm run test --workspace=apps/api -- --run test/ocr-layout-read.test.ts test/openapi.test.ts`
и `npm run typecheck --workspace=apps/web`. PostgreSQL integration тест
`persists only bounded OCR_REQUIRED pages with a fenced immutable result`
дополнительно проверяет авторизацию, объектный scope и HTTP-ответы после
сохранения; `pins OCR v3 and accepts only the committed heating-context pages`
проверяет чтение нового профиля. Их нужно запускать с тестовой PostgreSQL через
`INSPECTOR_POSTGRES_ADMIN_URL`.

На изолированном homeserver проверка `CHK-75051E60` прочитана через API и
браузер: 398 страниц требовали OCR, 2 обработаны, 396 отложены; F0201 p.30
имеет 365 строк, первые две порции по 50 доступны и исходный PNG открывается.
См. [скриншот просмотра](../../output/bounded-ocr-v2-20260927/f0201-ocr-v2-review-20260927.png)
и [журнал проверки](HOMESERVER_SMOKE.md#ocr-v2-и-повторный-полный-прогон-27-сентября).

Для OCR v3 реальный F0201 p.7 просмотрен порциями 50+40 строк. На
[снимке выбранной строки](../../output/bounded-ocr-v3-20260927/f0201-ocr-v3-crop-20260927.png)
видны исходный лист, рамка и читаемый фрагмент для «Стальные панельные
радиаторы». Параллельный browser smoke двух PDF дал временный `429` на
превью p.7, после чего автоматический повтор получил `200` и обе сессии
завершились успешно. Это проверка поведения просмотра под конкуренцией,
а не достоверности OCR.
