# SITE_TEP_AREA: проверка семейства PZ/SPZU

28 сентября 2026. Для `PZ-001`, `SPZU-026`, `SPZU-027` добавлен отдельный
opt-in пакет `site-tep-area-run-review-v1`. Это наблюдения строк технико-
экономических показателей и благоустройства, а не извлечённые значения
параметров. Все три кода остаются `ABSTAIN`; `findingCount` и
`parameterCoverage` равны `null`.

## Граница исполнения

Профиль `typed-pz002-pz017-site-tep-area-review-v1` включается только
явной настройкой `INSPECTOR_SITE_TEP_AREA_REVIEW_PROFILE=v1`. Источник
должен иметь неизменяемое решение `CURRENT` и `APPROVED`, стадию ПД,
раздел ГП и точный SHA. Worker получает committed `document-text-v2`,
ограничивает выдачу 16 лидами на код и сообщает об усечении. API
независимо восстанавливает те же строки, локаторы, причины, счётчики и
SHA при save/seal/GET. Положительный синтетический пакет Python принят
TypeScript валидатором; PostgreSQL тест проверил сохранение и отказы
при подмене. Публичные F0126/F0154/F0155 не получили экспертного
решения о редакции/утверждении, и факты из них не повышались.

Локальный полный `npm run check` после интеграции: API 278 pass/33 skip,
web 62 pass, Python worker 707 pass, сборка PASS. Полный последовательный
PostgreSQL suite: 10 файлов, 34 теста, exit 0. Тематический изолированный
Compose и просмотр интерфейса пока остаются следующей
проверкой. Даже после их завершения для сравнений нужны утверждённые
редакции ПД/РД, пара документов и предметная идентичность объекта.
