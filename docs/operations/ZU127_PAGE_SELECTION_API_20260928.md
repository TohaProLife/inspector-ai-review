# ZU-127: независимая проверка выбора страниц v3

`apps/api/src/zu127-page-selection-v3.ts` независимо воспроизводит результат
`services/worker/inspector_worker/zu127_page_selection_v3.py`. На вход подаются
исходные сведения об источниках, решения по источникам, полные артефакты
`document-text-v2` и результат worker. API заново проверяет структуру и SHA
текстового артефакта, качество каждой страницы по версии политики, решения
`CURRENT`/`APPROVED`/`ZU`, стадии страниц, лексические подсказки, общий лимит
четырёх страниц, отложенные `OCR_REQUIRED` и все итоговые счётчики. Затем
сравнивает весь результат, включая canonical `contentHash`.

Проверка синтетического пакета, созданного настоящей Python-функцией:
`npx vitest run apps/api/test/zu127-page-selection-v3.test.ts` — 6/6;
`npm run typecheck -w @inspector-ai/api` — PASS. Подмена счётчика с
пересчитанным SHA, блока, качества, решения или состава источников отклоняется.

Это pure verifier. Перед использованием в `save`/`seal`/`GET` API должен брать
источники и решения из аутентифицированного immutable snapshot текущего run,
текстовые артефакты — из сохранённых stage bytes, сверять с manifest и release,
а не доверять данным worker. Для последующего Poppler-анализа нужны исходные
PDF bytes и независимая проверка SHA, размера, количества и состава страниц.
Ни PostgreSQL, ни очередь, ни release здесь не подключены. Выбор страниц даёт
только навигацию для эксперта: `ABSTAIN`, `findings=null`, `typedFacts=null`,
`parameterCoverage=null`; отсутствие кандидата не доказывает отсутствие
нарушения. Положительных решений по публичным источникам не создано.
