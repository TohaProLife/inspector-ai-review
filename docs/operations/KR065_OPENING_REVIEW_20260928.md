# KR-065: подписи проёмов, отдельный review-only профиль

Публичный аудит [STRUCTURAL_DETAIL](STRUCTURAL_DETAIL_AUDIT_20260928.md) сверил исходные F0141/F0142/F0143 с manifest и SHA, а также визуально проверил соответствующие листы. На F0141 с.23 и F0143 с.21 напечатаны разные номера отверстий; F0142 с.12 содержит проектные детали заделки. Совпадение подписи детали, номера размера или слова «заделка» не устанавливает один элемент и не доказывает нарушение. Исходные PDF имеют статус `TRAIN_PUBLIC / INCLUDE / PUBLIC_TRAIN`; закрытые ответы и `TEST_HIDDEN` не использованы.

`kr065-opening-proposals-v1` читает committed `document-text-v2` только для отдельно проверенного `CURRENT / APPROVED` источника `RD / KR`. Результат содержит неизменяемые SHA PDF, текстового артефакта, страницы, блока и строки, bbox исходного текстового блока, точную подпись, счётчики OCR_REQUIRED, неоднозначных, повторных и усечённых строк. Номер отверстия и размер остаются сырым текстом. `drawingContourAssociation`, `detailAssociation` и `sameElementAssociation` всегда `UNVERIFIED`; армирование и несанкционированная заделка — `NOT_ESTABLISHED`. Единственный код `KR-065` всегда `ABSTAIN`, `findingCount` и `parameterCoverage` равны `null`.

Рабочий профиль `typed-pz002-pz017-kr065-opening-review-v1`, adapter 21, определение `pilot-kr065-opening-review-v1`, `codeCount=1`, RULE stage `outputCount=3`. Старые release-профили сохраняют прежние выводы и sidecar.

Независимый API verifier должен сверять immutable source/text/release и все локаторы при save/seal/GET. Реальные решения эксперта в публичном корпусе отсутствуют; positive tests используют только synthetic fixtures. До сравнения требуются проверенная пара ПД/РД одного объекта и редакции, тот же проём/оси/уровень и подтверждённый контур, армирование, согласование и при необходимости исполнительная запись. Простая близость блоков текста не проходит этот gate.
