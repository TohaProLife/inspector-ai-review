## Один конфигурационный механизм вместо профиля на каждый малый пакет

Текущий [run-scoped unresolved review](../../services/worker/inspector_worker/unresolved_family_run_review.py) жёстко перечисляет три кода и секции; [release adapter](../../services/worker/inspector_worker/pilot_rule_adapter.py) проверяет `codeCount: 3`. Для расширения предлагается **один opt-in `unresolved-review-config-v1`**: immutable конфигурация, закреплённая SHA-256 в release definition, содержит allowlist кодов из реестра, `candidateExtractorFamily`, допустимые *после экспертного решения* section/stage, безопасные строковые якоря, тип адреса (табличный ряд, размерная надпись, подпись сети), обязательные proof gates, лимиты строк/байтов и версию схемы. Каждый новый пакет меняет pin конфигурации в новом immutable release, но не создаёт отдельную ветку runtime-профиля. Механизм не должен интерпретировать якорь как доказанный факт.

Единый evaluator читает только committed `document-text-v2` и, при opt-in OCR, сохранённую OCR-стадию **того же run**; проверяет manifest/source SHA, решения `CURRENT`/`APPROVED`, раздел, стадию листа, artifact/page/block/line SHA и bbox; ведёт полные счётчики `OCR_REQUIRED`, deferred и усечений. По каждому коду возвращает `ABSTAIN`, причины и ограниченные адресные лиды; `findingCount=null`, `parameterCoverage=null`, без записи typed facts или пар. API независимо сверяет pin конфигурации, набор и порядок кодов, счётчики, локаторы и происхождение при save/seal/GET. Отсутствие проверенного источника или пары явно остаётся причиной abstain. Отдельное исполнение правила возможно только после доказанных применимости, редакции, элемента, нормативного значения и пары ПД/РД; этот план такого решения не принимает.

Ни `TEST_HIDDEN`, ни закрытые ответы для подсчёта и приоритизации не использованы.
