# Проверка комплекта H100 V9 и реальных пар, 20 октября 2026

H100 недоступен по сообщению пользователя. Выполнена локальная подготовка; аппаратная приёмка CUDA и настоящих моделей остаётся задачей проверяющих на выделенном стенде. Порядок запуска: [H100_READINESS_20261020.md](H100_READINESS_20261020.md). Для CPU: [CPU_LOCAL_QUICKSTART.md](CPU_LOCAL_QUICKSTART.md).

## Какой исходный комплект использовать

Актуальный комплект собирается по новой карте `source-map-v9.json` из проверенного PPM-113 среза `source-map1095.json` и явно перечисленных изменений V9, тёплых полов, зависимостей и переносимости тестов. В review ZIP приложение находится в `source/`: команды npm, Docker и Compose выполняются из этой директории. В ZIP есть `SHA256SUMS`; локальные `.env`, cookie, базы, веса моделей и закрытые ответы организаторов исключены. Первоначальная незакоммиченная рабочая копия автора содержала другие исторические варианты API. Принятый Git checkout уже включает V9 в корне; [порядок фиксации и дальнейшие задачи](NEXT_STEPS_20261020.md).

Пакет оригиналов `inspector-real-public-pairs.zip` передаётся отдельно: три публичных PDF, полные текстовые артефакты, отдельная открытая учебная разметка, рендеры и автономное воспроизведение. SHA256 `e0d294b8323c0cb51a8ded3f433c5547250005f63c7ca931e9030fcc5985d236`. Архив распакован в случайный временный каталог; повторная проверка прошла. Изменились только пять абсолютных путей происхождения и зависящий от них contentHash; все цитаты, кандидаты, отказы и SHA источников совпали.

## Изменения по исходному фидбеку

- Новый immutable V9 устраняет переключение server-профиля на ordinary 4B при выборе SAMPLE/FULL. Lease и API фиксируют 8B FP8, `vlm:8000`, revision и lock модели. Старые V1–V8 не переписаны.
- SAMPLE сообщает две выбранные области и точное число пропущенных. FULL обрабатывает все сохранённые подходящие области детектора; частичная обработка или превышение лимита не выдаются за полный результат. Display-crop до 2048 px; metadata, outline и многостраничный контекст сохраняются вместе, в том числе для смешанных систем.
- Ответ server-модели OTHER даёт ABSTAIN, без утверждения об отсутствии инженерной системы. Вероятность нарушения из ответа VLM не вычисляется.
- Native RabbitMQ healthcheck выполняется под пользователем `rabbitmq`: `su-exec rabbitmq rabbitmq-diagnostics -q ping`. Проверены daemon account, реальный успешный запуск и очистка собственного контейнера/тома. В Compose timeout 15 s, interval 10 s, start period 20 s, retries 10.
- Прямые зависимости закреплены на Fastify 5.12.7 и concurrently 9.2.5; lock включает shell-quote 1.12.0 и source-map-js 1.2.2. Повторная установка и Docker npm ci показали 0 записей npm audit. Это результат npm-аудита данного lock, а не полная сертификация безопасности всех Python/CUDA/образов. Исходные уведомления: [Fastify](https://github.com/advisories/GHSA-4mh8-r7rc-xpvc), [shell-quote](https://github.com/advisories/GHSA-pqg4-j6r4-53mv), [source-map-js](https://github.com/advisories/GHSA-68fv-2mgg-jv7q).
- Версия pdfminer.six закреплена на `20260107`, точно как в immutable профиле `document_text_v3`. Свежая установка другой версии больше не ломает проверку версии экстрактора.
- Статические JSON-эталоны тестов включены в переносимые fixtures без изменения байтов. Исторические тесты настоящих оригиналов и архивного worker имеют явно описанные внешние prerequisites; отсутствие таких данных не подменяется искусственным эталоном.

## Локальные проверки

Полный переносимый набор выполнен из отдельного `/tmp`-дерева с собственной установкой npm dependencies: **8480 успешных тестов, 246 skipped, 0 failed**. API: 4472 pass/204 skip, 225 успешных test files/60 skipped. Web: 1193 pass/88 files. Python: 2815 pass/42 skip во всех восьми suites (2857 зарегистрированных тестов). Typecheck и build всех TypeScript workspaces прошли. Отдельный повтор 51 concrete-boundary теста прошёл с обычной командой после добавления локального лимита30s только для валидации полного161-страничного случая; assertions не менялись.

Skipped проверки требуют внешних интеграций/исторических оригиналов. Восемь дополнительных исторических worker modules вне переносимого среза не объявляются пройденными: [PORTABLE_TESTS_20261020.md](PORTABLE_TESTS_20261020.md). Python QA использует существующие локальные third-party dependencies, а свежая runtime-установка worker проверена настоящей Docker-сборкой с закреплённым pdfminer. Повторный `npm audit --json` дал total0. Итоговые квитанции и границы — в `evidence/acceptance.json`; числа установленных image tests ниже не добавляются повторно к8480.

Настоящий merged Compose разрешён для V9 SAMPLE и V9 FULL. Три неправильные конфигурации отклонены: SCAFFOLD, V6, несовпадение выбранного режима. Разрешённая конфигурация отдельно проверена на новый RabbitMQ healthcheck. Контейнеры H100 и веса моделей при этом не запускались.

Собраны локальные Docker-образы API, worker и web. Изолированные проверки без bind mounts и внешней сети сверили 274 файла API/contracts, 177 файлов установленного Python-пакета, 25 файлов правил и 29 web-ресурсов. В установленном Python-пакете прошли 22 теста; обе настоящие синтетические worker-квитанции V9 приняты валидатором и HTTP-сериализатором внутри API-образа. Это проверки установленного кода, не сквозной запуск H100-стека.

Ранее отдельно приняты CPU NORMAL-очередь (9 заданий через ClamAV/RabbitMQ/outbox/worker) и PPM-113 TCP/HTTP read-only fixture. Они относятся к предыдущим принятым образам; их нельзя выдавать за текущий V9 GPU-прогон или новые инженерные пары.

## Фактическое машинное покрытие

Статическая инвентаризация принятого V13: 132 параметра, у 62 настроен хотя бы один включённый atomic rule; всего 63 scalar rules и семь typed rules. Это наличие отдельных способов проверки, не подтверждение полного покрытия 62 параметров и не результат на реальных парах. У 70 atomic rules отсутствуют. Причины: составной trigger — 25, геометрия/топология — 18, нормативное условие/применимость — 10, утверждение/контекст — 6, полнота перечисления и отрицательного доказательства — 4, внешний реестр — 4, конфликт публичного соответствия — 2, конфликт исходного trigger — 1. Точные коды, имена, rule IDs, ограничения и SHA восьми registries: [MACHINE_COVERAGE_V13_20261020.json](MACHINE_COVERAGE_V13_20261020.json).

H100 ускоряет OCR/VLM, но не устанавливает тождество помещений, полноту комплекта, применимость нормы или утверждённую редакцию. Следующая функциональная очередь должна разделять составные пункты на узкие проверяемые подправила и сохранять источник/границы каждой части. Геометрию и внешние реестры нельзя заменять текстовой уверенностью. В текущую заморозку входят уже принятые подправила; расширение всего каталога не заявляется.

## Реальные пары и уверенность

Открытые 10 TRAIN-случаев относятся к одному объекту; это учебные ожидания, не независимая оценка точности. По полным SHA-проверенным оригиналам подтверждены изменения конфигурации П17 и местных систем комнат 147/198. Для П17 сумма расходов РД 3340 + 5720 = 9060 м³/ч совпадает с ПД: снижение расхода не установлено. По комнатам 140/314 обнаружены конфликты соответствия; публичная ссылка TRAIN-0010 на РД:18 не подтверждает комнату 314.

Тёплые полы: машина сохраняет явные номера 267/270/271/272 из одного положительного абзаца ПД. Отсутствие системы в полном РД не доказано. Отдельный офлайн-поиск П17 дал 62 исходные цитаты, один кандидат и 18 отказов; повторные спецификации не удваивают расход. Подробности: [REAL_CONFIRMED_PAIRS_20261020.md](REAL_CONFIRMED_PAIRS_20261020.md).

Политика confidence V2 использует **строго больше 80%** для машинного предупреждения; ровно 80% остаётся кандидатом. Применимая независимая калибровка и квалифицированные доказательства обязательны. Без них вероятность `null`, вывод — кандидат; решение инспектора хранится отдельно. Новая калибровка на этих 10 учебных случаях не заявляется.

## Что требует целевого стенда или независимых данных

- Выделенный H100 80 GB: точный hostname/GPU UUID, CUDA kernel, совместимость драйвера и образов, реальные OCR/VLM/embedding inference, очередь и сохранённое чтение нового V9 release. Готов `infra/h100-readiness.py` с режимами config/runtime/inference и отдельными квитанциями. Подробные условия и команды — в runbook.
- MATRIX OCR остаётся bounded V2; V9 FULL относится к визуальному детектору, не ко всем страницам OCR и не ко всем 132 параметрам. Типизированный v13 путь ограничен 512 страницами на источник; реальный F0201 имеет 676. Автономный полный поиск этого ограничения API не снимает.
- IOS4-078/079 имеют конфликт между публичной разметкой и каталоговым смыслом. Сопоставление сущностей, утверждённые редакции, полнота РД и допустимость изменения ещё не квалифицированы. Число инженерно закрытых параметров этим этапом не повышено.
- Абсолютная геопривязка реального объекта не подтверждена независимо. Проверка преобразования и внутренней согласованности сама по себе не доказывает абсолютную точность.
- Новая браузерная приёмка не выполнена: automatic approval review ранее отклонил браузерную автоматизацию. Причина отказа в доступном журнале не сохранена. Запрет не обходился; HTTP, CLI и SSR не заменяют браузерное взаимодействие.

Публичный адрес, загрузка весов проверяющими, доступ жюри и отправка финальной формы этим комплектом не подтверждены.
