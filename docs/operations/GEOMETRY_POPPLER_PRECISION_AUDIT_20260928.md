# Независимая проверка PDF frame: граница точности

Дата: 28.09.2026. Область: `geometry-proposal-v1`, только разрешённый публичный `F0126` с.17 и синтетические PDF. Предметные коды остаются `ABSTAIN`; геометрия объекта, CRS, пары ПД/РД и findings не устанавливались.

## Проверено

- Оригинальный `F0126` извлечён из разрешённого ZIP, PDF SHA-256 `b4846376535dd97aa24a8e384e0cb71f40792084fc61981dad587b15bbf63088`. `pdfinfo -box -f 17 -l 17` (Poppler 26.05.0) даёт `MediaBox = CropBox = [-1192.08,-841.86,1192.08,841.86]`, `Rotate=0`.
- Независимый `pdftoppm` с фиксированными аргументами `-f 17 -l 17 -r 72 -cropbox -png -singlefile` дал PNG SHA-256 `a1aca1ee57070b4bec5182741bfba296621875eec802c31bd09280c10b61f24a`. Provider повторил рендер, получил те же байты и SHA. Версия renderer закреплена в `poppler-pdftoppm-cropbox-72dpi-png-singlefile-v1@26.05.0`.
- Worker PyMuPDF `_source_page` на тех же исходных байтах выдаёт `MediaBox = CropBox = [-1192.0799560546875,-841.8599853515625,1192.0799560546875,841.8599853515625]`. Расхождение первой координаты `0.000043945312427240424` пункта, второй `0.00001464843751364242` пункта. Текущий API `geometry-evidence.ts` требует строгого равенства массивов box. Поэтому worker artifact с публичного листа сейчас отклонится, хотя оба парсера указывают на ту же страницу. Это проверенный fail-closed предел v1, не ошибка, которую допустимо скрыть подстановкой чисел в provider.
- `pdfseparate` (другой установленный Poppler 25.03.0) пересохраняет страницу `F0126` с `/MediaBox [-1192.08 -841.86 1192.08 841.86]`. Это результат **перезаписи PDF**, не доказательство исходных raw токенов. На отдельном синтетическом `/MediaBox [0 0 123.456789 100]` `pdfinfo -box` печатает `123.46`, а `pdfseparate` — `123.45679`. Следовательно, оба CLI-вывода теряют часть точности и не служат универсальным lossless reader PDF numeric operands.
- Новый provider в `apps/api/src/geometry-poppler-inspection.ts`: `pdfinfo` проверяет frame, SHA привязаны к исходным PDF/PNG, vector map всегда пустой; режим с `pdftoppm` отдельно удостоверяет **точные байты** PNG. Frame-only режим пригоден лишь для `ABSTAIN`. Даже exact PNG не доказывает тип контура, корректность маски, регистрацию, CRS или предметное нарушение. Тесты 6/6, включая четыре Rotate/CropBox, отказ при отсутствии Poppler и публичный `F0126`.

## Решение для следующей версии контракта

Не менять `geometry-proposal-v1` и не округлять доверенный Poppler frame до worker float32. Для review-only навигации можно ввести `geometry-page-frame-v2`: явные `parserProfile`, `boxPrecisionPt`, исходные значения от worker, отдельные canonical box и интервал неопределённости. Worker и API независимо получают page box, затем проверяют попадание каждого исходного значения в интервал, соответствующий **задокументированной** точности парсера; числовые трансформации и допуск в пикселях выводятся из этого интервала. Пограничные пространственные предикаты обязаны давать `ABSTAIN`.

Для положительного геометрического сравнения сначала нужен отдельный независимый PDF-парсер, который проходит page tree, inherited boxes, compressed objects и incremental revisions без исправления повреждённого документа и возвращает исходные числовые значения с известной точностью. После этого сравнить два parser outputs и закрепить версионированный формат координат. `pdfinfo -box` и `pdfseparate` этой гарантии не дают. До неё не подключать `geometry-proposal-v1` к release/save/seal/GET как источник подтверждённых геометрических фактов.
