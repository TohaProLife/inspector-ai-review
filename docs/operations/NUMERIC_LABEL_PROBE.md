# Проверка буквальных числовых меток на публичном корпусе

`numeric_label_probe.py` делает однократный read-only проход по всем страницам
202 разрешённых PDF. Доступ открывается только с отчётом аудита
`public-document-index-audit-v1` со статусом `PASS`, тем же SHA манифеста,
версией индекса и точным инвентарём 203 источника / 202 PDF / 10 142 страницы.
F0194 остаётся только записью инвентаря: содержимое TXT не читается.

Для каждой страницы `get_indexed_page` повторно проверяет SHA кешированного
артефакта, схему, качество текстового слоя и FTS. Страницы `OCR_REQUIRED`
учитываются отдельно; OCR здесь не запускается. Для страниц с пригодным
текстовым слоем проверяются буквальные метки и единицы из
`numeric-family-labels-v1.json` для 31 кода и 35 атрибутов.
SQLite открывается через общий `readonly_index_uri`: после checkpoint WAL
используется `mode=ro&immutable=1`, что позволяет читать индекс с read-only
Docker mount без попытки создать `-shm`. При непустом WAL выбирается обычный
`mode=ro`, чтобы не скрыть ещё не перенесённые изменения. Состояние файла
проверяется до и после прохода.

Отчёт содержит счётчики точных строк, совпавших страниц, страниц с несколькими
значениями одного атрибута и строк с похожей меткой, но неразобранным числом
или единицей. Примеры содержат файл, страницу, индекс строки, SHA страницы и
обрезанный фрагмент текста. По умолчанию сохраняется максимум 20 примеров на
код; число пропущенных примеров явно указано в `examplesTruncated`.
Если более длинный алиас разобрал строку точно, та же строка не считается
похожим совпадением по короткой метке того же атрибута.
Счётчики по каждому файлу и коду сохраняются полностью. Никакой раздел
чертежа не подтверждается, значения не становятся фактами; `findingCount` и
`parameterCoverage` остаются `null`.

Команда на стенде с уже готовыми индексом и PASS-аудитом:

```bash
python3 scripts/probe-public-numeric-labels.py \
  --manifest datasets/reference_methodology/hackathon_gold_20260811/УЧАСТНИКАМ_БЕЗ_ОТВЕТОВ/data/document_manifest.jsonl \
  --index /data/index \
  --audit-report /data/family-batches/index-audit.json \
  --output /data/family-batches/numeric-label-probe.json
```

Для повторной проверки только известных страниц добавить четыре раза
`--page F0001:1` с нужными адресами. Такой отчёт получает
`purpose=TARGETED_ALIAS_VALIDATION_ONLY`, отдельно указывает выбранные и
фактически прочитанные страницы и не заявляет полный повторный проход.

Выходной файл должен быть новым. Инструмент не создаёт директории и не
перезаписывает прежний отчёт. При изменении манифеста, аудита или SQLite во
время прохода, повреждении страницы или несовпадении счётчиков проверка
завершается ошибкой без итогового отчёта.

Локальные тесты используют два разрешённых источника и малый PDF:

```bash
PYTHONPATH=services/worker uv run --no-project \
  --with 'pdfminer.six==20260107' --with 'PyMuPDF==1.27.2.2' \
  python -m unittest services.worker.tests.test_numeric_label_probe -q
```

Интерпретация: ноль точных совпадений не доказывает отсутствие параметра.
Число может находиться в таблице с раздельными колонками, графическом
размере или на странице `OCR_REQUIRED`. Для буквальных подписей в таблицах
добавлен отдельный геометрический review-only проход; его полный адресный
результат описан в `NUMERIC_TABLE_ROW_CANDIDATES.md`.
