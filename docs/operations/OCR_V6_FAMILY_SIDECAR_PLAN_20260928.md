# OCR v6: отдельные семейные наблюдения

Статус: отдельный opt-in release, durable rule stage, независимый API-валидатор
save/seal/GET и UI подключены; изолированный Compose ещё выполняется.

## Граница источника

`DOCUMENT_OCR_LAYOUT` v6 выбирает не более четырёх `OCR_REQUIRED` страниц только
для immutable `CURRENT`/`APPROVED` решения по источнику, раздела `AR`/`VK` и
разрешённой стадии `PD`/`RD`. Отложенная страница остаётся неизвестной. Ни
наличие строки OCR, ни отсутствие строки в обработанной части документа не
являются проверенным фактом элемента или выводом по параметру.

## Следующий opt-in контракт

Отдельный `unresolved-family-ocr-review-v1` формирует строки для `AR-042`,
`IOS2-072`, `IOS3-075`. Каждая строка привязана к SHA исходного PDF,
`document-text-v2`, committed OCR stage, странице и OCR page artifact, точному
индексу OCR-строки, её координатам, score, render и provider. Строка может
попасть в пакет только после совпадения триггеров одного кода в этой же строке.
Три кодовые строки всегда имеют статус `ABSTAIN`; `findingCount` и
`parameterCoverage` равны `null`.

Worker и API независимо проверяют профиль и SHA входов. API при save, seal и
GET заново читает immutable snapshot этого run, а не последние решения по
источнику. При несовпадении источника, текста, страницы, строки или SHA пакет
отклоняется. Старые OCR v4/v5 heat/table профили остаются отдельными.

Положительный синтетический пакет Python с тремя OCR-лидами принят независимым
TypeScript verifier, при этом статус всех трёх кодов остаётся `ABSTAIN`.
Дополнительно API отклоняет пустую кодовую строку, если на выбранной
`OCR_REQUIRED` странице есть точное совпадение её же триггера. Это проверка
только выбранных OCR-страниц; полнота всего документа не утверждается.

## Проверка перед включением

1. Синтетический положительный пример и подмены source/text/OCR/page/line в
   Python и TypeScript — пройдено. Отдельный PostgreSQL тест 2/2 проверил
   fenced OCR read, save, seal, auth GET и tamper; legacy v5 изолирован.
2. Новый opt-in release и полный локальный check — пройдено: API 274 pass/32
   skip, web 60, worker 698, сборка. Весь PostgreSQL suite после sidecar
   изменений прошёл последовательно: 9 файлов, 33 теста, exit 0.
3. Изолированный Compose на разрешённом публичном PDF и аутентифицированный UI
   просмотр. Без реального `CURRENT`/`APPROVED` решения по F0163 ожидается
   пустой пакет и явные причины отложенной обработки.

Даже после этого сравнение ПД/РД допустимо только при проверенной редакции,
паре документов, идентичности элемента и предметном контексте.
