## Повторение

Переносимый runner: `python3 scripts/smoke-cpu-normal.py --output-dir output/cpu-replay-v1 --images-json /absolute/path/images.json --port 28186`. Каждый прогон требует новый каталог: существующий `first-results` вызывает отказ. Нужны Linux amd64, Docker, свободный loopback-порт, минимум 4 GiB доступной RAM, образы и реальные базы сигнатур ClamAV. Runner не скачивает сигнатуры и не обращается к внешним моделям. Фикстуры лежат в `fixtures/cpu-normal-v1` и `services/worker/tests/fixtures/matrix-inventory-v1/pd-both.pdf`.

Перед прогоном собрать API/web из корня с Dockerfile соответствующего приложения, worker из `services/worker`; каждый образ должен иметь label `org.opencontainers.image.revision=<commit>`. Квитанция JSON содержит `revision`, `images` (ровно роли `api`, `worker`, `web`, для каждой `imageId` вида `sha256:...`), `infrastructure` (роли `postgres`, `rabbitmq`, `clamav`, для каждой `imageId` и `originalManifestDigest`). Runner проверяет установленные image IDs, архитектуру, revision labels, фактически установленную каноническую политику V13 и всю карту применённых миграций. Одна revision label не доказывает происхождение сборки: сохраняйте отдельные build logs и квитанцию сборщика.

Ожидаемые foundation manifest digests закреплены в runner. Текущие значения: PostgreSQL `sha256:dca0d688bbb31d3f851502ffcb9c7791387b4fcc544ae434dab41761e5ece317`, RabbitMQ `sha256:11c9d525392fa42ea090550a6d2d8fca0d4c0d0e21912f91f7018296a3f66228`, ClamAV `sha256:49a035c7b33154dc829bc15eff2fe44f1d07c63d3d20b681bf42e8e658d21152`. Передайте соответствующие локальные IDs из проверенной квитанции приобретения/сборки; runner проверяет заявленную связь, но сам заново не реконструирует OCI manifest из локальных слоёв.

Runner создаёт уникальные ресурсы с owner-label, отдельную внутреннюю backend-сеть и вход только через localhost web. Не подключает пользовательские секреты/кэши. Сохраняет редактированные HTTP/SQL/Docker-квитанции и удаляет только свои ресурсы. Проверяет отсутствие изменений исходного runtime и соседних Docker-наборов. Перед запуском остановите изменения исходного runtime в этом checkout, иначе проверка неизменности закономерно откажет.

Для дополнительного настоящего прогона F0201 используйте `--full-source-pdf /absolute/path/F0201.pdf`. Runner принимает только исходные 43,033,348 байт с SHA `0c398d7bca356455568413a6fc3b14044b7e538a902251b80e2a5574d80184fd`, требует минимум 6 GiB доступной RAM, выделяет document/render worker 3 GiB, API 2 GiB с Node heap 768 MiB. После обычного сценария он создаёт отдельный объект, сканирует оригинал, запускает V4 через реальную очередь, читает полный сохранённый artifact и шесть пакетов до страницы 676, проверяет отказы неверной пагинации, перезапускает свои процессы и сравнивает повторное полное чтение. Это отдельный профиль SOURCE_AUDIT_ONLY: нет автоматического OCR, квалификации редакций или инженерных замечаний. Заявленная при тестовой загрузке стадия RD не распространяется на все физические страницы: `pageStages` остаётся пустым, authority unverified. Этот режим должен иметь собственную итоговую квитанцию; наличие кода проверки ещё не означает успешный прогон.
