# IOS4-078: независимая проверка пяти открытых примеров

Проверены `TRAIN-0006`–`TRAIN-0010` из открытого `TRAIN_PUBLIC`. Цель — установить, можно ли вывести положительное заключение IOS4-078 из указанных листов ПД и РД, не используя само значение публичной метки как доказательство. Закрытые ответы и `TEST_HIDDEN` не использовались. Исходники и состояние системы проверялись только на чтение; решения reviewer и результаты проверок не изменялись.

Оригиналы на homeserver прочитаны из `dataset-smoke/F0171_raw.pdf` и `dataset-smoke/F0201_raw.pdf`; размер и SHA-256 каждого заново сверены с манифестом **до** чтения страниц.

Обе страницы заново отрендерены из оригинальных PDF через `pdftoppm -r 100`. Рендер F0171 p.88 побайтно совпал с открытым [PNG ПД](../../datasets/reference_methodology/hackathon_gold_20260811/УЧАСТНИКАМ_БЕЗ_ОТВЕТОВ/evidence_pages/VIO-0003_PD_sheet10_pdf88.png), SHA-256 `abc7464a73110784536607a10694b28e74fa3abeeb0c802ddecbb417835221fb`. Причина этих различий не установлена; визуальная сверка не выявила содержательных отличий. Наблюдения ниже сверены также с текстовым слоем оригиналов. У всех пяти публичных записей указан `document_sheet_number=4` для F0201 p.18, тогда как видимый штамп этого листа показывает `5`; при сопоставлении используется проверенный номер страницы PDF и оригинальный рендер.

## Предметные и процедурные барьеры

1. Исходный [каталог 132 параметров](../../datasets/reference_methodology/hackathon_gold_20260811/УЧАСТНИКАМ_БЕЗ_ОТВЕТОВ/data/parameter_catalog_132.jsonl) определяет IOS4-078 как «Сечения и геометрия воздуховодов общеобменной вентиляции», единица `мм²`, триггер — уменьшение площади сечения в РД. Публичные примеры описывают отсутствие вытяжки или изменение конфигурации, но на указанных листах нет сопоставленной пары сечений одного воздуховода. [Q-04](../architecture/13_OPEN_QUESTIONS.md) остаётся открытым конфликтом отображения кода на демонстрационные формулировки; исходный каталог не переименован.
2. F0201 — смешанный `RD_ID_MIXED`. Штамп самой p.18 содержит `РД`, но сохранённая [карта проверки источника](../../output/f0201-source-audit-20260926/f0201-stage-audit.json) оставляет `pageStages["18"] = "UNRESOLVED"`. В ней `revisionStatus = UNKNOWN`, `approvalStatus = UNKNOWN`, `linkGroupId = null`; остальные страницы также не превращаются в РД по одному штампу. Нужны отдельное подтверждение стадии страницы, актуальности и утверждённой связи с ПД.
3. Для комнаты требуется подтверждённая идентичность помещения/функции между редакциями. Для результата по IOS4-078 требуются ещё конкретная система и ветка, геометрия/размеры воздуховода в ПД и РД, нормализация площади сечения, provenance каждого измерения и проверенная связь редакций. Различие обозначений приборов или отсутствие номера на другом этаже не заменяет эти данные.

**Вывод:** ни один из пяти открытых примеров нельзя независимо превратить в положительный машинный результат IOS4-078 по указанной паре листов. `TRAIN-0008` и `TRAIN-0009` можно показать эксперту как предложения для ручной проверки; все пять требуют `ABSTAIN` / `CLARIFICATION_REQUIRED` до закрытия указанных барьеров. Это не объявляет публичную разметку ошибочной: полный контекст её экспертного решения может находиться за пределами этих двух листов.
