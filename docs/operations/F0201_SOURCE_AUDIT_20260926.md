# Проверка смешанного источника F0201, 26 сентября 2026

Цель: самостоятельно сверить открытый оригинал с пакетом участника, зафиксировать только доказуемые стадии страниц и проверить, как это решение влияет на полный `NORMAL` run. Работа выполнена на изолированном homeserver с RTX 2080 SUPER; H100 недоступна. Использован только `TRAIN_PUBLIC`, без `TEST_HIDDEN` и закрытых ответов.

## Оригинал и граница доказательств

`F0201_raw.pdf` имеет 676 страниц, размер 43 033 348 байт и SHA-256 `0c398d7bca356455568413a6fc3b14044b7e538a902251b80e2a5574d80184fd`. Все три признака совпали с открытым `document_manifest.jsonl`; запись помечена `TRAIN_PUBLIC / INCLUDE / PUBLIC_TRAIN / RD_ID_MIXED`. Исходник в smoke-объекте `OBJ-4993F5F1` имеет ID `FIL-35450220`. Полная повторная загрузка через API также дала тот же SHA-256.

В текстовом слое обнаружены явные признаки рабочих чертежей на страницах 1–4, 6, 10–12 и 14. Страница 14 дополнительно просмотрена как изображение: это лист «Общие данные» с ведомостью рабочих чертежей ОВ и основной надписью РД. [Изображение страницы 14](../../output/f0201-source-audit-20260926/page-14.png). Всего **9 страниц отмечены РД**, остальные **667 оставлены `UNRESOLVED`**. Отсутствие текстовой фразы «исполнительная схема» не доказывает отсутствие ИД: 114 страниц имеют почти пустой текстовый слой. На просмотренных страницах 6 и 13 есть подписи/утверждения отдельных листов, но они не подтверждают актуальность, согласование всего PDF или связь с ПД F0150. Поэтому `revisionStatus=UNKNOWN`, `approvalStatus=UNKNOWN`, `linkGroupId=null`.

[Полный машинный отчёт и карта 676 страниц](../../output/f0201-source-audit-20260926/f0201-stage-audit.json) сохраняют признаки, хеш исходника и ограничения. Карта является ограниченным по доказательствам решением для smoke-объекта, а не полной классификацией смешанного документа.

## Путь решения через приложение

Контракт, API, PostgreSQL, маршрутизатор и экран исходных документов теперь принимают `UNRESOLVED` только в карте смешанного источника. Карта должна назначить состояние каждой странице без пропусков и пересечений. Неопределённые страницы исключаются из поиска РД/ИД и блокируют автоматический вывод. Для одноэтапных файлов карта страниц не принимается. Независимый серверный verifier требует полного подтверждённого разделения перед возможным `CANDIDATE` и проверяет только подходящие страницы РД.

Скрипт применения проверил права reviewer, ID объекта, SHA, число страниц и регистрацию стадий `RD`/`ID`, затем записал append-only решение `04dfa13b-03c4-4130-9e86-ae8b51ace5e0` с content hash `180102322f605017f9306e8f315e68b75d48ba6ac35c063313e2b40fbad4fce9`. Повторное чтение через API совпало. Неизменённое решение экран повторно сохранять не предлагает. [Скриншот после сохранения](../../output/f0201-source-audit-20260926/source-review-unresolved.png).

```bash
python3 scripts/apply-public-source-review-proposal.py \
  --base-url http://127.0.0.1:18081 \
  --credentials-file infra/.smoke-source-reviewer \
  --proposal dataset-smoke/probes/f0201-stage-audit-20260926.json \
  --object-id OBJ-4993F5F1 --source-file-id FIL-35450220
```

Команда намеренно откажется повторно записать решение для этого источника. Пароль reviewer хранится только на homeserver.

## Полный повторный прогон

После записи решения создан immutable run `CHK-9443227E`. При чтении его сохранённого артефакта обнаружены две записи причин для одного источника РД; маршрутизатор исправлен так, чтобы объединять их без потери кодов. После пересборки worker повторный immutable run `CHK-4672F74B` завершил все 10 jobs как `SUCCEEDED` с первой попытки. Итог `PARTIAL`, 131 параметр `UNSUPPORTED`, PZ-002 `PARTIAL`, findings 0. [Сводка из сохранённых БД-артефактов финального run](../../output/f0201-source-audit-20260926/durable-run-final.json) показывает, что snapshot содержит именно hash решения выше. Маршрут РД охватывает ровно 9 страниц, находит предметный текст F0201 p.14; извлечены факты F0150 p.26 (`11 618,27 м²`) и F0201 p.14 (`11 030,3 кв.м`). У источника РД одна запись причин: `STAGE_PAGES_UNRESOLVED`, `REVISION_UNRESOLVED`, `APPROVAL_UNRESOLVED`. Правило сохранило `CLARIFICATION_REQUIRED/REVISION_UNRESOLVED`, без числового заключения. Из 305 страниц, требующих OCR в текущем scope, обработаны 2, 303 отложены.

Таким образом, частичная разметка реально проходит через snapshot, маршрутизацию, извлечение и правило, но не превращается в утверждение о нарушении. Для предметного решения ещё нужны подтверждённые редакции/согласование и связь ПД–РД, завершённое разделение релевантных страниц и доказанная полнота поиска. Визуальное распознавание элементов чертежей и остальные 131 параметр этим прогоном не проверены.
