# Независимая геопривязка: источник и граница доверия

## Реализованный путь

API читает `GET /api/objects/:id/files/:sourceFileId/geometry-registrations/:registrationId` только после проверки сессии и доступа к исходнику. Пользовательский HTTP-запрос не принимает контрольные точки и не может записать доверенный пакет.

Оператор монтирует каталог `GEOMETRY_TRUST_STORE` только для чтения. Каталог содержит:

- `<registrationId>.json`: envelope `signed-geometry-control-source-v1` с подписью Ed25519;
- `<keyId>.pub.pem`: разрешённый публичный ключ оператора;
- независимый PDF/CSV/JSON с координатами; имя без директорий, SHA-256 в подписанном envelope.

Payload связывает организацию, объект, sourceFileId и SHA оригинала, регистрационный номер, происхождение независимого документа (`authority`, `reference`), согласовавшего и время, а также полный `geometry-registration-v1` packet. Независимый документ должен иметь другой SHA, чем исходный PDF. Это необходимая проверка, но другой SHA сам по себе не доказывает независимость: оператор обязан проверить происхождение и принадлежность реперов.

Подпись ставится офлайн:

```sh
node_modules/.bin/tsx scripts/sign-geometry-control-source.ts payload.json /secure/operator-private.pem operator registration.json
```

Приватный ключ не монтируется в API. Утилита отказывается перезаписывать существующий файл. Формат payload определён в `apps/api/src/geometry-trust-store.ts`; структура packet и требования к 4–32 точкам — в `services/worker/inspector_worker/geometry_registration_v1.py` и [описании численной проверки](GEOMETRY_REGISTRATION_V1_20260928.md).

При чтении проверяются подпись, SHA обоих документов, scope, реальное наличие страницы и её поворот через `pdfinfo`; затем вычисляются affine transform, holdout residual, inverse roundtrip и границы масштаба/области. Symlink-файлы не принимаются. В этом runtime доступен только `CANONICAL_VISIBLE_NORMALIZED`; растровый режим закрыт до независимого закрепления renderer/frame. Действует существующий лимит чтения оригинала API 8 MiB; независимого документа — 64 MiB; envelope — 256 KiB.

Успех возвращает `REVIEW_ONLY`, измеренные ошибки и происхождение; `findings=[]`, `coverage=null`. Это проверка привязки для инспектора, не предметный вывод о нарушении. Неподтверждённые точки, неверные ключи, изменённые байты, ошибочные holdout и другой объект не принимаются. UI показывает причину недоступности и не считает синхронизацию панелей геопривязкой.

В ТЗ перечислены требуемые акты геодезической основы и исполнительные схемы. Сам перечень не означает, что эти документы предоставлены. В проверенных путях не найден отдельный согласованный каталог реперов с парами «точка PDF / проектная координата», независимыми holdout, допустимой ошибкой и подтверждённой принадлежностью объекту/редакции. Подпись «МСК-50» не задаёт однозначное определение CRS. Единственный центр не позволяет проверить affine регистрацию.

Поэтому реальные исходники не объявлены зарегистрированными. Извлечение топоплана из того же PDF или переименование файла не создаёт независимый источник. Для внешней квалификации абсолютного положения нужен оригинал геодезического отчёта/ведомости либо иной независимый координатный источник и согласованные пары точек с допустимой погрешностью; затем оператор устанавливает подписанный пакет. Численный и доверительный пути проверены на явно синтетических данных, включая подмену источника, страницы, ключа, объекта и holdout.

## Уточнение после архитектурного разбора 17.10

Отсутствие независимой ведомости **не блокирует относительное сравнение ПД/РД** или измерения в локальной проектной сетке. Текущий signed trust store реализует более узкий путь независимой абсолютной квалификации; его ограничения нельзя распространять на все геометрические задачи.

На PDF-странице 13 (лист 3 «Разбивочный план осей», /Rotate=270) ПЗУ-2024 найдены и визуально проверены четыре пары подписей X/Y: (5408,70; 24280,48), (5446,79; 24285,87), (5409,95; 24358,42), (5447,95; 24357,81). Их выноски/пересечения осей, единицы, согласованность с размерными линиями и контрольная ошибка ещё не квалифицированы. Bbox текста не является координатой самого репера. Это пригодный вход для следующего этапа **локальной** привязки, но не независимая съёмка.

Обе проверенные версии содержат /VP и /Measure с /Subtype/RL, но не /GPTS, /LPTS, /GCS или /LGIDict: measurement metadata не доказывает геопривязку. План нового локального пути и его приоритет — в [плане к 20 октября](DELIVERY_PLAN_20261020.md). Реальный transform этим аудитом не вычислен, квалификация остаётся открытой.
