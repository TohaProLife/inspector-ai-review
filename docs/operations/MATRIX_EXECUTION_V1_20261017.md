Для каждого атома отдельно заданы атрибут, размерность, допустимые текстовые обозначения, семейство сравнения, строгий порог, разделы документов, необходимые доказательства области и допустимые пары стадий.

Пары с ИД разрешены только явно перечисленным правилам. Наличие ИД во входных данных добавляет предусмотренные реестром результаты, включая отказ при отсутствии требуемого факта. Один атом может выдать несколько результатов для разных явно установленных сущностей; поэтому число строк результатов не всегда равно числу групп.

## Наблюдения и квалификация

[`matrix_engine.py`](../../services/worker/inspector_worker/matrix_engine.py) извлекает факты из канонических `document-text-v2` **до** проверки CURRENT/APPROVED. Факт содержит SHA исходника, стадию, PDF-страницу, исходный блок/строку, bbox, исходный текст, исходное и нормализованное значение, единицу и версию extractor. Составная строка таблицы сохраняет каждый исходный фрагмент. Метаданные штампа остаются кандидатами и не меняют ручные решения об актуальности или согласовании.

Число, размерность и подпись должны соответствовать конкретному правилу. Многозначная строка, диапазон или неоднозначный выбор столбца не дают произвольно выбранного значения. Единица из отдельного заголовка допускает видимое наблюдение с `TABLE_HEADER_UNIT_SCOPE_UNVERIFIED`, но не квалифицированное сравнение. Положительное предложение о степени огнестойкости и классе конструктивной пожарной опасности извлекается фиксированной грамматикой; отрицание не подменяется положительным утверждением.

Для квалифицированного результата нужны доказательства обоих источников:

- текущая согласованная редакция, допустимый раздел и одна подтверждённая группа документов;
- `ENTITY_SCOPE`, привязанный к точным source ID, SHA, object ID, input manifest и явно названной сущности;
- все дополнительные контексты конкретного атома; для нормы — применимость, код параметра, атрибут, порог и размерность; для ограничения ТУ — соответствующее проектное ограничение;
- для ИД — собственное доказательство `DRAWING_SECTION_VERIFIED`, которое нельзя взять из другого документа;
- отсутствие флагов недостаточного качества текста, неопределённой стадии или неподтверждённой единицы заголовка.

`linkGroupId` не устанавливает идентичность здания или элемента. Один пакет может включать соседние здания. Признаки `CURRENT`, `APPROVED`, сущность и полнота не угадываются по тексту, имени файла или частоте совпадений. API получает доказательства из аутентифицированного снимка review; доказательства из ответа worker не становятся доверенными.

На атом и сущность выбирается ровно один ожидаемый и один фактический факт. Пропуск, несовпадение сущностей, несколько значений, неизвестный контекст и нулевой относительный baseline имеют разные явные причины отказа. Отрицательный результат требует `RULE_SCOPE_COMPLETE:<ruleId>` на обоих источниках. Без него совпадение двух чисел не становится `NEGATIVE_VERIFIED`.

## Точная математика и независимая проверка

Семейства: различие, увеличение, уменьшение, относительное отклонение, относительное увеличение, снижение класса, нижняя и верхняя нормативная граница. Python использует `Decimal`; независимый [`matrix-rule-verifier.ts`](../../apps/api/src/matrix-rule-verifier.ts) — рациональную арифметику `bigint`, с воспроизведением Decimal ROUND_HALF_EVEN для отображаемого относительного delta. Порог сравнивается строго: ровно 1% при пороге 1% не срабатывает, 1.0001% срабатывает. `EI-60` и `E-30` относятся к разным доменам; числовое сравнение этих марок не выполняется. Исходный ПД, уже находящийся за нормативной границей, даёт `PROJECT_BASELINE_OUTSIDE_BOUND`, а не новую ошибку РД.

API независимо проверяет исходные фрагменты, геометрию bbox, подпись атрибута и нормализацию значения. Atomic verifier затем пересчитывает весь обязательный набор правил/стадий/сущностей, ID ссылок, значения, delta, статусы, причины и покрытие. Пропущенный или лишний результат, самоназначенный `FAILED`, чужая сущность, подмена доказательства, единицы или области отвергаются.

Покрытие рассчитывается по фактическим атомам и их результатам:

- `UNSUPPORTED`: нет установленного атома;
- `PARTIAL`: атом установлен, но остаются пропуски, отказ от сравнения или неподтверждённая полнота;
- `EVALUATED`: у параметра нет остаточного catalog gap, все запущенные атомы квалифицированы и каждый задействованный источник имеет `PARAMETER_SCOPE_COMPLETE:<parameterCode>` для той же сущности;
- `TECHNICAL_FAILURE`: отдельный технический отказ исполнения; worker не вправе подменить им произвольный атомарный результат.

`EVALUATED` относится к сконфигурированной области этого запуска. Это не заявление о 100% автоматизации всех формулировок параметра и не разрешение считать отсутствие находки отсутствием нарушения.

## Уверенность

Детерминированное совпадение условия, OCR score, связывание источников и подтверждение человеком не являются вероятностью корректности машинного вывода. У текущего generic профиля нет калиброванной вероятности: `confidenceKind=NOT_ESTIMABLE`, probability и calibrationVersion равны null. Такие выводы остаются кандидатами. Порог показа предупреждения 0.80 предусмотрен общей политикой только для доказательно квалифицированного вывода с закреплённой версией калибровки; этот срез сам калибровку не объявляет.
