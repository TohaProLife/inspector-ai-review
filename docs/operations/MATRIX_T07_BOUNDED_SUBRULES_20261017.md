# T07: ограниченные числовые subrules, 17 октября 2026

## Реализованный срез

К существующему реестру добавлены восемь исполняемых атомов четырёх параметров.
Исходные названия, trigger и SHA каталога 132 параметров сохранены. Каждый атом
сравнивает уменьшение одного явно подписанного числового значения по одной
reviewed сущности. Пустая строка, отсутствие подписи и отсутствие документа не
считаются нулевым значением или отсутствующим элементом.

| Параметр | Attribute | Каноническая единица | Literal labels | Секции ПД / actual |
| --- | --- | --- | --- | --- |
| IOS2-073 | `PUMP_FLOW_RATE` | `m3/h` | Расход насоса; Расход насосной станции | IOS2 / VK |
| IOS2-073 | `PUMP_HEAD` | `m` | Напор насоса; Напор насосной станции | IOS2 / VK |
| IOS4-077 | `RADIATOR_SECTION_COUNT` | `count` | Число секций радиатора; Количество секций радиатора | IOS4 / OV |
| IOS4-077 | `RADIATOR_HEAT_OUTPUT` | `kW` | Теплоотдача радиатора | IOS4 / OV |
| PPM-112 | `SMOKE_CONTROL_FAN_FLOW_RATE` | `m3/h` | Производительность вентилятора ДУ; Производительность вентилятора подпора воздуха | PPM / OV |
| PPM-112 | `SMOKE_CONTROL_FAN_PRESSURE` | `Pa` | Давление вентилятора ДУ; Давление вентилятора подпора воздуха | PPM / OV |

`ruleId = matrix-<parameterCode lowercase>-<attribute lowercase>`, version `1`.
Все восемь: `family=DECREASE`, `threshold=null`, `enabled=true`, без нормативной
границы. Число секций — `INTEGER`; остальные — `DECIMAL`. Равенство и увеличение
не срабатывают; отрицательный результат дополнительно требует прежнего proof
полноты области конкретного правила.

IOS2-073, IOS4-077, PPM-112 разрешают только `PD_RD`. Для SPZU-032 исходный
каталог явно содержит уменьшение толщины в РД и ИД: разрешены `PD_RD`, `PD_ID`,
`RD_ID`. ИД требует собственного section proof и всех остальных source/context
gates. Контекст РД к ИД не переносится.

## Грамматика и единицы

Используется существующая literal-грамматика matrix engine: полная подпись,
одно числовое значение и явная единица. Проза, диапазоны, альтернативы,
паспортные максимумы и подбор произвольных чисел из соседней строки не
добавлены. Существующая строгая геометрическая сборка literal-строки таблицы
сохраняет каждый исходный фрагмент; она не устанавливает reviewed scope.

- `m3/h`: `м³/ч`, `м3/ч`, `m3/h`.
- `m` и `mm`: явные `м/m`, `см/cm`, `мм/mm`, с точными коэффициентами.
- `count`: `шт.`, `шт`; дробное число секций отвергается.
- `kW`: `кВт`, `kW`, `Вт` с коэффициентом 0.001, `МВт` с коэффициентом 1000.
- Новая размерность `Pa`: `Па/Pa` с коэффициентом 1, `кПа/kPa` с коэффициентом
  1000. Регистр значим; МПа, мПа, bar и неизвестные единицы не конвертируются.

Нормализация и сравнение выполняются через `Decimal`. В проверке сохранено
различие после более 90 десятичных знаков; float и округление для сравнения
не используются.

## Контракт подтверждённого контекста

Каждый новый атом объявляет:

```json
{
  "requiredContext": ["ATOMIC_SUBRULE_SCOPE:matrix-ios2-073-pump_flow_rate"],
  "subruleContext": {
    "schemaVersion": "matched-atomic-context-v1",
    "componentRole": "POTABLE_WATER_PUMP",
    "identityFields": [
      "componentKey", "zoneKey", "operatingModeKey", "measurementBasisKey"
    ]
  }
}
```

Роли: `POTABLE_WATER_PUMP`, `RADIATOR`, `SMOKE_CONTROL_FAN`, `ASPHALT_LAYER`,
`CRUSHED_STONE_LAYER`. Для каждого source нужен отдельный аутентифицированный
proof. Структурный пример, не подтверждение реального документа:

```json
{
  "status": "VERIFIED",
  "reference": "fixture:reviewed-pump-duty-point",
  "sourceFileId": "pd",
  "sourceSha256": "<source SHA-256>",
  "objectId": "<internal object UUID>",
  "inputManifestHash": "<immutable input manifest SHA-256>",
  "entityKey": "pump:P1",
  "parameterCode": "IOS2-073",
  "attribute": "PUMP_FLOW_RATE",
  "canonicalUnit": "m3/h",
  "componentRole": "POTABLE_WATER_PUMP",
  "componentKey": "pump:P1",
  "zoneKey": "V1:zone-A",
  "operatingModeKey": "normal-duty:design-point-1",
  "measurementBasisKey": "volumetric-flow-at-duty-point"
}
```

Прежние binding source ID/SHA, object, manifest, entity, status/reference
проверяются независимо для обоих источников. `parameterCode`, `attribute`,
`canonicalUnit`, `componentRole` обязаны соответствовать атому. Четыре identity
поля должны быть непустыми строками и побайтно совпадать между источниками.
Отсутствие, подмена, иной режим/зона/компонент/основа измерения дают
`CONTEXT_UNVERIFIED:<proofKey>` и `qualified=false`.

Подтверждение означает проверку смыслового контекста по указанному основанию:

- насос: одна рабочая точка и режим, а не максимальные Q/H из разных частей
  характеристики;
- радиатор: одинаковые помещение/нагрузка, температурный режим и основа
  определения теплоотдачи;
- вентилятор: назначение ДУ/подпора, одна система и рабочие условия;
- дорожный слой: одинаковый компонент, зона и поперечный разрез/основа измерения.

Extractor не создаёт эти ключи из похожих подписей. Один `linkGroupId` не
доказывает контекст. CURRENT/APPROVED, ENTITY_SCOPE, секции, link group и
полнота отрицательного scope остаются обязательными прежними gates.

## Оставшиеся gaps и честное покрытие

У каждого из четырёх entry сохранён ненулевой `gap` с префиксом
`PARTIAL_SUBRULES_ONLY:`:

- IOS2-073: мощность насоса и полная рабочая характеристика не реализованы;
- IOS4-077: произвольная замена модели и полная спецификация не реализованы;
- PPM-112: полная характеристика вентилятора и диапазон режимов не реализованы;
- SPZU-032: исключение слоя требует полного inventory; другие слои и полный
  послойный состав не реализованы.

Даже при успешном сравнении обоих атомов и наличии parameter scope proof эти
entry остаются `PARTIAL`, а coverage reason содержит их точный gap. Явный 0 мм
может быть сравнён как записанная толщина; он не превращается в вывод об
отсутствии слоя. Пустые `MISSING_EVIDENCE` не считаются successful comparisons.
AR-044 остаётся `UNSUPPORTED`: шкалы мембран и полного inventory кровли нет.

В реестре 132 entry: 49 имеют хотя бы один атом, всего 55 атомов и 84 разрешённые
группы стадий; 83 entry остаются без реализации. Эти числа описывают установленные
правила, а не процент реально проверенных документов или полноту параметров.
Probability не калибровалась и этим этапом не добавлена.

Canonical registry SHA-256:
`45443b2e85afe07074e4e2f96d78f81b9ab38366417068408b8e32b9b16ccd6d`.
Старые run сохраняют свои immutable definitions/hash; новые локальные definitions
не переписывают их результат. Развёртывание и browser gate выполняет основной
агент после seal предыдущего реального прогона.

## Проверки

Python matrix suite: 41 тест. Новые T07 проверки охватывают все восемь атомов:
уменьшение/равенство/увеличение, преобразования единиц, неправильную размерность,
missing evidence, wrong entity, неизвестный review, каждый отсутствующий и
несовпадающий context binding/identity, отдельный ИД proof, частичные gaps,
дробные секции, явный 0 мм, отклонение ослабленного registry context policy.
Тестовый source helper создаёт полный bound context только в fixtures и доступен
существующему Python/TypeScript golden generator.

Отдельно проверяются durable engine source pin и прежние family/fact comparator
tests. Успешные локальные fixtures не доказывают real-source extraction новой
грамматики, аутентифицированное review реального оборудования или browser/runtime
поведение после deployment.

Что проверить в следующем gate:

- независимый TS verifier принимает согласованные goldens и отвергает подмену
  режима/зоны/компонента, единицы и самоотчёт qualified;
- новый durable run получает именно новый registry и engine SHA; старые sealed
  run сохраняют прежние байты;
- UI показывает отдельные atomic outcomes и PARTIAL с явными оставшимися gaps,
  сохраняя число successful comparisons отдельно от abstentions.
