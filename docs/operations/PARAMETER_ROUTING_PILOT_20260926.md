# Пилот маршрутизации по параметру (26.09.2026)

Первый исполняемый срез [ADR-012](../architecture/01_DECISIONS.md#adr-012-маршрутизация-доказательств-по-параметру): `parameter_routing.py` получает frozen manifest источников, одно правило навигации и проверенные артефакты `document-text-v2`. Выход — отсортированные листы-кандидаты с ID/хешем файла, номером страницы, индексами текстовых блоков и причинами выбора. Пустой поиск никогда не помечается как доказанное отсутствие элемента.

## Что реализовано

- Проверка объекта, стадий ПД/РД/ИД, идентичности SHA-256 артефакта и качества каждой страницы. Смешанный РД/ИД без `pageStages` уходит в `STAGE_SEGMENTATION_REQUIRED`; явно `UNRESOLVED` страницы исключаются из маршрута, а источник получает `STAGE_PAGES_UNRESOLVED`.
- `CURRENT`/`APPROVED` требуются для `sourceGate=REVISION_APPROVAL_CLEARED`. Неизвестные статусы сохраняют страницы как предложения для просмотра с `REVISION_APPROVAL_REVIEW_REQUIRED`. Устаревшие и несогласованные источники исключаются из кандидатов. Даже cleared-источник ещё не связан с парным документом.
- Для страниц без пригодного text layer возвращается очередь `ocrPages`. Отдельно выводятся `pageCountInScope` и `textSearchedPageCount`. Текстовые совпадения по предметным и локальным терминам ранжируются воспроизводимо; совпадение раздела добавляет только слабый бонус. Это буквальный поиск внутри текстовых блоков, а не оценка полноты смыслового поиска.
- Результат маршрутизатора всегда `NAVIGATION_ONLY`, `comparisonStatus=NOT_EVALUATED`, `absenceVerified=false`. Отдельный пилот PZ-002 ниже добавляет извлечение площади и типизированное сравнение; графические проверки приборов, подключений и выносок остаются вне этого пилота.

Маршрут `IOS4-077` остаётся **офлайн-пилотом** и не меняет coverage. Правило `pilot-ios4-077-navigation-v1.json` задаёт только поиск страниц отопительных приборов; оно не доказывает сравнение секций, теплоотдачи и нагрузки помещения. Ниже описан отдельно подключённый durable-пилот только для `PZ-002`.

## Запуск на открытых материалах

Нужны распакованные оригинальные PDF, `document_manifest.jsonl` из пакета участника и Python с зависимостями worker. Пример из корня репозитория (пути заменить на фактический каталог распаковки):

```bash
PYTHONPATH=services/worker uv run --no-project \
  --with 'pdfminer.six>=20250506,<20270000' \
  python3 -m inspector_worker.public_pilot \
  --manifest datasets/reference_methodology/hackathon_gold_20260811/УЧАСТНИКАМ_БЕЗ_ОТВЕТОВ/data/document_manifest.jsonl \
  --materials-root /path/to/unpacked/participant/materials \
  --source-id F0171 --source-id F0201 \
  --rule services/worker/rules/pilot-ios4-077-navigation-v1.json \
  --output /tmp/ios4-077-route.json
```

Скрипт принимает только строки `TRAIN_PUBLIC` + `INCLUDE` + `PUBLIC_TRAIN`, перед разбором сверяет размер и SHA-256 каждого PDF. Уже извлечённые файлы вне исходного дерева можно указать через `--source F0171=/path/to/F0171_raw.pdf`: сверка размера и хеша сохраняется. F0201 помечен `RD_ID_MIXED`, поэтому пока нет проверенной постраничной разметки, его листы не становятся РД-кандидатами. Пакет не содержит статусов актуальности и согласования: все источники из этого запуска остаются на проверке.

## Числовой пилот PZ-002

`analysis_pilot.py` связывает проверенный manifest, `document-text-v2`, маршрут, извлечение фразы «общая площадь здания», сравнение `Decimal` с порогом строго `> 0.01` и проверку двух локаторов. Источник с пустым text layer при включённом локальном `document-ai` проходит рендер и OCR; координаты OCR сохраняются отдельно в `RENDER_TOP_LEFT_PX` вместе с SHA рендера и профилем. Подмена значения, единицы, страницы, исходного хеша или OCR-строки блокирует кандидат. Бюджет `--max-ocr-pages` помечает непросмотренные страницы, а неполный поиск даёт `CLARIFICATION_REQUIRED/SEARCH_SCOPE_INCOMPLETE`. Порог без превышения не даёт `NEGATIVE_VERIFIED`: достоверный сертификат полноты поиска ещё не реализован.

Если подпись, единица и число разбиты по ячейкам, `table_rows.py` повторно извлекает геометрию строк только на страницах с предметным попаданием. Каждая из трёх строк привязана к индексу сохранённого блока, индексу строки и координатам PDF; все блоки повторного разбора должны дословно совпасть с сохранённым text artifact. Несколько возможных пар единица/число на строке дают отказ. `--max-table-pages` (по умолчанию 8) ограничивает эту работу, число отложенных страниц записывается и препятствует выводу о полном поиске. Координаты строк первоначально предлагает worker, поэтому для возможного `CANDIDATE` требуется ещё один локальный OCR того же листа: ровно одна строка с той же подписью и числом, с score не ниже 0,8. API независимо сверяет оба вида локаторов, OCR artifact hash, текст, геометрию и fingerprint. Без OCR-согласования таблица остаётся только для ревью. На реальных документах этот путь создал факт для ревью, но finding не был разрешён из-за неподтверждённых источников и неполного OCR-поиска.

При малом бюджете OCR применяется `subject-stage-neighbor-v1`: сначала страницы `OCR_REQUIRED` рядом с предметными попаданиями, с чередованием релевантных ПД/РД, затем стабильный fallback. Этот порядок не означает, что соседняя страница содержит тот же объект, и не доказывает полноту. Он отдельно проверен на исходных `TRAIN_PUBLIC` F0150/F0201: выбраны p.29 и p.9, OCR выполнен, новых фактов общей площади нет.

```bash
PYTHONPATH=services/worker uv run --no-project \
  --with 'pdfminer.six>=20250506,<20270000' \
  python3 -m inspector_worker.analysis_pilot \
  --manifest datasets/reference_methodology/hackathon_gold_20260811/УЧАСТНИКАМ_БЕЗ_ОТВЕТОВ/data/document_manifest.jsonl \
  --materials-root /path/to/unpacked/participant/materials \
  --source-id F_PD --source-id F_RD \
  --source-decisions /path/to/reviewed-source-decisions.json \
  --navigation-rule services/worker/rules/pilot-pz-002-navigation-v1.json \
  --numeric-rule services/worker/rules/pilot-pz-002-numeric-v1.json \
  --document-ai-url http://127.0.0.1:8080 \
  --max-table-pages 8 \
  --max-table-ocr-pages 2 \
  --output /tmp/pz-002-pilot.json
```

`F_PD`/`F_RD` здесь placeholders: нужны реальные ПД/РД файлы с сопоставимой общей площадью и проверенные решения об актуальности, согласовании и связи. В открытом manifest 203 включённых `TRAIN_PUBLIC` источника, но ни один не помечен разделом `PZ`; РД раздела `AR` также нет. На homeserver проверена пара `F0150` (ПД/OTHER) и `F0201` (смешанный РД/ИД/ОВ): значения общей площади видны на исходных страницах, но их юридическая и проектная сопоставимость не установлена. В 10 строках `public_train_checks.jsonl` нет PZ-002, поэтому для него отсутствует опубликованный положительный контроль качества. Смешанные `RD_ID_MIXED` требуют `pageStages` для всех страниц. `source-decisions` привязаны к SHA каждого PDF и содержат `basis.reference`; пилот не выводит согласование автоматически.

## Проверено и ограничения

- Текущий suite: 61 тест worker, включая маршрут, OCR-происхождение, запрет подмены, геометрию строки таблицы, сравнение, durable-адаптер и освобождение AMQP event loop на долгой задаче: `OK`.
- Локальный Docker build worker успешен; встроенный CLI запускается в контейнере. На двух созданных для теста PDF с реальным `pdfminer` полный CLI дал `CANDIDATE`, площадь 100/102 м², дельту 0,02 и два проверяемых локатора. Это синтетические PDF, не предметная оценка на конкурсных данных.
- Полный офлайн-прогон на синтетическом PDF с настоящим text extraction: 1 ПД-кандидат с `REVISION_APPROVAL_REVIEW_REQUIRED`, обязательная РД помечена `MISSING_SOURCE`, сравнение не выполнено.
- `extract_pdf_text_artifact` прошёл отдельный smoke на доступном локальном методическом PDF: 1 страница, 1 text-layer candidate. Этот файл не использовался для оценки точности и не является исходной парой ПД/РД.
- На homeserver выполнен реальный сквозной NORMAL-run `CHK-64A1D37B` с исходными `TRAIN_PUBLIC` F0150/F0201: все 10 jobs `SUCCEEDED`, итог `PARTIAL`, coverage 131 `UNSUPPORTED` и одна `PARTIAL`, 0 findings. OCR в этом первом run не был подключён. Повторный run `CHK-673B2639` с локальным `document-ai` также завершил все 10 jobs, обработал OCR двух страниц из 398 требующих его и извлёк один факт РД, но не нашёл машинный факт ПД: 0 findings. Детали в [журнале smoke](HOMESERVER_SMOKE.md#durable-pz-002-на-проверенных-исходных-документах-26-сентября).
- Run `CHK-1E3D8D30` после включения геометрии таблицы завершил 10/10 jobs, сохранил два факта (ПД F0150 p.26, РД F0201 p.14), итог `PARTIAL`, 0 findings; статус правила `CLARIFICATION_REQUIRED/REVISION_UNRESOLVED`. Новый порядок OCR отдельно вызвал локальный provider на F0150 p.29 и F0201 p.9; оба ответа без факта площади. Run `CHK-A9C2743D` сохранил также локальный OCR и crosscheck F0150 p.26 с тем же числом; 10/10 jobs `SUCCEEDED`, 0 findings из-за неподтверждённых исходных документов. [Сводка](HOMESERVER_SMOKE.md#строка-таблицы-в-полном-durable-прогоне).
- Повторный `CHK-B93E6F4C` после исправления AMQP heartbeat завершил 10/10 jobs с первой попытки, тем же hash rule artifact и без перезапуска двух активных worker. Покрытие и предметный статус не изменились.

Теперь API принимает ненулевой артефакт `RULE_EVALUATION` только в отдельном `DRAFT` release `PILOT_PZ002`; остальные стадии сохраняют scaffold-артефакты. [Частичная проверка F0201](F0201_SOURCE_AUDIT_20260926.md) дала 9 страниц РД и 667 `UNRESOLVED`; новый durable run использовал 9 страниц и p.14, сохранив `CLARIFICATION_REQUIRED`. На реальных открытых источниках ещё нужны завершённое разделение релевантных страниц смешанных PDF, решения об актуальности/согласовании и измерение recall. Отсутствие текстового совпадения не доказывает отсутствие прибора.

Downstream job с действующим attempt получает сохранённый text artifact через `GET /api/internal/v1/jobs/:id/text-artifacts/:sourceFileId`. API проверяет принадлежность source immutable manifest, SHA входного PDF, SHA и размер JSON; Python-клиент `durable_text.py` повторяет проверки и валидирует структуру `document-text-v2`. `PilotPz002RuleAdapter` теперь вызывает этот клиент и сохраняет ненулевой результат через durable job. PostgreSQL integration проверяет доступ, fence, чужой source, terminal job, `DRAFT` release, сохранённый результат и `PARTIAL` coverage.

## Включение в приложении

В `.env.laptop` или `.env.server` укажите `INSPECTOR_ANALYSIS_PROFILE=PILOT_PZ002` перед запуском стека. По умолчанию остаётся `SCAFFOLD`. Compose передаёт `DOCUMENT_PROVIDER_BASE_URL` rules worker; `PZ002_MAX_OCR_PAGES` ограничивает страницы `OCR_REQUIRED` (по умолчанию 2), `PZ002_MAX_TABLE_PAGES` — повторный разбор таблиц (8), `PZ002_MAX_TABLE_OCR_PAGES` — визуальную перепроверку найденных строк таблицы (2). После изменения профиля нужен новый NORMAL-run: старые run сохраняют свой immutable release.

Решения об актуальности, согласовании, группе связи и постраничной стадии смешанных PDF записываются через аутентифицированный `POST /api/objects/:id/files/:sourceFileId/source-review`. Тело содержит `sourceSha256`, `revisionStatus`, `approvalStatus`, `linkGroupId`, `pageStages` и `basis.reference`; запрос требует сессию инспектора, CSRF и `Idempotency-Key`. `GET` по тому же пути показывает последнее решение. Новый run включает хеш решения в immutable manifest и выдаёт именно этот snapshot в lease. После изменения решения запустите новый run.

В веб-приложении из результатов NORMAL-run доступен экран «Исходные документы». Он получает файлы через `GET /api/objects/:id/files`, позволяет скачать исходный PDF через `GET /api/objects/:id/files/:sourceFileId/content` и требует полной непересекающейся карты страниц для файла, зарегистрированного одновременно как РД и ИД. Если смешанный PDF первоначально загружен только в одну стадию, те же байты нужно добавить и во вторую: дедупликация по SHA оставляет прежний source ID. Это не определяет редакцию, согласование и границу стадий автоматически. Проверка на открытом F0201 и команды — в [homeserver smoke](HOMESERVER_SMOKE.md#проверка-исходных-файлов-в-приложении-26-сентября-2026).

API принимает `CANDIDATE` только для полностью квалифицированного текстового слоя: самостоятельно сканирует сохранённые блоки всех источников run, повторно проверяет две метки «общая площадь здания» (включая три ячейки одной строки), единицы, числа, порог строго больше 1%, PDF-локаторы, SHA файлов, согласование и связь ПД/РД, а затем сохраняет finding для ревью. Подмена значения отвергается до записи результата. OCR-кандидат durable worker переводит в `CLARIFICATION_REQUIRED/OCR_CANDIDATE_REQUIRES_INDEPENDENT_REVIEW` с сохранением локаторов; серверного verifier рендера и строк OCR ещё нет. `NEGATIVE_VERIFIED`, визуальные параметры чертежей, проверка отсутствия, 131 другое правило и предметная оценка по `TRAIN_PUBLIC` остаются отдельной работой. `TEST_HIDDEN` и закрытые ответы не используются для настройки.
