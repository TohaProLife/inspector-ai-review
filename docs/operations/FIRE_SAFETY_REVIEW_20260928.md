# PPM-102 / PPM-113: открытая предметная проверка

Отдельный офлайн-извлекатель `fire-safety-review-v1` даёт только адресные
лексические наблюдения для эксперта. Он не создаёт типизированный факт,
сопоставление ПД/РД, нарушение или покрытие параметра. Оба кода остаются
`REVIEW_ONLY_ABSTAIN`.

## Область и целостность

Каталог определяет `PPM-102` как деление здания на пожарные отсеки: для
сравнения нужны схема и площади ПД/ППМ, кладочные планы и маркировка
отсеков РД/АР-КР, непрерывность противопожарных стен. `PPM-113` — расход
воды и число струй ВПВ: нужны расчёт ПД/ППМ, планы и аксонометрия РД/ВК,
а также контекст диаметра кольца и количества кранов. Одно совпадение
термина не отвечает ни одному из этих определений.

Проверены четыре PDF с публичными метками `TRAIN_PUBLIC / INCLUDE /
PUBLIC_TRAIN`: `F0117` ПД/OTHER (название файла МОПБ), `F0193` ПД/PB,
`F0164` ПД/VK, `F0204` смешанная РД/ИД/VK. Первые две последние записи
принадлежат объекту `OBJ-TYUMENSKAYA-5-GOLD-SEED`, `F0117` — другому
объекту `OBJ-NOVOSLOBODSKAYA`. Метка `OTHER` не превращается автоматически
в подтверждённый раздел ППМ. `RD_ID_MIXED` не превращается автоматически
в утверждённую РД.

Манифест SHA-256
`853225daec1888fbed19bbeb45e958154135f069799cea883dcd3c754c6c4ee7`.
Независимый полный `PASS`-аудит v4 SHA-256
`69ef56fc23e779dfed25aa60c5615be3ee58f244200c6620c2b1ddaec335f49a`;
`indexVersionHash=7d7dfa2f3e0279a91095`. Каждый из четырёх оригинальных
PDF считан из `01_ПАКЕТ_УЧАСТНИКАМ_3_ОБЪЕКТА.zip` на homeserver и полностью
сверен с манифестом по размеру и SHA-256. Для каждой индексированной
страницы повторно проверены источник, номер, disposition, SHA сжатого
артефакта, кандидаты раздела и таблицы. Закрытые ответы и `TEST_HIDDEN`
не читались.

## Решение первого прохода по OCR

Сильнейшие текстовые лиды и шесть конкретных страниц удалось проверить
по исходным пикселям. Два просмотренных листа смешанного VK-комплекта
относятся к водоотведению. На первом проходе OCR не запускался;
после уточнения области все 69 `OCR_REQUIRED` страниц обработаны адресно,
с SHA-кешем и независимым аудитом ниже. Отсутствие строки в текстовом
слое или результате OCR не доказывает отсутствие элемента на изображении.

Для обоих кодов `comparableFacts=[]`, `finding=null`, `findingCount=null`,
`parameterCoverage=null`. Нужны проверенные редакции одного объекта,
конкретный отсек/ветвь ВПВ и их связь ПД/РД. Для PPM-102 дополнительно
нужны графические границы и непрерывность стен; для PPM-113 — определение
расхода, число струй, краны и геометрия сети. До этого результат `ABSTAIN`.

## Адресный OCR 69 страниц

Продолжение выполнено в изолированном homeserver-окружении с локальным
PaddleOCR. Только страницы с точным `OCR_REQUIRED` в уже проверенных четырёх
PDF допущены в очередь: F0117 — 1, F0193 — 5, F0164 — 0, F0204 — 63.
Каждый исходный PDF повторно сверен по размеру, SHA и числу страниц;
каждая индексная страница — по SHA артефакта. Ключ кеша включает SHA PDF,
физическую страницу, DPI и закреплённые профили рендера и OCR. Размер
рендера ограничен 20 млн пикселей. Кешированный ответ каждой страницы
проверен повторным рендером **того же исходного PDF**; SHA пиксельного PNG
совпал с SHA в OCR-артефакте 69/69 раз. Даже cache HIT не миновал эту
проверку.

Первый проход завершился **69/69**, без технических пропусков: 2 `HIT`,
67 `MISS_WRITTEN`, 11 431 OCR-строка, **1 буквальный лид** по двум кодам.
Результат [ocr-report.json](../../output/fire-safety-review-20260928/ocr-report.json),
SHA-256 `ab42acefd4dba238df5760de6c4eadaecd8adebf35f2c63473a7c8fc7d7e6be1`.
Отдельный offline-аудитор повторно прочитал 4 оригинала из открытого ZIP,
394 индексные страницы, 69 receipts и 69 файлов кеша. Он пересчитал
ключи, SHA, профиль, список OCR-лидов и суммарные счётчики: **PASS**.
[ocr-audit.json](../../output/fire-safety-review-20260928/ocr-audit.json),
SHA-256 `8c3c649aba01fa98d8adbfa86e4d665f0d1bc14202ff5b743ac17267bfa894d5`.
Все [69 receipts](../../output/fire-safety-review-20260928/ocr-receipts/)
скопированы локально и ещё раз сверены по SHA с аудитом.

Единственный лид: F0204, физическая с. 6, OCR line 100,
`Внутренний противопожарный водопровод`, SHA строки
`3d8769870d12326a2069a4e9659603a8d74cbbdc28ffc1112cf2b2ca1825df45`.

он находится **в ведомости ссылочных документов**: название СП 10.13130.2009.
Это не описание ветви ВПВ, расхода, числа струй, диаметра или кранов.
[Отдельный триаж](../../output/fire-safety-review-20260928/ocr-lead-triage.json)

Остальные 68 страниц не дали буквального совпадения узких шаблонов;
это **не отрицательный результат по параметрам**. OCR мог пропустить

топологию и идентичность элемента.

После OCR оба кода остаются `ABSTAIN`, `comparableFacts=[]`,
`finding=null`, `findingCount=null`, `parameterCoverage=null`. Положительных
экспертных решений и проверенной пары ПД/РД нет. Для новой редакции или
сопоставления нужны ручная проверка источника, конкретного отсека/ветви,
условий расчёта и визуальной геометрии чертежей.
