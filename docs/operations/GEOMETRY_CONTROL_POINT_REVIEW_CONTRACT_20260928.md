# Геометрические контрольные точки: чистый review contract v1

28.09.2026. `apps/api/src/geometry-control-point-review.ts` задаёт отдельную
версию ручного решения для одной страницы PDF. Контракт пока не подключён к
маршрутам, БД, save/seal/GET, UI или worker runtime.

Вход содержит `geometry-page-frame-v2` artifact, исходные PDF/PNG bytes,
канонический review artifact и `authenticatedActorId`, который вызывающая
сторона обязана получить **независимо** из своей системы аутентификации.
Контракт вызывает строгую проверку исходной страницы через raw PDF page tree
и exact Poppler render. Затем связывает review с `frameContentHash`,
`sourceFileId`, полным SHA-256 PDF, номером страницы, профилем рендера,
полным SHA-256 PNG и размером PNG. Сам review artifact имеет отдельный
канонический SHA-256 и лимит 64 KiB. Self-hash фиксирует содержимое, но
не подтверждает подлинность решения; durable слой должен закрепить digest
и неизменяемый audit trail.

`decision=null` даёт `UNVERIFIED`. Решение `REJECT` требует совпадения
`actorId` с независимо переданным `authenticatedActorId`, ID, UTC timestamp
и причину; результат `REJECTED` без принятых точек/CRS. `CONFIRM` с такой же
привязкой даёт `CONFIRMED_REVIEW_ONLY` **только** при полной схеме. Target frame
требует вид (`LOCAL_2D` или `PROJECTED_CRS`), ID, единицы, оси, границы
масштаба и адрес доказательства на той же странице PDF. Для `PROJECTED_CRS`
дополнительно требуются authority, code, SHA определения CRS, горизонтальный
датум и явное значение либо `null` эпохи координат. Для каждой из 4–32 точек
обязательны ID, evidenceRef, координаты страницы и проекта, адрес на исходной
странице и адрес источника проектных координат с SHA/страницей/locator.
Повтор ID или координат, неполные метаданные и выход за растр дают
`UNVERIFIED`; принятые поля остаются `null`. Подмена PDF/page/frame/render,
неверный hash, неподтверждённый actor и неподдержанная схема также дают
`UNVERIFIED`.

`CONFIRMED_REVIEW_ONLY` означает лишь структурно полное и привязанное к
аутентифицированному actor ручное решение. Контракт **не проверяет байты
внешнего геодезического источника**, истинность CRS/репера, полномочия actor,
принадлежность точек одному объекту/фазе или качество affine регистрации.
Ссылка SHA/locator для проектной координаты остаётся декларацией до
независимой проверки источника. Следующий отдельный gate должен установить
авторитетный источник CRS/датума и каждой проектной точки; затем явный выбор
трёх обучающих точек, независимые holdout, допуск и query domain проходят
`geometry-registration-v1`. Его результат по-прежнему `REVIEW_ONLY` и
`facts=[]`. Ни одно состояние текущего контракта не даёт предметных
`findings` или coverage: они всегда `[]` и `null`.

Публичный оригинал `F0126` с.17 подтверждает только page-frame v2 и остаётся
`ABSTAIN`: утверждённых CRS, реперов, контрольных пар и решения эксперта нет.
Положительный тест этого контракта полностью синтетический и не объявляет
публичную страницу зарегистрированной. Реальные CURRENT/APPROVED источники,
утверждённые пары ПД/РД и решения эксперта отсутствуют.

Локальная проверка: `npm exec --workspace=@inspector-ai/api -- vitest run
test/geometry-control-point-review.test.ts` — 4/4; `npm run typecheck
--workspace=@inspector-ai/api` — PASS. Тесты проверяют три разных review
состояния, подмену PDF/page/render/hash, неполный CRS и provenance точки.
