# T22: высота ограждения территории

SPZU-036 получил один исполняемый атом: снижение высоты одного и того же участка ограждения между ПД и РД. Это частичное покрытие каталожного параметра. Замена типа ограждения, размеры ворот, геометрия чертежа, полный перечень участков и сравнение с ИД этим атомом не проверяются.

Полная каноническая текстовая выгрузка: SHA-256 `f1a7f8ab64f879a7ac3fcb714f14293b24961a559f8665f2d121da38b6d00907`, 19 текстовых страниц и 8 страниц, требующих OCR. Фикстура сохраняет все 23 блока PDF14 без редактирования текста, координат или окружения; номер страницы явно перенесён в синтетическую страницу 1 только для unit-тестов.

На PDF14 блок17 содержит проектное описание установки ограждения высотой 2,5 м. Извлечение сохраняет две исходные строки 17:0 и17:1, их независимые рамки и общую рамку. Указанная рядом длина 480,0 м не превращается в факт высоты. Полный replay всех27 страниц даёт ровно один факт `TERRITORY_FENCE_HEIGHT=2.5m`, 0 квалифицированных сравнений; источник остаётся UNKNOWN, entity отсутствует.

Поддержаны два ограниченных формата:

- Полная строка «Высота ограждения территории: 2.5 м» с одним числом и единицей. Диапазоны, альтернативы, разделители тысяч, обратный порядок unit/value и чужие виды ограждений не принимаются.
- Две точные соседние строки одного исходного многострочного блока ПД: начало «По границе территории объекта проектом предусмотрена установка» и продолжение «ограждения высотой …, протяженностью … с учетом длины ворот и». Требуются исходные рамки строк, последовательные индексы, отступ первой строки 0–40 000mpt, расхождение правых краёв не более2000mpt, высоты строк не более1000mpt, межстрочный просвет 0–18000mpt. Реальный абзац имеет отступ35400mpt. Конкурирующее начало, пересекающаяся посторонняя строка или грубая/невалидная рамка блокируют этот разбор. Для РД такой проектный абзац не поддержан.

## Контекст сравнения

`matrix-spzu-036-territory_fence_height`, версия1, family DECREASE, единицаm, только PD_RD. Универсальный нормативный порог не придуман: сравниваются значения проекта и рабочей документации.

Перед квалификацией независимо подтверждаются актуальность/согласование источников, связь документов, участок и тип ограждения, отсутствие согласованного изменения и точные привязки фактов. Обязательные условия: APPROVED_CHANGE_STATUS, FENCE_TYPE_IDENTITY, ZONE_IDENTITY и собственный ATOMIC_SUBRULE_SCOPE. `approvedChangePresent` должен быть false.

Typed role `TERRITORY_FENCE_SEGMENT` требует совпадения componentKey, zoneKey, operatingModeKey и measurementBasisKey на обеих сторонах. Назначение строго TERRITORY_BOUNDARY; база измерения строго FINISHED_GROUND_TO_FENCE_TOP. Даже одинаковые ошибочные базы двух источников отклоняются. Снятие typed policy или atomic gate не позволяет превратить известное правило в обычное неограниченное числовое сравнение. Python и TypeScript проверяют это независимо.

UI оставляет назначение, базу и согласованное изменение пустыми до явного решения пользователя. Тип ограждения проверяется отдельно от числовой высоты. Понижение после подтверждения всех условий создаёт CANDIDATE. Равенство/увеличение без доказанного полного охвата не объявляет весь параметр проверенным. Вероятность не вычисляется: независимой калибровки для этого правила нет.
