# Кандидаты набора мер из публичного индекса

`presence_family_candidates.py` извлекает отдельные положительные упоминания
для ровно восьми кодов семейства `PRESENCE_SET`. Словарь признаков и якорей
области находится в `services/worker/rules/presence-family-labels-v1.json`.
Загрузчик сверяет его с SHA исходного каталога, SHA 47 правил-кандидатов,
именем кода, атрибутом и полным набором восьми кодов. Изменившаяся или
неполная политика останавливает извлечение.

| Код | Какие предметные упоминания ищутся | Обязательная область строки |
| --- | --- | --- |
| `SPZU-039` | открытый лоток; закрытый пристенный дренаж | именованная зона дренажа |
| `AR-053` | демпферная лента; звукоизоляционная прокладка | именованный узел перегородки |
| `POD-092` | защитный короб; защитное ограждение сети | действующая сеть и зона работы техники |
| `POD-095` | гидроорошение; пылезащитный экран; водяная пушка | зона демонтажа |
| `ODI-120` | стационарный или откидной поручень | санузел МГН |
| `ODI-122` | предупреждающая тактильная полоса | лестница или дверь |
| `ODI-123` | кнопка вызова помощи; двусторонняя связь | санузел МГН или вход |
| `ZU-129` | счётчик электричества, воды или тепла | тот же энергоноситель и именованный узел учёта, квартира или здание |

Каждый якорь области должен быть на **той же физической строке**. Для
объектных якорей нужен номер или буквенно-числовое обозначение. Две разные
области одного типа на строке дают abstention. Слово признака сверяется как
ограниченная словами фраза из словаря; похожее слово и общее название раздела
не подходят. Для `ZU-129` энергоноситель должен соответствовать виду
счётчика. Отрицание, исключение, демонтаж, план, вариант, условное требование
или вопрос отбрасывают всю строку. Такая консервативная фильтрация может
пропускать реальные элементы; это осознанный предел кандидата.

На входе `load_indexed_page_evidence` проверяет разрешённый публичный PDF,
SHA источника и артефакта страницы, полноту индекса и качество текста;
извлекатель повторно сверяет SHA выбранного доказательства. Страница
`OCR_REQUIRED` требует адресного OCR и не превращается в текстовый кандидат.
Для `UNKNOWN_ABSTAIN` в правиле нужен `section_resolution` со статусом
`VERIFIED`, ссылкой, `sourceFileId`, SHA источника и манифеста, стадией,
категорией манифеста и точной маркой чертежа. Для точной категории, когда
марка отличается от неё, нужен такой же `drawing_section_proof`.

Результат сохраняет исходную строку, координаты, номер страницы, индексы
строки/блока, стадию, раздел, марку, SHA источника/страницы/доказательства,
код, атрибут и ключ предметного признака. Всегда `CANDIDATE`, `REVIEW_ONLY`,
`NON_EXECUTING_ABSTAIN`. Никакой набор не объявляется полным: отсутствие
упоминания, отсутствие элемента в РД, связь ПД и РД, редакция, finding и
coverage не выводятся. Нулевой результат означает только отсутствие
квалифицированного упоминания среди выбранных строк.

Проверка восьми отображений и отказов при неоднозначной области, неверном
разделе, SHA, отрицании и будущей мере:

```bash
PYTHONPATH=services/worker python3 -m unittest \
  services.worker.tests.test_presence_family_candidates -q
```

Следующий этап: разбор пропусков в таблицах, графике и OCR на публичных PDF.
Результаты нельзя превращать в проверку отсутствия без независимого
доказательства полного поискового охвата и сопоставления областей.

## Пакетный поиск по 10 142 страницам

`presence_family_corpus.py` читает **только** завершённый индекс 202 публичных
PDF и запись F0194 как метаданные. Сначала требует отчёт аудита со статусом
`PASS`, нулём ошибок, SHA точного публичного манифеста, совпавшей версией
индекса и всеми 10 142 проверенными артефактами страниц. Полный текст F0194,
`TEST_HIDDEN` и закрытые ответы не открываются. CLI не позволяет подменить
проверочные числа и SHA; приватные аргументы в Python API служат лишь для
малого синтетического теста.

Один FTS-запрос по буквальным корням выбирает страницы. По умолчанию
просматриваются все найденные страницы и все блоки с корнями. Блоки читаются
порциями до 16; слишком большие порции автоматически делятся. Строки заново
проверяются через `indexed_page_evidence` с SHA и координатами. Упоминания
в источнике с неразрешённым разделом идут в `nearMissCounts` с причиной
`SECTION_PROOF_REQUIRED`; программа не выдумывает подтверждение раздела.
Остальные причины включают неясную область, отрицание/будущий контекст,
неверную стадию или раздел и несоответствие вида счётчика энергоносителю.
Примеры ограничены числом на код и содержат исходную строку, локатор и SHA.

Все страницы `OCR_REQUIRED` перечисляются отдельной адресной очередью
`ocrQueue`; их текст не ищется через FTS. Очередь по умолчанию ограничена
2000 адресами, фактическое число и обрезка указаны в отчёте. Отчёт всегда
содержит `searchCompleteness=NOT_ESTABLISHED`,
`absenceInference=PROHIBITED`, `findingCount=null` и
`parameterCoverage=null`. Статус `FTS_HITS_SCANNED` означает проход по
найденным FTS-страницам, а не полноту перечня мер. `PARTIAL` означает
лимит страниц либо ошибку выбранного доказательства.

После полного `PASS` аудита запускать:

```bash
PYTHONPATH=services/worker python3 -m inspector_worker.presence_family_corpus \
  --manifest datasets/reference_methodology/hackathon_gold_20260811/УЧАСТНИКАМ_БЕЗ_ОТВЕТОВ/data/document_manifest.jsonl \
  --index /path/to/public-index \
  --audit /path/to/public-index-audit.json \
  > /path/to/presence-corpus-report.json
```

Тесты включают реальный PDF, индекс, полный аудит, положительный кандидат,
близкие совпадения, пустую страницу для OCR и отказ при неверном аудите:

```bash
PYTHONPATH=services/worker uv run --no-project \
  --with 'pdfminer.six==20260107' --with 'PyMuPDF==1.27.2.2' \
  python -m unittest \
  services.worker.tests.test_presence_family_candidates \
  services.worker.tests.test_presence_family_corpus -q
```

## Мост к проверенному сравнению состава, 28.09.2026

Offline `evaluate_candidate_observations` теперь принимает `reviewed_sets`
только для восьми правил `PRESENCE_SET`. Ключ — `observationId`; значение
содержит точный `typed-fact-v1` с `rawUnit=set` и отдельное решение
`review`. Решение обязано иметь `status=VERIFIED`, ссылку и привязку к SHA
манифеста, исходника, текстового артефакта, странице, локатору, коду,
атрибуту, наблюдению и `factId`. Текст факта сверяется с SHA исходного
блока, локатор — с машинным наблюдением. Лишняя запись, подмена или
неполный набор review дают `SET_ENUMERATION_REVIEW_INVALID`.

Даже такой факт подтверждает лишь **якорь перечисления**. Для вывода
сравнения нужны независимо проверенные источники `CURRENT/APPROVED`, связь
одной сущности ПД/РД, применимый раздел, контекст и `set_scope` с полными
перечнями обеих сторон и одинаковой областью поиска. Без любого звена
результат `ABSTAIN`; при всех синтетически заданных доказательствах —
только `REVIEW_REQUIRED`, никогда finding или coverage. Все восемь кодов
проверены в тестах положительного review-пути и отказов. На исходном
публичном корпусе доказанных полных перечней по-прежнему нет; реальные
сравнения и полнота обнаружения этим изменением не подтверждены.
Полный worker-набор в локальном Python 3.12 с `pdfminer.six==20260107`
прошёл 619/619 тестов. На homeserver три профильных модуля прошли 41 тест
в контейнере без сети. Ранее запущенный полный набор в старом образе
homeserver не был пригоден для вывода о регрессии: checkout и образ имели
разные версии соседних OCR/registry-модулей; проверки нового моста
проводились с исходниками, примонтированными только на чтение.

Следующая проверка связала каждое наблюдение и каждый числовой/классовый
`typedFact` с **тем же** `inputManifestHash`, что и весь пакет. Подменённый
манифест теперь даёт `OBSERVATION_PACK_INVALID` или
`TYPED_OBSERVATION_UNAVAILABLE`; передача `reviewed_sets` для другого
семейства отвергается как `INPUT_INVALID`. Полный локальный worker-набор
после проверки SHA-связки прошёл 620/620; после проверки аргумента
`reviewed_sets` профильный модуль прошёл 13/13.
