# Независимая разметка полного листа TRAIN_PUBLIC

Инструмент [`scripts/prepare-visual-annotation.py`](../../scripts/prepare-visual-annotation.py) создаёт автономную папку для одного исходного PDF-листа и одного класса. В папке только рендер **целого видимого листа**, пустой черновик и локальный HTML для рисования рамок. Геометрические предложения модели, известные ответы и тестовые метки в генератор не передаются. Это заготовка для эксперта, а не подтверждённая разметка.

## Подготовка

```bash
python3 scripts/prepare-visual-annotation.py \
  --manifest datasets/reference_methodology/hackathon_gold_20260811/УЧАСТНИКАМ_БЕЗ_ОТВЕТОВ/data/document_manifest.jsonl \
  --source-pdf /path/to/original/F0202.pdf \
  --file-id F0202 --page 16 --class RADIATOR \
  --output-dir /path/to/independent-reviews/F0202-p16-RADIATOR
```

Нужен PyMuPDF (`fitz`). Скрипт до рендера требует ровно одну запись `file_id` в manifest с `TRAIN_PUBLIC / INCLUDE / PUBLIC_TRAIN`, проверяет размер и SHA-256 исходного PDF, число страниц и отсутствие шифрования. Папка назначения должна отсутствовать; готовая папка не перезаписывается. По умолчанию рендер ограничен 180 dpi, 8192 px по длинной стороне и 48 млн пикселей. Листы, которые нельзя целиком представить в этих пределах с короткой стороной от 128 px, отклоняются. Снижение масштаба на крупном чертеже может скрыть мелкие символы: эксперт должен оценить читаемость до утверждения.

## Что находится в папке

- `page.png` — весь видимый лист без подсказок модели;
- `index.html` — локальный просмотрщик: масштаб, рисование рамок, отмена и выгрузка JSONL; сетевых запросов нет;
- `metadata.json` — идентификатор файла, SHA исходника и manifest, геометрия, угол поворота, размер PNG, коэффициенты px→pt;
- `draft.jsonl` — начальная запись без рамок.

Откройте `index.html` локально. Нарисуйте **все** экземпляры выбранного класса после просмотра всего листа, включая края и штамп. Кнопка выгрузки создаст один JSONL для пары «лист, класс». При подтверждённом нуле рамок файл всё равно содержит `instances: []`, но статус остаётся `UNREVIEWED`: генератор не знает, просмотрен ли лист полностью. Проверьте экспорт и сохраните его отдельно от исходного черновика.

Рамки экспортируются в `DISPLAY_POINT_TOP_LEFT`: начало в левом верхнем углу видимой, уже повёрнутой страницы; размеры и координаты в PDF display points, как требует [`evaluate-visual-proposals.py`](../../scripts/evaluate-visual-proposals.py). `metadata.json` хранит фактический масштаб PNG, поэтому округление пиксельного размера не смещает координаты. При повороте PDF экспорт не использует неповёрнутый user-space.

## Граница подтверждения

Черновик имеет точную структуру полей `visual-full-sheet-review-v1`, которую читает оценщик, но намеренно содержит `coverage=UNREVIEWED`, `review_status=UNREVIEWED`, пустой `reviewer_id`, `annotation_origin=UNVERIFIED_DRAFT` и `created_without_proposals=false`. Сам генератор и HTML **никогда** не пишут `HUMAN_APPROVED` или `FULL_SHEET`. Оценщик обязан вернуть `NOT_ESTIMABLE` для такого файла.

Отдельный уполномоченный эксперт должен открыть оригинал без предложений модели, подтвердить полный обход листа, класс, каждый прямоугольник либо отсутствие экземпляров и сохранить решение с идентификатором, датой и SHA исходного PDF/черновика в отдельном журнале утверждения. Только после этого оператор формирует утверждённую JSONL запись согласно [контракту оценки](VISUAL_PROPOSAL_EVALUATION.md). Структурная корректность JSONL не подтверждает личность или независимость эксперта; текущий оценщик также указывает `HUMAN_ATTESTED_NOT_EXTERNALLY_AUTHENTICATED`.

При нескольких листах и классах создайте отдельную папку для каждой пары. Не показывайте annotator'у `visual-proposals.json`, старые overlay, public verdict или чужие рамки до завершения независимого просмотра. Не используйте `TEST_HIDDEN` и закрытые ответы. Не трактуйте метрики на одном листе как качество на всём корпусе.

Проверка инструмента: `python3 -m unittest scripts.tests.test_prepare_visual_annotation -v`. Тесты покрывают отказ для закрытого split, неверного SHA/числа страниц, перезаписи, синтаксис браузерного скрипта и PDF с поворотом 90°.
