# Пакетный поиск кандидатов по семействам

`scripts/batch-public-family-candidates.py` читает **готовый** индекс
`TRAIN_PUBLIC / INCLUDE / PUBLIC_TRAIN`. По умолчанию берёт только десять
кандидатных PDF для `KR-061`/`KR-062` из [плана семейств](PARAMETER_FAMILY_BATCH_PLAN.md):
ПД `F0105–F0107`, РД `F0136, F0139–F0144`. Иные семейства требуют явно указать
источники и слова для FTS-поиска. Код не читает исходные PDF заново, таблицы
разметки, `TEST_HIDDEN` или текст `F0194`.

```bash
python3 scripts/batch-public-family-candidates.py \
  --manifest datasets/reference_methodology/hackathon_gold_20260811/УЧАСТНИКАМ_БЕЗ_ОТВЕТОВ/data/document_manifest.jsonl \
  --index /path/to/completed-public-index \
  --output /path/to/new-kr-review.json
```

Явный набор для другого семейства:

```bash
python3 scripts/batch-public-family-candidates.py \
  --index /path/to/completed-public-index \
  --family RELATIVE_DELTA \
  --source-id F0105 --source-id F0140 \
  --term бетон* --term объем* \
  --output /path/to/new-volume-review.json
```

Перед FTS-поиском инструмент сверяет каждый ID с точным public manifest,
статус `COMPLETE`, объект/стадию/раздел, SHA и число страниц. Он проверяет,
что каждая страница выбранных PDF имеет ровно одну запись FTS и нет лишних
адресов. Если запись пропала или продублирована, пакет завершается ошибкой.
Эта проверка выполняется только для выбранных исходников. FTS даёт только
кандидатные страницы. Лимит распределяется по источникам с чередованием ПД/РД;
внутри файла страницы упорядочены по FTS-рангу. `sourceSelection` показывает
для каждого файла число совпавших, выбранных и пропущенных страниц. Если лимит
меньше числа файлов с совпадениями, часть файлов не войдёт в выдачу и это
видно по `omittedTextPages`. Для каждой найденной страницы повторно проверяется
SHA артефакта, выбираются **исходные** номера блоков и вызывается
`load_indexed_page_evidence`. Выход содержит текст и координаты этих блоков,
строки, признаки таблиц/разделов, версию парсера, качество чтения и SHA
источника/страницы/evidence. `reviewQueue` содержит точные локаторы для
человека. Страницы `OCR_REQUIRED` входят в отдельную `ocrQueue`; OCR здесь не
запускается. Списки ограничены `--max-pages`, `--max-blocks-per-page`,
`--max-ocr-pages`; усечение помечается явно.

Совпадение слова, найденный текст или пустая очередь **не доказывают** наличие
или отсутствие факта. `findingCount` и `parameterCoverage` равны `null`.
Следующий шаг для `KR-061/062`: вручную просмотреть найденные PDF-локаторы,
извлечь толщину стены и диаметр продольной арматуры с типом измерения,
этажом/зоной/элементом, затем подтвердить редакцию, согласование и связь
ПД–РД. Без этих проверок сравнение остаётся `ABSTAIN`. Если словарь поиска
не нашёл страницу, её отсутствие нужно проверять отдельно; сканированные
страницы проходят адресный OCR с кешем по SHA и номеру страницы.

Локальная проверка синтетического индекса:

```bash
PYTHONPATH=services/worker uv run --no-project \
  --with 'pdfminer.six==20260107' --with 'PyMuPDF==1.27.2.2' \
  python -m unittest services.worker.tests.test_public_family_batch -v
```

Сквозное подключение к durable pipeline и покрытие кодов этим инструментом
не подтверждаются. Перед подключением нужен пакетный просмотр реальных
PDF и отдельная проверка ложных совпадений, OCR, версий и связей элементов.
