# Opt-in сохранение кандидатов OCR_ROW

Миграция 025 добавляет неизменяемый `run_ocr_typed_fact_candidate_artifacts`.
Только при `INSPECTOR_OCR_TYPED_FACT_CANDIDATE_PROFILE=v1` профиль входит в
hash immutable release. После снимков решений об источнике, транскрипции и
предметной применимости сервер выводит `typed-fact-v2` с отдельным
локатором `OCR_ROW`, сохраняет канонические байты и SHA. При seal и GET
сервер заново выводит кандидатов из исходных OCR/rule артефактов, PDF SHA
и трёх решений и сравнивает с сохранённым артефактом. Подмена артефакта
или снимка блокирует чтение/запечатывание. Старый `typed-fact-v1` с
`TEXT_BLOCK` и сравнения не менялись.

Профиль остаётся review-only: `findingCount=0`, `coverageCount=0`. Сейчас
числовой конструктор принимает только единицы, нормализуемые существующим
закреплённым контрактом (`m2`, `m3`, `mm`, `count`). Другие единицы,
классы и наборы возвращают воздержание; положительная применимость строки
сама по себе не создаёт finding или сравнение ПД/РД.

Локальная проверка: полный `npm run check` прошёл (API 219 passed/27
skipped, web 33, worker 648, сборка). PostgreSQL integration вместе с
журналом, снимком и durable артефактом: 25/25; отдельный синтетический
положительный тест проверил непустой `OCR_ROW`, отрицательное перекрытие,
FK, immutable trigger и отказ при подмене. Реальных экспертных решений
в тесте нет.

На изолированном homeserver Compose применена миграция 025 и включён
opt-in только для новых запусков. Публичный F0202 повторно обработан в
`CHK-927C1BB0`: 10 jobs `SUCCEEDED`, `PARTIAL` 7/125, 0 findings,
17 некодированных OCR-строк и три воздержания; 47 кандидатных правил
остались `ABSTAIN`. Release закрепил `ocr-typed-fact-candidates-v1`.
Неизменяемый артефакт создан один раз: 0 OCR-фактов, 0 снимков
применимости, SHA-256
`deedabe2bd2abfbb607e0811701270a0fef1e682c0de9a28e49d14f9320c860a`.
Ноль ожидаем: решений эксперта по этим строкам нет. Авторизованный GET
вернул 200/0, анонимный 401, неизвестный профиль 400; подложный POST
в журнал применимости вернул 409 без записи.

Этот этап проверяет выпуск артефакта и границы доверия, а не точность OCR,
качество извлечения или полноту 132 кодов. Для реального сравнения нужны
проверенные ПД/РД источники, редакции, разделы, предметный контекст,
связь одного элемента и одобренное изменение.
