# T11: контекст таблицы ПД на соседней странице

## Исполняемый контракт

Дополнительный путь извлечения применяется только к PD / CONCRETE_CLASS / B_CLASS. Полный заголовок о тяжёлом бетоне и классах по прочности на сжатие должен быть одним блоком из 1–3 строк на текущей или непосредственно предыдущей PDF-странице. Два подходящих заголовка блокируют извлечение. Страница заголовка также должна иметь установленную стадию ПД.

Текущая страница содержит ровно один заголовок области «Подземная часть». Ниже допускаются ограниченные названия фундаментной плиты, пилонов/колонн, стен, этажных плит и плиты покрытия. Напротив строки требуется единственная точная ячейка класса B/В с числовой частью; альтернативы, несколько колонок, пересекающиеся строки и грубые неоднозначные рамки отклоняются. Допуск центров — четверть высоты строки, горизонтальный промежуток — не более 32 её высот. Следующая проза завершает таблицу.

`evidenceFragments` и основная рамка относятся только к строке и значению на странице таблицы. `contextFragments` содержат отдельные `pageNumber`, `blockId`, `rawText`, нормализованную рамку и роль `ATTRIBUTE_HEADER` / `TABLE_SCOPE`. Идентификатор наблюдения включает весь массив контекста. Для прежних наблюдений без массива состав идентификатора не меняется.

Сервер независимо воспроизводит ограниченную грамматику и геометрию по сохранённому каноническому текстовому слою. Каждый контекст проверяется по собственному оригинальному листу. Удаление/подмена контекста или флага `TABLE_CONTEXT_UNVERIFIED`, даже с новым ID, не разрешает квалифицировать табличную догадку. OCR-качество любой участвующей страницы также сохраняет ограничение.

## Реальное основание

Публичный исходник F0106, SHA `ae8b16439650526a5ef6e1975c852fa38c2ab4466cd73ab725a47bcb32a6b655`: заголовок PDF49/block10:0–1, область PDF50/block0:0, шесть строк PDF50/block1:0,1:1,1:2,1:4,1:5,1:6 с соответствующими ячейками block2. Заголовки и координаты проверены на исходном PDF; номера листов не подменяются номерами страниц.

На каноническом пакете F0106/F0141/F0144 получено 10 наблюдений вместо 4, включая шесть новых строк ПД. Независимый TS boundary принял эти же источники. Все шесть остаются с `entityKey=null`, неизвестными статусами источников и `TABLE_CONTEXT_UNVERIFIED`; квалифицированных сравнений — 0. Реестр не изменён: 49 параметров / 55 атомов / 83 без реализации.

## Проверки и последующие задачи

Python: 48 matrix + 4 source-pin + 82 существующие регрессии прошли. API: 18 focused tests и 133 общих Python goldens прошли; web: 4 focused tests прошли. PostgreSQL: 27 integration tests прошли. Полный check: 1744 passed / 80 skipped, typecheck/build PASS. На homeserver новый CHK-B49D31BF сохранил 10 фактов / 6 новых строк ПД / 0 qualified. Браузер 1440/768/375 проверил обе страницы контекста и возврат к значению; исходные изображения загрузились, page errors/overflow отсутствуют. Подробные хеши и пути — в основном журнале.

Следующий срез — толщина перекрытия в таблице ПД и составной строке РД. После него требуется факт-ориентированная привязка выбранных строк к элементам: область всего файла не может разрешить шесть разных конструкций. Контроль полноты инвентаря и предметная калибровка остаются отдельными задачами.
