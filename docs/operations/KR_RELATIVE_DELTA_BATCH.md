# Пакетная проверка KR-067 по открытому индексу

Команда [`evaluate-public-kr-relative-delta-batch.py`](../../scripts/evaluate-public-kr-relative-delta-batch.py)
читает только `TRAIN_PUBLIC / INCLUDE / PUBLIC_TRAIN` после полного
`PASS`-аудита индекса. Она сверяет SHA манифеста и аудита, версию индекса,
203 открытые записи, 202 законченных PDF на 10 142 страницах, один
`F0194` TXT только как метаданные, SHA 10 142 страничных артефактов и
адреса FTS. Числа корпуса нельзя изменить через CLI. Внутренний параметр
`_expected_counts` применяется только в тестах с малым синтетическим индексом.

```bash
python3 scripts/evaluate-public-kr-relative-delta-batch.py \
  --manifest datasets/reference_methodology/hackathon_gold_20260811/УЧАСТНИКАМ_БЕЗ_ОТВЕТОВ/data/document_manifest.jsonl \
  --index /data/index --audit /data/index-audit.json \
  --output /data/kr-067-review.json
```

По умолчанию выбраны ПД/КР `F0105–F0107` и РД/КР `F0136, F0139–F0144`
одного объекта. FTS ищет префиксы `бетон*`, `объем*`, `объём*`, `стал*`,
`масс*`. Поиск выбирает страницы, затем индексный адаптер сверяет точные
блоки, происхождение и SHA; само совпадение слова ничего не доказывает.
При передаче собственного набора нужно одновременно задать `--source-id`
и `--term` (параметры можно повторять). Допускаются только открытые PDF
стадий ПД/РД, раздел КР, одного объекта.

Отчёт содержит `CONCRETE_VOLUME` и `STEEL_MASS` раздельно по каждой
выбранной странице, исходнику, стадии и всей пачке. Для кандидатного факта
сохранены исходная строка, SHA оригинала из открытого manifest, SHA страницы
и evidence, parser provenance, bbox/offset числа и явная область здания.
`candidatePages` и `abstainPages` считаются отдельно для каждого материала.
Отдельные `tableObservationCounts` считают только локальные итоги сводных
ведомостей. Пакет перечитывает полную SHA-проверенную страницу индекса,
ищет уникальную геометрическую тройку «заголовок, ИТОГО, число» и добавляет
её блоки к выбранному evidence. Если лимит 64 выбранных блоков не позволяет
это сделать, `truncated.tableBlocks=true`; частичная тройка не принимается.
Если хотя бы у одной строки полной индексированной страницы геометрия
некорректна, включая bbox нулевой площади, скан всей страницы получает
`tableGeometryScanStatus=ABSTAIN_INVALID_GEOMETRY` и пустой
`tableObservations`. Строка может оказаться конкурирующим числом, поэтому
её нельзя молча пропустить. Остальные страницы пакета обрабатываются;
статус и счётчики текстовых фактов остаются отдельными от табличного скана.
Такие наблюдения сохраняются в `tableObservations`, **не в `facts`** и не
повышают `candidatePages` фактов KR-067.
`ocrQueue` перечисляет страницы, требующие адресного OCR; этот пакет не
запускает OCR и не читает `F0194`. `truncated.textPages`,
`truncated.ocrPages`, `truncated.blocks` и `omittedTextPages` показывают
усечение. По умолчанию лимиты: 100 страниц текстового поиска, 8 блоков
на страницу, 100 OCR-адресов.

Пакет не рассчитывает процент, не связывает ПД с РД, не доказывает полноту
поиска и не делает вывод об отсутствии расхода. `findingCount` и
`parameterCoverage` равны `null`. Даже два числа одной области остаются
наблюдениями до подтверждения редакций, листов КЖ/КМ, компонента материала,
связи источников и знаменателя относительного расхождения. Порог из каталога
строго `> 2%` по каждому компоненту; сумма м³ и тонн недопустима.

Локальная проверка: шесть тестов строят три PDF на шести страницах,
метаданные `F0194`, единый индекс и полный `PASS`-аудит. Проверяются оба
материала по ПД/РД, отдельная таблица с тремя PDF-блоками, ложное текстовое
совпадение, SHA/локаторы, видимое
усечение, отказ при порче аудита/манифеста, изоляция страницы с bbox нулевой
площади и жёсткие числа CLI. Эти
тесты не подтверждают качество извлечения на оригинальных PDF. Следующий
шаг после аудита реального индекса — запустить команду на исходном пакете,
просмотреть все кандидатные страницы и ложные совпадения, затем прицельно
обрабатывать `OCR_REQUIRED`.

## Реальная пачка, 27 сентября 2026

После полного `PASS`-аудита запущено 100 выбранных текстовых страниц десяти
исходных PDF (`maxBlocksPerPage=8`, `maxOcrPages=500`). По обоим атомарным
атрибутам получено 0 квалифицированных кандидатов и 100 `ABSTAIN`.
Текстовые страницы и блоки усечены лимитом; очередь OCR содержит 44 страницы.
[Постраничный отчёт](../../output/public-index-20260927/kr-relative-delta-batch.json)
имеет SHA-256
`1a1b201d8be4cc5e6696c0552ea3a77514d907d1e4a366c030a2bb6b4cff1645`.
Результат не подтверждает отсутствие объёма бетона либо массы стали:
извлекатель требует полный итог с областью конструкции в одной физической
строке. В таблицах и разнесённых ячейках такая связь ещё не доказана.

Повторный пакет с постраничным сканом таблиц завершился на тех же 100
выбранных страницах. Семь страниц с bbox нулевой площади получили
`ABSTAIN_INVALID_GEOMETRY`; остальные 93 страницы проверены. На `F0141` p.4
и `F0143` p.4 найдены отдельные строки «Сводная ведомость расхода бетона» /
«ИТОГО» / `432` и `310` м³. Их локаторы, SHA страницы и источника сохранены в
[отчёте](../../output/public-index-20260927/kr-relative-delta-table-batch-v2.json)
(SHA-256 `85fd41b49a6811ec3ffa0b5cb1663a7375d188f1eccedc0e83480d56fea9204b`).
Это два наблюдения по РД без проверенного общего конструктивного объёма ПД;
`candidatePages` для сравнения остаётся 0 по обоим атрибутам. Поиск страниц
и блоков всё ещё усечён, очередь адресного OCR — 44 страницы.
