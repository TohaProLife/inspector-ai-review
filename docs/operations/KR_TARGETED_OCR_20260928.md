# КР: адресное чтение всех 44 ранее неизвестных страниц

Статус: **REVIEW_ONLY_ABSTAIN**. Проверена выбранная десятидокументная пачка
КР одного объекта `OBJ-NOVOSLOBODSKAYA` из
[`KR_DECREASE_FAMILY.md`](KR_DECREASE_FAMILY.md). Это не проверка всего
корпуса КР и не доказательство полноты извлечения параметров.

## Источники и исполнение

- Исходная [очередь 44 страниц](../../output/kr-targeted-ocr-20260928/input-triage.json)
  взята из предыдущего публичного triage, SHA-256
  `b259025e14917db00ac3ed52c3786daa17d1d3b06842f15ad4c3165d95fce21f`.
  Страницы принадлежат `F0105` (1), `F0106` (6), `F0107` (37), все ПД/КР.
  РД-исходники в этой пачке не имели `OCR_REQUIRED`.
- Только `TRAIN_PUBLIC / INCLUDE / PUBLIC_TRAIN`: исходные PDF извлечены
  из `01_ПАКЕТ_УЧАСТНИКАМ_3_ОБЪЕКТА.zip`; для каждого PDF сверены размер,
  SHA-256, число страниц и запись открытого `document_manifest.jsonl`.
  `TEST_HIDDEN` и закрытые ответы не читались.
- [Аудит индекса v4](../../output/public-index-20260927/index-audit-v4-20260927.json)
  имеет `PASS`, SHA-256
  `69ef56fc23e779dfed25aa60c5615be3ee58f244200c6620c2b1ddaec335f49a`.
  Все 44 адреса повторно найдены как `OCR_REQUIRED`, gzip-артефакты сверены
  по SHA. SHA страниц прежнего индекса v3 отличаются от v4, поэтому
  [план](../../output/kr-targeted-ocr-20260928/plan.json) сохраняет
  оба значения; обработка опирается на подтверждённый v4. SHA плана
  `34336d734299f63fb4ec5f0a1cd5214f4972501a9539453bcdbc8e6fbee7a26d`.
- OCR-кеш использует SHA исходного PDF, номер страницы, DPI, script,
  renderer и provider profile. Все 44 страницы имели точный `HIT` при
  120 DPI; нового OCR-запроса и новой записи кеша этот проход не делал.
  Перед каждым `HIT` исходный PDF повторно проверен по manifest SHA.
  [Отчёт](../../output/kr-targeted-ocr-20260928/report.json): 44/44
  завершено, 0 ошибок, 2 458 строк; SHA-256
  `4a8778cbb51cc3ad3dc2a282c1c6b1dccf304f8dd2bfade8caa03e1b13b567dd`.

## Независимый аудит и предметный просмотр

Для всех 44 страниц отдельно сверены [receipts](../../output/kr-targeted-ocr-20260928/receipts/),
manifest, исходный ZIP, запись v4 SQLite, SHA gzip-страницы, ключ и SHA
файла кеша, hash OCR-артефакта, локаторы и геометрия строк. Второй,
изолированный от сети контейнер с PDFium 5.12.1 и лимитом 2 CPU
повторно отрендерил все 44 страницы **из оригинальных PDF**. Все 44 PNG SHA,
размеры и DPI точно совпали с OCR receipt.
[PDFium audit](../../output/kr-targeted-ocr-20260928/render-audit.json)
`PASS`, SHA-256
`71548bee5220bda51d041d654285cdd36c54d5bbae5bef4d3e380c103da5ddb8`.
Итоговый [независимый аудит](../../output/kr-targeted-ocr-20260928/audit.json)
`PASS`, 44/44, SHA-256
`a435ca33872778b0def8ad486b2d1d7ed06a4c330d9496d11c7bf118f141b170`.

Широкий поиск названий КР-тем нашёл 63 строки на 10 страницах. Ни одна из
2 458 OCR-строк не содержит **одновременно** выбранное слово про
конструкцию/материал и размерность/диаметр по проверяемому буквальному
шаблону. Это результат фильтра, не доказательство отсутствия размера:
таблицы и схемы часто разделяют название и число по ячейкам.

Вывод по этой выборке: **ABSTAIN**. Реальной утверждённой пары ПД/РД

## Воспроизведение

Скрипты [плана и cache replay](../../output/kr-targeted-ocr-20260928/run.py),
[PDFium render audit](../../output/kr-targeted-ocr-20260928/render.py),
[независимого receipt audit](../../output/kr-targeted-ocr-20260928/audit.py)
лежат рядом с результатом. `python3 -m py_compile` этих скриптов прошёл.
Пакет выполнялся в изолированном homeserver checkout; приложение Compose
этот offline OCR пакет не импортировало.
