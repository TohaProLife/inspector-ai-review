# Локальный запуск на обычном CPU

Актуализация: 20 октября 2026, принятый код `37281628828bb98695a818e2d328291a6e357d72`. Начальная точка передачи — [комплект v4](FINAL_PACKAGE_V4_20261020.md): SHA архивов, распаковка и границы приёмки. Команды ниже предназначены для отдельного локального стенда. Linux x86_64, Docker Engine и Compose уже должны быть доступны. H100, NVIDIA runtime и модели для PDF с текстовым слоем не требуются.

Базовый Compose вместе с `docker-compose.core-smoke.yml` и `docker-compose.matrix-v13.yml` включает 13 CPU-сервисов. Объединение конфигурации проверено; отдельный полный запуск именно этой тройки Compose ещё не принят. Установленная CPU-сборка 3728162 (отчёт приёмки передаётся отдельно) принята отдельно: 51 миграция сверена, каталог 132, 18 успешных заданий/подтверждённых outbox-записей, настоящий F0201 прочитан до страницы 676. После перезапуска БД/API/relay/четырёх worker результат совпал побайтно. Это изолированный queue smoke; он не подтверждает H100 или инженерную точность.

Инженерный профиль этого запуска — `matrix-text-facts-concrete-walls-v13`, adapter13. Обозначения v14/v15 в именах пакетов сборки относятся к упаковке, а не к автоматическому включению нового инженерного профиля PPM-113. Ветка диаметра PPM-113 пока не активирована.

## Подготовить отдельный стенд

Распаковать source ZIP v4 в пустой каталог. Выполнять команды прямо из его корня, где находятся `package.json` и `infra/`: вложенного `source/` нет. Companion с реальными PDF распаковать отдельно; проверить SHA обоих архивов по [комплекту v4](FINAL_PACKAGE_V4_20261020.md). Каталог `source/`, source-map и V9 review ZIP в прежних инструкциях относятся к исторической упаковке; поверх v4 её не накладывать.

Для отдельного полного чтения до 1024 страниц добавить `-f infra/docker-compose.source-audit-v4.yml` **последним** к тем же командам `config`, `up`, `ps` и `down` ниже. Сохранять имя проекта и env-файл; [порядок V4 и лимиты](full-source-audit-v4-v1.md). Для обычного V13 этот ресурсный overlay не нужен. История CPU-прогонов: [CPU NORMAL](CPU_NORMAL_ACCEPTANCE_20261020.md); актуальная версия — receipt 3728162 выше.

```bash
export INSPECTOR_ENV_FILE="$PWD/infra/.env.cpu-local"
./infra/stack.sh laptop init
```

`init` создаёт файл0600 со случайными паролями и токеном. Он не запускает GPU-проверку или контейнеры. Для CPU используются приведённые ниже команды Compose напрямую.

В новом файле `infra/.env.cpu-local` задать свободные порты отдельного стенда. Пример:

```dotenv
POSTGRES_PORT=25490
RABBITMQ_PORT=25690
RABBITMQ_MANAGEMENT_PORT=25691
REDIS_PORT=26390
MINIO_API_PORT=29090
MINIO_CONSOLE_PORT=29091
API_PORT=24190
WEB_PORT=28190
```

`HOST_BIND_ADDRESS` оставить `127.0.0.1`. На одном хосте каждому стенду нужен свой проект Compose и свой набор портов. Исходные PDF, база, результаты и секреты не входят в архив исходников. При первом запуске база и файловое хранилище пустые.

## Проверить конфигурацию и запустить

```bash
docker compose --project-name inspector-ai-cpu-local \
  --env-file "$INSPECTOR_ENV_FILE" \
  -f infra/docker-compose.yml \
  -f infra/docker-compose.core-smoke.yml \
  -f infra/docker-compose.matrix-v13.yml config --quiet

COMPOSE_PARALLEL_LIMIT=1 docker compose --project-name inspector-ai-cpu-local \
  --env-file "$INSPECTOR_ENV_FILE" \
  -f infra/docker-compose.yml \
  -f infra/docker-compose.core-smoke.yml \
  -f infra/docker-compose.matrix-v13.yml up -d --build
```

Оверлей включает `MATRIX_V1`, текущий V13 и локальное рабочее место. В этом режиме аутентификация рабочего места служит локальной проверке. Для внешнего стенда отдельно настраиваются доступ и HTTPS.

ClamAV должен загрузить настоящую базу сигнатур и стать готовым до загрузки PDF. Успешный запуск API сам по себе не подтверждает готовность антивируса, очереди или обработчиков. Ограничения памяти заданы для каждого сервиса; их сумма не является измеренным пиком. Прогон очереди проверяется отдельно, с контролем свободной памяти.

```bash
docker compose --project-name inspector-ai-cpu-local \
  --env-file "$INSPECTOR_ENV_FILE" \
  -f infra/docker-compose.yml \
  -f infra/docker-compose.core-smoke.yml \
  -f infra/docker-compose.matrix-v13.yml ps

curl --fail --silent --show-error http://127.0.0.1:24190/api/health
```

Интерфейс при указанных портах: `http://127.0.0.1:28190/`. Это локальный адрес. Проверить создание объекта, загрузку исходного PDF, завершение NORMAL-анализа и доступ к цитате исходника. Результат на одном PDF без пары ПД/РД не подтверждает межстадийное нарушение. OCR-кандидаты и неподдержанные параметры сохраняют свои отдельные состояния.

В «Исходных документах» доступен отдельный «Полный аудит PDF до 1024 страниц»: запуск, список сохранённых V4, полное пакетное чтение и поиск с переходом к исходной странице. После завершения V4 можно открыть «Историю OCR пропусков» и импортировать сохранённый JSON-пакет того же PDF. Импорт не запускает OCR, не изменяет native artifact и не превращает OCR в машинное инженерное доказательство. Ручная сверка подтверждает только буквальную транскрипцию; [путь OCR и права](SOURCE_OCR_IMPORT_ACCEPTANCE_20261020.md). Исторические V3 и инженерный V13 сохраняют свои профили и ограничения. Текущая матрица: 62 частично реализованных параметра, 70 unsupported; source-only сверки/OCR имеют `p=null`, `coverageDelta=0`.

## Остановить этот стенд

```bash
docker compose --project-name inspector-ai-cpu-local \
  --env-file "$INSPECTOR_ENV_FILE" \
  -f infra/docker-compose.yml \
  -f infra/docker-compose.core-smoke.yml \
  -f infra/docker-compose.matrix-v13.yml down
```

Именованные тома с базой и файлами сохраняются. Принятые проверки и ограничения: [комплект v4](FINAL_PACKAGE_V4_20261020.md), installed CPU 3728162 (отчёт приёмки передаётся отдельно). Приёмка от 19 октября и прежние срезы описывают историю, а не текущую сборку.
