## Исправление извлечения строк

В p.7 OCR-значение строки 44 начинается на x=654, за прежним допуском
правой колонки x≥685. Отдельный opt-in профиль
`INSPECTOR_OCR_TABLE_ROWS_PROFILE=v2` расширяет этот допуск с 32 до 64 px.
Остальная геометрия и исходный v1 сохранены. Из неизменяемой OCR-стадии
`abc417e23740320ba4004dc05ec84d951b3715abde02a91c563c7954dffb327a`
v2 строит **17 некодированных строк** (p.7 — 4, p.9 — 13) и три воздержания.
Новая p.7 пара имеет индексы строк 42/44. OCR потерял продолжение подписи и
исказил единицу; это предложение для ручной сверки, не готовый факт.

Release имеет отдельные rule profile, adapter version 8 и config SHA.
Worker и API независимо пересчитывают версию v2; API запрещает результат v1
под v2 release и наоборот при сохранении, sealing и чтении. В PostgreSQL
integration проверены оба release profile и отказ результату чужой версии.

## Снимок решений

Миграция 021 добавляет append-only `run_ocr_transcription_snapshots`.
Создание нового run выбирает последнее решение для каждого файла и
отпечатка строки, заново сверяет происхождение OCR/rule stage, SHA исходного
PDF, source scope, каноническое решение и его hash. `REJECTED` перекрывает
старый `CONFIRMED_TRANSCRIPTION`; подмена блокирует запуск. Снимок хранит
происхождение и решение, **не создаёт** код, предметный факт или finding.
На реальном `CHK-FA35FEA0` снимков 0, потому что решений F0202 нет.
Положительная и отрицательная логика проверена отдельно в синтетической
PostgreSQL интеграции; реальное подтверждение за эксперта не создавалось.

Локально: полный `npm run check` с worker venv, API 198 pass/24 skip,
web 29, worker 648; PostgreSQL integration 22/22 и два отдельных теста
записи/снимка. Это проверяет контракты и транспорт, а не точность OCR,
пригодность F0202 как утверждённого источника или полноту 132 параметров.
Следующий этап: решение о предметной применимости строки с подтверждённым
контекстом источника, затем отдельный OCR-локатор типизированного факта и
его независимый валидатор. Сравнение требует реальную проверенную пару ПД/РД.
