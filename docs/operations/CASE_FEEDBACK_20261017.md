## Задачи и приёмка

- [x] F01. Явные режимы SAMPLE/FULL в immutable release; FULL направляет все подходящие области в обработку, SAMPLE сообщает точные пропуски.
- [x] F02. Точные счётчики страниц, предложенных/выбранных/обработанных/ошибочных областей. Сбой модели не означает проверенное соответствие.
- [x] F03. Кропы повышенного разрешения; мелкие детали доступны в исходном листе.
- [x] F04. Контекст по метаданным, оглавлению и тексту/штампам страниц, включая титул после второй страницы. Смешанные системы сохраняются вместе; неоднозначность видима.
- [ ] F05. Реальная квалификация геопривязки (код и подписанный trust store готовы; независимая ведомость не найдена): независимый источник контрольных точек, SHA исходника, происхождение, измеренные residual/holdout errors. Неподтверждённые координаты не дают предметный вывод.
- [x] F06. Поиск кандидатов по коду/названию/описанию; фильтры раздела и решения; явно выбранная карточка.
- [x] F07. Стадии ПД/РД/ИД и явная пара сравнения; принадлежность одному элементу подтверждается отдельно. Одного совпавшего числа недостаточно.
- [x] F08. Адрес доказательства: оригинал, SHA, редакция, страница, лист и bbox; переход к связанному источнику.
- [x] F09. Просмотр полного листа: zoom/pan, страницы, полноэкранный режим, независимые панели и включаемая синхронизация; bbox движется с листом и скрывается.
- [x] F10. Карточка: параметр, элемент, значения/единицы, delta, правило/основание; confidence отдельно, без выдуманной вероятности нарушения.
- [x] F11. Раздельные состояния: нет документа, нет значения, несопоставимость, ошибка, проверка не завершена, расхождение не найдено; причины и действия.
- [x] F12. Durable решения: подтверждение, отклонение с причиной, уточнение и частичное решение по составным частям; автор/время/история и optimistic concurrency.
- [x] F13. Версионируемые исправления значения/страницы/bbox; исходное и новое состояния, причина, автор; после изменения требуется повторное рассмотрение.
- [x] F14. Дозагрузка: незатронутая история сохраняется, изменившиеся доказательства требуют review; предыдущие run/протоколы доступны.
- [x] F15. Согласованный экспорт и протокол: источники, значения, статусы, решения/причины; финализация блокирует изменения; отмена с правами и аудитом; предупреждение об отсутствующей ИД.
- [x] F16. Проверки API/worker/web/PostgreSQL + сквозной обычный стенд homeserver; фактические результаты отдельно от fixture-тестов.

## Результат реализации

Закрыты 15 из 16 пунктов приёмки. По F05 реализованы защищённый маршрут, источник доверия вне пользовательского запроса, подпись Ed25519, проверка исходных байтов, страницы/поворота, affine и holdout ошибок, UI и негативные тесты. Независимый согласованный пакет точек для реального объекта в проверенных данных homeserver не найден; реальная квалификация остаётся открытой. Подробности и найденные оригиналы — [provenance геопривязки](FEEDBACK_GEOMETRY_PROVENANCE_20261017.md).

- F01–F04: новые immutable профили `red-vector-proposals-v7-sample` / `red-vector-proposals-v7-full`; режим входит в release и idempotency hash. Попытка сменить режим активного запуска отвергается. FULL не выбирает две области: обходит все сохранённые подходящие предложения. SAMPLE сохраняет прежний выбор двух, но точно сообщает пропуски. Успешные ответы закреплены source/profile/crop SHA и атомарно сохраняются для повторного выполнения задания. Прогресс проходит fenced heartbeat и сохраняется в PostgreSQL.
- F03: сторона VLM-кропа до 2048 px вместо 768; просмотр оригинала до 4800 px, zoom до 800%, исходный PDF доступен отдельно. Браузерная проверка подтвердила фактический растр 4800 px и перемещение листа.
- F04: контекст v2 проверяет metadata, outline и текст всех страниц; поздний титул и смешанные HEATING/VENTILATION сохраняются. Добавлены WATER_SUPPLY/DRAINAGE/ELECTRICAL. Пустой текст учитывается как unreadable, не как проверенное отсутствие системы.
- F06–F11: карточка инспектора с поиском, фильтрами, выбранной записью, тремя стадиями и явной парой; элемент, правило/порог/основание и delta; полный адрес исходника, рамки и независимые панели. Синхронизация требует подтверждённой связи и отключается при её сбросе. Ошибка обработки показывается с причиной и действием; неподтверждённая вероятность не вычисляется.
- F12–F13: append-only события CONFIRM/REJECT/CLARIFY/PARTIAL_CONFIRM/CORRECT_EVIDENCE/ACCEPT_FOR_REVIEW. Исправление требует нового рассмотрения. Server проверяет optimistic version, SHA/страницу/стадию immutable manifest, CURRENT/APPROVED и связь подтверждаемых источников. Все версии и авторы сохраняются; модельный артефакт остаётся неизменным.
- F14: новая проверка сохраняет неизменные решения только при совпадении кандидата, release, текстовых артефактов, стадий, source review и зависимостей. Новый неизвестный или относящийся к тому же разделу источник сбрасывает автоматическое наследование. Машинный DAG выполняется заново консервативно; обещания пересчитать исключительно изменившиеся правила нет. Предыдущие запуски доступны для чтения, протоколы — по своим immutable snapshots.
- F15: JSON карточки содержит те же источники, события и версии; финальный canonical JSON содержит отдельный candidateReview с историей. Незавершённые/исправленные карточки блокируют финализацию. После финализации действует запрет изменения; отзыв требует роли/причины и оставляет аудит. Отсутствие ИД выделяется. Счётчики решений инспектора показаны отдельно от результатов исполняемых правил.

Миграция `030_inspector_candidate_review.sql` применена только в новом тестовом контуре. Rollback отказывается удалять новую историю решений. Локальные секреты и операторские пакеты исключены из Git.

## Запуск и проверка стенда

Основные файлы: `infra/docker-compose.yml` + `infra/docker-compose.feedback.yml`, пример переменных `infra/feedback.env.example`. Скопировать пример в gitignored `infra/feedback.env`, заменить все REPLACE отдельными случайными секретами, создать `infra/geometry-trust` и предоставить participant reference data по пути базового Compose.

Overlay ожидает уже работающие обычные сервисы моделей. Отдельная external network document-ai должна содержать существующий provider с alias `document-ai`; external VLM network — provider `visual-vlm:8080`. Не подключать H100 server overlay. До запуска проверить Compose:

```sh
docker compose -p inspector-feedback-20261017 --env-file infra/feedback.env -f infra/docker-compose.yml -f infra/docker-compose.feedback.yml config --quiet
docker compose -p inspector-feedback-20261017 --env-file infra/feedback.env -f infra/docker-compose.yml -f infra/docker-compose.feedback.yml up -d --build
```

С рабочего компьютера доступ через SSH:

```sh
ssh -N -L 28082:127.0.0.1:28082 -L 24101:127.0.0.1:24101 homeserver
```

Открыть `http://127.0.0.1:28082`, затем кабинет и объект. Состояние нового стенда сохраняется в его собственных Docker volumes.

Повтор браузерной приёмки требует Playwright и session state тестового объекта с тремя fixture-файлами; скрипт проверяет имена и отказывается работать с другим комплектом. State JSON содержит objectId/checkId/cookies, хранится вне Git с правами 0600. На текущем рабочем компьютере он находится в `/tmp/feedback-smoke-state.json` и истекает вместе с сессией:

```sh
PLAYWRIGHT_MODULE=/path/to/playwright node scripts/smoke-feedback-review-ui.cjs /secure/fixture-state.json
```

Скрипт добавляет две версии решения только синтетическому объекту. Реальные исходники и исходные машинные артефакты не изменяет. Для общего прогона установить зависимости Python из requirements worker/scripts и PyYAML в отдельную venv, передать её через PYTHON_BIN и URL отдельной PostgreSQL через INSPECTOR_POSTGRES_ADMIN_URL; затем `npm run check`.
