Проверены ровно `PZ-009`, `SPZU-034`, `KR-054`, `KR-064` из
[`unresolved-parameter-strategy-v1.json`](unresolved-parameter-strategy-v1.json).
Все четыре в [реестре](../../services/worker/rules/parameter-family-registry-v1.json)
имеют `UNRESOLVED / GEOMETRY_OR_TOPOLOGY`. Семейство `BOUNDARY_OVERLAY` сюда
не включено. Это аудит адресов для просмотра, **не** проверка координатной
согласованности: утверждённые редакции, геодезическая основа, сопоставимая
пара ПД/РД, `finding` и `parameterCoverage` не установлены. Итог для всех
четырёх кодов — `ABSTAIN`.

Каталог задаёт разные обязательные источники: для `PZ-009` текст ПЗ и

для `KR-054` схема осей КР, разбивочные планы КЖ/КМ и исполнительные оси;
для `KR-064` планы отверстий/перекрытий КР, чертежи шахт/закладных КЖ и
исполнительная схема шахт. На просмотренных страницах этот комплект и
проверенные связи не собраны. Два документа одного объекта и одинаковое
число `159,95` не превращаются автоматически в утверждённую пару.

## Вывод для extractor

Общий конфигурационный поиск строк дал бы только повторную очередь
`ABSTAIN`: у `PZ-009` это фраза с отметкой, у `SPZU-034` — выноска,
у `KR-054` — упоминание оси, у `KR-064` — слово «шахта». Он не продвинет
проверку ни одного условия каталога. Поэтому **новый text-line config v4 для
этих четырёх кодов сейчас не нужен**.

Минимальный предметный следующий этап: отдельный immutable слой геометрии
страниц с SHA исходного PDF и рендера, системой координат/высотным датумом,
масштабом и контрольными точками; затем проверенные человеком соответствия
листов, редакций и одной точки/оси/шахты между ПД, РД, ТУ и исполнительной
геодезией. Геометрический extractor должен возвращать адресованные
предложения с неопределённостью и отклонять сравнение, если CRS,
трансформация, остаточная ошибка, идентичность объекта или исходные листы
не подтверждены. Лишь после этого возможны разности отметок/координат,
шага осей и габаритов. Сейчас для всех четырёх — только `ABSTAIN`, без
вывода об отсутствии и без положительных фактов.
