# Определения правил для 47 кандидатов

`services/worker/rules/parameter-candidate-rules-v1.json` задаёт по одному
определению для каждого `GENERIC_CANDIDATE` из реестра 132 кодов. Пакет
закреплён SHA-256 каталога и реестра. Загрузчик проверяет точный состав и
порядок кодов, семейство, атомарные атрибуты, единицы, разделы ПД/РД,
обязательный контекст и пороги.

`requiredExpectedSections` и `requiredActualSections` относятся только к
**категориям открытого manifest**. Обозначения разделов и марок листов из
каталога хранятся отдельно в `requiredExpectedDrawingSections` и
`requiredActualDrawingSections`. `KR-061/062/067` теперь допускают
`section=KR` для ПД и РД; КЖ/КМ остаются более тонкой проверкой листа.
Это включает в предварительный поиск F0105–F0107 и F0136/F0139–F0144,
не объявляя их автоматически сравнимыми.

В 203 разрешённых записях manifest есть категории `OTHER` (154), `KR` (12),
`VK` и `OV` (по 8), `SS` (7), `POS` (4), `AR`, `GP`, `EOM` (по 3), `PB` (1).
Ни `КЖ`/`КМ`, ни `ПП`/`ППР`, ни `ПЗ` отдельной категорией manifest не являются.
`OTHER` не интерпретируется как любой конкретный раздел. Поэтому для 36
кандидатов ожидаемая категория ПД и для 14 кандидатов категория РД пока
`UNKNOWN_ABSTAIN`: строгий список пуст, требуется отдельная проверка
обозначения в самом документе. Среди однозначных категорий в текущем
открытом наборе 7 документов `RD/KR`, но нет `RD/AR`, `RD/EOM` и `RD/VK`;
часть материалов помечена `RD_ID_MIXED` и требует подтверждения стадии
страницы. Отсутствие пары в этом наборе ведёт к `ABSTAIN`, не к finding.

Пакет имеет `disposition=REVIEW_ONLY`, `executionPolicy=DEFINITION_ONLY`.
У каждого определения `evaluationPolicy=NON_EXECUTING_ABSTAIN`; действующий
pipeline его не исполняет. Поэтому создание пакета не меняет coverage и не
создаёт findings. Для подключения каждого семейства отдельно нужны извлечение
фактов с локатором страницы, проверка стадии/редакции/согласования источников,
связь того же элемента и пакетная проверка на разрешённых PDF.
Определения пока допускают только пару ПД/РД; упомянутая в некоторых
триггерах ИД потребует отдельной проверки стадии конкретных страниц.

Сравнение задаёт только направление и буквальный порог из каталога. Всего
14 кодов содержат строгие числовые пороги: PZ-002; SPZU-024/025/030;
AR-040/041/049; KR-067; POS-082; POD-093; PPM-104/105; ODI-118; SM-132.
Для остальных порог `null`: ноль и допуск не подставляются автоматически.
Относительные семейства требуют отдельно определить знаменатель процента.
Классы требуют утверждённой порядковой шкалы (в частности, EI/E/I нельзя
считать просто числом). Наборы требуют доказанной полноты списка и области
поиска. Нормативные границы требуют проверки применимости к конкретному
элементу и объекту. До этого результат остаётся `ABSTAIN`.

SPZU-024 хранит отдельно `EXCAVATION_VOLUME` и `BACKFILL_VOLUME` в м³;
KR-067 — `CONCRETE_VOLUME` в м³ и `STEEL_MASS` в тоннах. Сумма разных
компонентов или единиц не образует сравнение. POS-088 также разделён на
временную мощность и объём ресурса; формулировка триггера про мощность не
разрешает автоматически сравнивать вторую величину. POS-086 не имеет даже
оператора: триггер сравнивает пик персонала с вместимостью бытового городка,
которая ещё не установлена как факт ПД.

Проверка определений:

```bash
PYTHONPATH=services/worker python3 -m unittest \
  services/worker/tests/test_candidate_family_rules.py -v
```

Это проверка структуры и отказов при подмене. Достоверность извлечения и
семейные сравнения будут проверяться после завершения единого индекса
разрешённых документов по
[плану пакетной проверки](PARAMETER_FAMILY_BATCH_PLAN.md).
