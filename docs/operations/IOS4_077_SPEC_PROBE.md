# IOS4-077: исследовательское извлечение спецификаций радиаторов

## Граница результата

Это автономный эксперимент только с PDF из `TRAIN_PUBLIC`. Он извлекает строки
спецификаций с точной страницей источника и хешем файла. Совпадение обозначения
модели между ПД и смешанным РД/ИД является **наблюдением**, а не подтверждённой
связью конкретных приборов. Результат всегда `ABSTAIN`, `finding: null`.
Публичные метки/вердикты и закрытые ответы не читаются и не служат правилами.

Параметр `IOS4-077` — «Технические параметры отопительных приборов
(радиаторов)», единица измерения `Вт / шт.`. См.
[`14_PARAMETER_IMPLEMENTATION_MATRIX.md`](../architecture/14_PARAMETER_IMPLEMENTATION_MATRIX.md)
(строка параметра 77) и общие гейты
[`07_RULES_AND_EVIDENCE.md`](../architecture/07_RULES_AND_EVIDENCE.md).

## Запуск

[`probe-radiator-spec.py`](../../scripts/probe-radiator-spec.py) принимает
манифест и два локальных PDF, сверяет стадию/раздел/split, размер, SHA-256 и
число страниц с манифестом **до OCR**. Затем читает текстовый слой ПД и
вызывает только локальный `document-ai` для выбранных страниц F0202. Выбор
страниц явно помечен как `EXPLICIT_EXPLORATORY_PAGES`; это не результат
автоматического поиска. Пример внутри изолированного контейнера с доступом к
локальному `document-ai`:

```bash
python scripts/probe-radiator-spec.py \
  --manifest datasets/reference_methodology/hackathon_gold_20260811/УЧАСТНИКАМ_БЕЗ_ОТВЕТОВ/data/document_manifest.jsonl \
  --pd-source /path/to/F0171_raw.pdf --rd-source /path/to/F0202_raw.pdf \
  --pd-page 133 --pd-page 134 \
  --rd-page 25 --rd-page 26 --rd-page 27 --rd-page 28 --rd-page 29 \
  --document-url http://127.0.0.1:18084 \
  --output /path/to/ios4-077-f0171-f0202.json
```

Запуск требует установленных зависимостей `services/worker/pyproject.toml` и
доступного `document-ai` на loopback либо в Docker DNS. В отчёте есть
`contentHash` канонического JSON; CLI отдельно печатает SHA-256 байтов файла.
Тесты: `PYTHONPATH=services/worker python3 -m unittest
services/worker/tests/test_radiator_spec.py -v`.

### Проверка стадий и редакций по оригиналам

Дополнительный read-only просмотр сверенных `TRAIN_PUBLIC` PDF показал:
F0171 PDF с. 1–4 имеет титул ПД `АНО/150321/1-П-ИОС5.4.2` (2022), но не
подтверждает текущую редакцию и согласование всего тома. F0202 с. 1–4 имеет
титул РД `АНО/150321/1-РД-ОВ2.1` с изменениями 2023–2024; с. 6 содержит
разрешение `861-24` на замену перечисленных листов. С. 10–12 — ведомость РД,
с. 14–36 — листы со штампами РД, включая спецификацию. У с. 7–9 нет явного
штампа стадии, а с. 13 содержит справку о проектной документации внутри
РД-файла. Подтверждённых страниц ИД не найдено. Для будущего частичного
review обоснована лишь карта `1-6=RD, 7-9=UNRESOLVED, 10-12=RD,
13=UNRESOLVED, 14-36=RD` и статусы редакции/согласования `UNKNOWN`.
F0171 с. 99 и F0202 с. 17 упоминают помещения 267/270, но совпадение
номеров не удостоверяет связь приборов или температурную базу. Состояние
source review не менялось: это наблюдения по документам, а не утверждение
актуальности комплектов или связи каждой позиции прибора.

## Что ещё требуется для правила

`revisionStatus`, `approvalStatus`, стадия каждой страницы F0202,
`entityLinkStatus` и `thermalBasisStatus` оставлены `UNKNOWN`. При OCR
неоднозначная единица, например `kBm` вместо `кВт`, остаётся только сырым
текстом; нормализованная мощность равна `null`. Никакая разница в перечне
моделей, количестве или суммарной мощности не становится нарушением без
удостоверенных актуальной редакции и утверждения, связи сравниваемых помещений
и приборов, одинаковой температурной базы и релевантного ИД/паспорта.

Для долговечного правила потребуется подписанная проверка этих источников,
страничная классификация смешанного PDF, привязка к помещениям/маркам и
проверка паспортов. Этот probe не подключён к durable API, правилам или
публикации findings.

## Ограниченный срез наблюдения в worker

`build_public_observation_slice` в `radiator_spec.py` повторно сверяет байты
F0171/F0202 с открытым manifest, принимает не более двух выбранных страниц ПД
и пяти страниц смешанного РД/ИД, требует ровно один OCR-артефакт для каждой
выбранной страницы и сохраняет исходные строки и координаты ячеек. Конкурирующие
ячейки OCR в одной колонке не превращаются в значение; `kBm` остаётся сырым
текстом с `unitHeatOutputKw=null`. Выход имеет отдельную схему
`ios4-077-public-observation-slice-v1`, `CLARIFICATION_REQUIRED`, пустые
`comparableFacts`, `finding=null`; совпадение кодов моделей отмечено лишь как
лексическое наблюдение. Даже распознанное `кВт` не разрешает сравнение при
неустановленной стадии страницы, редакции, связи приборов и температурной базе.
В `scripts/probe-radiator-spec.py` этот формат выбирается только флагом
`--observation-slice`; без него CLI сохраняет прежнюю схему отчёта.

Проверка `contentHash` OCR-артефакта подтверждает целостность переданной записи,
но этот worker-only срез не сверяет пиксели рендера и правильность OCR с PDF.
Он не подключён к normal-run API или release. Адресные тесты:
`PYTHONPATH=services/worker python3 -m unittest services/worker/tests/test_radiator_spec.py services/worker/tests/test_radiator_observation_slice.py -v`.
Данные предыдущего публичного прогона выше остаются историческим
свидетельством; новый ограниченный запуск описан ниже.
