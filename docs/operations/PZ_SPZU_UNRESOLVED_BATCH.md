# Публичная диагностическая пачка PZ/SPZU

Пачка охватывает **20 кодов** со статусом `UNRESOLVED` в
[`unresolved-parameter-strategy-v1.json`](unresolved-parameter-strategy-v1.json):
9 PZ и 11 SPZU. Это поисковые подсказки для ручной проверки, а не
извлечённые факты или сравнение ПД с РД. Все 20 кодов остаются `ABSTAIN`:
в реестре для каждого `verifiedComparablePair=false`, а назначение
конкретных файлов на роли каталога не доказано.

## Вход и ограничения

- Используется только полный индекс документов с признаками
  `TRAIN_PUBLIC / INCLUDE / PUBLIC_TRAIN`: 203 источника, включая 202 PDF
  на 10 142 страницы. `F0194` учитывается как TXT-инвентарь; его содержимое
  не читается. Перед проходом проверяются `PASS`-аудит, SHA манифеста,
  каталога, реестра, стратегии и её отчёта, версия индекса и метаданные
  всех PDF по манифесту.
- Для каждого кода FTS находит страницы текстового слоя по широким словам,
  затем регулярное выражение ищет более узкую **строку-кандидат**. Каждая
  найденная страница читается из индекса с проверкой SHA артефакта.
  Подсказки из имени файла влияют только на порядок выборки. Стадия и раздел
  берутся из манифеста, но не подтверждают роль, редакцию или связь элемента.
- Отчёт показывает максимум **16 страниц на код и 3 строки на страницу**;
  счётчики всех найденных страниц и строк сохранены отдельно. Выборка
  распределяется между объектами и стадиями. Поля `omittedLexicalTextPages`
  и `omittedMatchingLines` явно фиксируют усечение.
- `OCR_REQUIRED` остаётся неизвестным: в индексе 1 474 таких страницы.
  Отдельная очередь содержит максимум 80 страниц на расстоянии до двух
  страниц от выбранных текстовых подсказок. В этом прогоне их 21,
  `ocrQueueOmitted=0`. OCR здесь не запускался; отсутствие буквального
  совпадения на текстовой странице не доказывает отсутствие параметра.
- В каждой показанной строке закреплены ID и SHA файла, номер и SHA
  страницы, объект, стадия, раздел, координаты, SHA строки и
  `revisionStatus=UNVERIFIED`. Нельзя соединять строки разных файлов
  только по одинаковому слову: нужны совпадение объекта, редакции,
  элемента и назначенных ролей источников.

Воспроизведение при доступном индексе:

```bash
PYTHONPATH=services/worker python3 scripts/batch-pz-spzu-unresolved-public.py \
  --index /data/index \
  --audit output/public-index-20260927/index-audit.json \
  --output output/pz-spzu-unresolved-20260927/new-report.json
```

CLI требует новый путь и не перезаписывает существующий отчёт. На
homeserver проход выполнен в отдельном worker-контейнере без сети,
с лимитами 2 CPU / 3 GiB RAM; checkout и индекс подключены только для
чтения. Результат — [`report.json`](../../output/pz-spzu-unresolved-20260927/report.json),
SHA-256 `a09fec0b2c39826b537d294cef9c670f376041504c0e90012c1e4496486d5535`.

## Наблюдения на публичных PDF, 27 сентября 2026

буквальное совпадение в строке. Все FTS-пары прошли `get_indexed_page`
с проверкой SHA артефакта до строкового отбора. Для подробных примеров
отобраны 253 пары и показаны 346 строк; 945 лексических пар не вошли в
примеры из-за лимита, но были прочитаны и посчитаны.

## Проверка кода

```bash
PYTHONPATH=services/worker uv run --no-project \
  --with 'pdfminer.six==20260107' --with 'PyMuPDF==1.27.2.2' \
  python -m unittest services.worker.tests.test_pz_spzu_unresolved_batch -v
```

Пять тестов проверяют инвентарь кодов, защиту FTS-запроса, отсечение
очевидно чужих контекстов, порядок выборки и полный синтетический
индекс с публичным TXT-инвентарём и непрочитанной OCR-страницей. Отдельно
проверяется отказ при изменении SHA отчёта стратегии. Дальше нужна
ручная привязка конкретных листов, редакций и источников к ролям каталога,
а затем адресный OCR/визуальная геометрия и сравнение чисел или объектов.
