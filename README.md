# Инспектор ИИ

> Публичный снимок исходного кода для жюри. Конкурсные PDF исключены из этой копии; [состав и ограничения](PUBLIC_RELEASE.md).

**Меньше поиска по томам, больше времени на проверку по существу.** «Инспектор ИИ» помогает работать с проектной (ПД), рабочей (РД) и исполнительной (ИД) документацией. Он находит в PDF места, которые стоит сверить, показывает исходный лист и сохраняет решение инспектора. Проект команды **«ИИ друны»** для ЛЦТ 2026.

> **ИИ подсказывает, инспектор решает.** Кандидат на замечание — повод открыть документы и проверить их. Сам по себе он не означает нарушения. Подтверждённые замечания и официальный протокол показаны отдельно.

## Что уже работает

1. **Собрать комплект.** Создайте объект и загрузите документы по стадиям ПД, РД и ИД. Оригиналы сохраняются; можно вернуться к объекту и добавить недостающие файлы.
2. **Найти, что проверить.** Откройте список кандидатов. Каждая карточка ведёт к конкретной странице и строке или фрагменту чертежа. Рядом указано, почему вывод пока не подтверждён.
3. **Принять решение.** Сверьте оригинал, оставьте подсказку для дальнейшей проверки или отклоните её с пояснением. Решение можно увидеть в истории и выгрузить в JSON.
4. **Увидеть ограничения.** В справочнике есть все 132 пункта матрицы. Если для пункта не хватает источников или способа проверки, интерфейс так и сообщает; такой пункт не превращается в нарушение.

В одном сквозном прогоне двух разрешённых PDF обработаны **213 страниц** и получены **17 подсказок**. Все **17 ссылок на исходные фрагменты** повторно проверены. Анализ остался частичным; подтверждённых нарушений в этом прогоне **нет**. [Как проходила проверка](docs/operations/TZ_REVIEWER_REHEARSAL_20260929.md).

В более широкой сохранённой выборке на 29.09.2026 — **269 подсказок на 53 исходных PDF** по **113 из 132 кодов**. Это показывает, для скольких тем удалось найти фрагменты. Это не число завершённых проверок и не оценка точности. [Подробности выборки](docs/operations/REVIEW_CANDIDATES_20260929.md).

### Что посмотреть за две минуты

Откройте **«Объекты»**, выберите проверку, перейдите в **«Кандидаты»**, посмотрите исходный лист и сохраните решение с причиной. Затем откройте экспорт. Для первого показа можно подготовить три примера, если у вас есть оригинальные PDF из конкурсного пакета: в публичный репозиторий они не включены. Кабинет открывается без регистрации и пароля.

## Как запустить

Есть два пути. **Обычный запуск** открывает приложение и API на вашем компьютере. **Стендовый запуск** дополнительно поднимает сервисы обработки документов и локальные модели; он нужен, чтобы загрузить новые PDF и дождаться результата проверки. Все команды выполняются из корня репозитория.

### 1. Обычный запуск: Node.js + PostgreSQL

Нужны Node.js **22+**, npm **10+** и работающий PostgreSQL **17** с правом создавать таблицы. Подставьте адрес своей локальной БД. На Linux/macOS:

```bash
npm ci
export DATABASE_URL='postgresql://USER:PASSWORD@127.0.0.1:5432/inspector'
export INSPECTOR_OPEN_WORKSPACE=1
export API_HOST=127.0.0.1
export SESSION_COOKIE_SECURE=0
npm run db:migrate
npm run dev
```

На Windows PowerShell после `npm ci`:

```powershell
$env:DATABASE_URL = 'postgresql://USER:PASSWORD@127.0.0.1:5432/inspector'
$env:INSPECTOR_OPEN_WORKSPACE = '1'
$env:API_HOST = '127.0.0.1'
$env:SESSION_COOKIE_SECURE = '0'
npm run db:migrate
npm run dev
```

Откройте **http://localhost:5173**; API отвечает на **http://127.0.0.1:4100/api/health**. Vite проксирует `/api` на порт 4100.

Так запускаются интерфейс и API. Сервисы фоновой обработки, проверки файлов и модели в эти команды не входят: для загрузки отдельно нужен `clamd`, для просмотра страниц PDF — Poppler (`pdfinfo`, `pdftoppm`). Чтобы пройти весь путь от нового файла до результата, используйте стендовый запуск. Без `DATABASE_URL` кабинет не откроется.

### 2. Стендовый запуск: Linux + Docker Compose

Нужны Linux x86_64, Docker Engine **24+**, Compose **v2.30+** и NVIDIA Container Toolkit. Конкурсный профиль `server` рассчитан на один выделенный H100 с 80 ГБ видеопамяти. В `SERVER_GPU_DEVICE` укажите индекс или UUID выданного GPU. Первая команда создаст `infra/.env.server` с отдельными паролями; существующий файл она не заменяет.

```bash
./infra/stack.sh server init
```

Чтобы на стенде появлялись адресные подсказки, задайте в `infra/.env.server` следующие значения **до запуска**. Остальные строки файла, включая пароли, сохраните. `SERVER_GPU_DEVICE` должен указывать ровно на один выделенный GPU.

```dotenv
INSPECTOR_ANALYSIS_PROFILE=PILOT_PZ002_PZ017
INSPECTOR_OCR_LAYOUT_SELECTION_PROFILE=v4
INSPECTOR_VISUAL_PROFILE=V6
INSPECTOR_OCR_HEAT_ROW_PROFILE=v1
INSPECTOR_FACT_FAMILY_PROFILE=v1
INSPECTOR_CANDIDATE_FAMILY_PREVIEW_PROFILE=v1
INSPECTOR_CANDIDATE_FAMILY_OBSERVATIONS_PROFILE=v1
```

```bash
python3 infra/check-competition-profile.py
./infra/stack.sh server preflight
./infra/stack.sh server config --quiet
./infra/stack.sh server up -d --build
python3 infra/check-competition-profile.py --running
./infra/smoke-providers.sh server
./infra/stack.sh server ps
```

Откройте **http://127.0.0.1:8080** на сервере. Если подключаетесь с другого компьютера, выполните `ssh -N -L 8080:127.0.0.1:8080 user@server` и откройте этот адрес у себя. Проверка API: `http://127.0.0.1:4100/api/health`. Для постоянной ссылки проверяющим нужен отдельный HTTPS-адрес.

**Добавить три примера** после готовности стенда и получения PDF F0101, F0142, F0147 из конкурсного пакета:

```bash
python3 scripts/prepare-public-review-examples.py \
  --base-url http://127.0.0.1:4100 \
  --pdf-dir /path/to/approved-pdf \
  --env-file infra/.env.server \
  --receipt output/public-review-examples.json
./infra/stack.sh server up -d --no-deps api
```

Скрипт загружает три PDF (F0101, F0142, F0147), предварительно сверяет каждый с исходным манифестом по размеру и SHA-256 и проверяет, что в результате появились подсказки. В новой базе примеров ещё нет: эту команду нужно выполнить один раз после предоставления оригиналов. [Подробнее о примерах](docs/operations/PUBLIC_REVIEW_VISITOR_20260929.md).

Для обычного рабочего компьютера есть профиль `laptop`. Ориентир по ресурсам: **процессор примерно от 8 потоков, 16 ГБ оперативной памяти, видеокарта NVIDIA с 8 ГБ видеопамяти и 40 ГБ свободного диска**. Замените `server` на `laptop` в командах `init`, `preflight`, `up` и `ps`. По умолчанию этот профиль запускается без предметных подсказок; нужные настройки описаны в [инструкции Docker-профилей](docs/operations/DOCKER_PROFILES.md). Для конкурсного сервера есть [отдельная пошаговая инструкция](docs/operations/COMPETITION_H100_LAUNCH.md).

> **Перед публичным показом:** любой посетитель открытого стенда может менять данные в его рабочей области. Поэтому используйте отдельную демонстрационную базу и только согласованные документы. По умолчанию Compose открывает порты лишь на самом сервере (`127.0.0.1`).

## Где пока нужна проверка человеком

- Справочник охватывает 132 пункта, но автоматическое сравнение всех 132 пока не готово. Интерфейс показывает, что удалось проверить, а что осталось открытым.
- Найденная строка в одном PDF не подтверждает, что документы относятся к одной редакции и одному элементу. Сопоставимость и само замечание устанавливает инспектор.
- Точность выявления нарушений на полном наборе, число ложных срабатываний и работа стенда на H100 ещё не подтверждены. [Методика оценки](docs/DATASET_AND_EVALUATION.md) и [итоги проверок](docs/FINAL_VALIDATION_2026-09-29.md).
- Выгрузка подсказок и решений — рабочий материал для проверки, а не официальный список нарушений. Обмен с ИАИС и подписанный PDF-протокол пока не реализованы.
