# Инспектор ИИ

## Актуальная версия для жюри — исправления 20 октября 2026

В этом Git-репозитории опубликован исправленный исходный код приложения. Команды выполняются из корня с `package.json`. [Что исправлено и проверено](FIXES.md): очередь смешанных форматов, отдельный аудит источников, права и FINAL, сохранность старых протоколов и чтение прежних результатов V13.

**Рекомендуемый первый запуск — CPU без GPU и моделей:** Linux x86_64 (на Windows — Linux/WSL2 с Docker), Docker Engine и Compose. Штатный скрипт создаёт локальный env со случайными секретами; затем запускается CPU Compose:

```bash
export INSPECTOR_ENV_FILE="$PWD/infra/.env.cpu-local"
./infra/stack.sh laptop init
docker compose --project-name inspector-ai-cpu-local --env-file "$INSPECTOR_ENV_FILE" \
  -f infra/docker-compose.yml -f infra/docker-compose.core-smoke.yml \
  -f infra/docker-compose.matrix-v13.yml up -d --build
```

С портами по умолчанию откройте **http://127.0.0.1:8080** (API: `http://127.0.0.1:4100/api/health`). База нового стенда пустая; локальный кабинет не требует регистрации. Дождитесь готовности ClamAV перед загрузкой. [Полная CPU-инструкция](docs/operations/CPU_LOCAL_QUICKSTART.md) включает отдельные порты 28190/24190, проверку готовности и остановку; [полный аудит PDF V4](docs/operations/full-source-audit-v4-v1.md) — дополнительный overlay и лимиты.

Текущий путь извлечения текста — **PDF-only**. DOCX/XML принимаются, но здесь явно пропускаются как неподдерживаемые для анализа, без выдуманных результатов. DWG возвращает `503 DWG_VALIDATOR_UNAVAILABLE`: экспортируйте чертёж в PDF. Поддержка всех 132 инженерных проверок, качество GPU/OCR/LLM и обмен с внешними АИС этим запуском не заявляются.

Повторные проверки: web **1369**, целевые API **170**, backend/PostgreSQL **38**, worker **26**, миграции **16** — PASS; наборы частично пересекаются. Проверены CPU-сценарии, сохранённые экспорты и права. [Передача и история приёмки](docs/operations/FINAL_HANDOFF_20261020.md), [парный просмотр ПД/РД](docs/operations/PAIR_VIEWER_ACCEPTANCE_20261020.md), [отдельная подготовка H100](docs/operations/H100_READINESS_20261020.md). Настоящий H100 при подготовке был недоступен.

**Меньше поиска по томам, больше времени на проверку по существу.** «Инспектор ИИ» помогает работать с проектной (ПД), рабочей (РД) и исполнительной (ИД) документацией. Он находит в PDF места, которые стоит сверить, показывает исходный лист и сохраняет решение инспектора. Проект команды **«ИИ друны»** для ЛЦТ 2026.

> **ИИ подсказывает, инспектор решает.** Кандидат на замечание — повод открыть документы и проверить их. Сам по себе он не означает нарушения. Подтверждённые замечания и официальный протокол показаны отдельно.

Публичный состав и исключённые конкурсные материалы описаны в [PUBLIC_RELEASE.md](PUBLIC_RELEASE.md). Результаты тестов выше получены на полном локальном комплекте; корпусные тесты требуют отдельно предоставленных материалов организатора.

## Что уже работает

1. **Собрать комплект.** Создайте объект и загрузите документы по стадиям ПД, РД и ИД. Оригиналы сохраняются; можно вернуться к объекту и добавить недостающие файлы.
2. **Найти, что проверить.** Откройте список кандидатов. Каждая карточка ведёт к конкретной странице и строке или фрагменту чертежа. ПД и РД открываются рядом: независимое листание, масштаб, подсветка цитат и исходных областей, переход к расхождению, поиск текста и полноэкранный просмотр. Рядом указано, почему вывод пока не подтверждён.
3. **Принять решение.** Сверьте оригинал, оставьте подсказку для дальнейшей проверки или отклоните её с пояснением. Решение можно увидеть в истории и выгрузить в JSON.
4. **Увидеть ограничения.** В справочнике есть все 132 пункта матрицы. Если для пункта не хватает источников или способа проверки, интерфейс так и сообщает; такой пункт не превращается в нарушение.

В одном сквозном прогоне двух разрешённых PDF обработаны **213 страниц** и получены **17 подсказок**. Все **17 ссылок на исходные фрагменты** повторно проверены. Анализ остался частичным; подтверждённых нарушений в этом прогоне **нет**. [Как проходила проверка](docs/operations/TZ_REVIEWER_REHEARSAL_20260929.md).

В более широкой сохранённой выборке на 29.09.2026 — **269 подсказок на 53 исходных PDF** по **113 из 132 кодов**. Это показывает, для скольких тем удалось найти фрагменты. Это не число завершённых проверок и не оценка точности. [Подробности выборки](docs/operations/REVIEW_CANDIDATES_20260929.md).

### Что посмотреть за две минуты

Откройте **«Объекты»**, выберите проверку, перейдите в **«Кандидаты»**, посмотрите исходный лист и сохраните решение с причиной. Затем откройте экспорт. Для первого показа можно подготовить три публичных PDF командой ниже. Кабинет открывается без регистрации и пароля.

## Текущая CPU-сборка, 20 октября 2026

Для обычного компьютера используйте [локальный CPU-запуск](docs/operations/CPU_LOCAL_QUICKSTART.md): PostgreSQL, RabbitMQ, ClamAV, API, web и обработчики PDF с текстовым слоем. GPU и H100 для этого пути не требуются. [Текущая приёмка](docs/operations/CURRENT_ACCEPTANCE_20261019.md) отдельно указывает выполненные проверки и ограничения. Просмотр OCR-кандидатов PPM-113 не подтверждает инженерное нарушение; вероятность без принятой калибровки остаётся неизвестной.

## Как запустить

Есть два пути. **Обычный запуск** открывает приложение и API на вашем компьютере. **Стендовый запуск** дополнительно поднимает сервисы обработки документов и локальные модели; он нужен, чтобы загрузить новые PDF и дождаться результата проверки. Все команды выполняются из корня репозитория.

### 1. Обычный запуск: Node.js + PostgreSQL

Нужны Node.js **22+**, npm **10+** и работающий PostgreSQL **17** с правом создавать таблицы. Подставьте адрес своей локальной БД. На Linux/macOS:

```bash
npm ci
export DATABASE_URL='postgresql://USER:PASSWORD@127.0.0.1:5432/inspector'
export INSPECTOR_OPEN_WORKSPACE=1
export API_HOST=127.0.0.1
export SESSION_COOKIE_SECURE=0
npm run db:migrate
npm run dev
```

На Windows PowerShell после `npm ci`:

```powershell
$env:DATABASE_URL = 'postgresql://USER:PASSWORD@127.0.0.1:5432/inspector'
$env:INSPECTOR_OPEN_WORKSPACE = '1'
$env:API_HOST = '127.0.0.1'
$env:SESSION_COOKIE_SECURE = '0'
npm run db:migrate
npm run dev
```

Откройте **http://localhost:5173**; API отвечает на **http://127.0.0.1:4100/api/health**. Vite проксирует `/api` на порт 4100.

Так запускаются интерфейс и API. Сервисы фоновой обработки, проверки файлов и модели в эти команды не входят: для загрузки отдельно нужен `clamd`, для просмотра страниц PDF — Poppler (`pdfinfo`, `pdftoppm`). Чтобы пройти весь путь от нового файла до результата, используйте стендовый запуск. Без `DATABASE_URL` кабинет не откроется.

### 2. Конкурсный H100: актуальный V9

Используйте [пошаговый запуск H100 V9](docs/operations/H100_READINESS_20261020.md) из корня нового source ZIP (из `source/` только для прежнего V9 review ZIP). Там подготовка env с сохранением секретов, выбор одного GPU, аппаратный preflight, запуск и проверки моделей. Нужны Linux x86_64, Docker Engine 24+, Compose v2.30+, NVIDIA Container Toolkit и выделенный H100 80 ГБ; действующий preflight также требует 240 GiB RAM и 150 GiB диска.

Сначала можно проверить Compose без GPU и запуска контейнеров:

```bash
python3 scripts/check-h100-offline-compose.py --output-dir output/h100-offline-compose
```

Для V9 нужны `MATRIX_V1`, `V9_SAMPLE` либо `V9_FULL` и четыре Compose-файла: base, server, matrix-v13, h100-feedback. Команда ниже проверяет конфигурацию **после подготовки `INSPECTOR_ENV_FILE` по инструкции**:

```bash
docker compose --project-name inspector-ai-server --env-file "$INSPECTOR_ENV_FILE" \
  -f infra/docker-compose.yml -f infra/docker-compose.server.yml \
  -f infra/docker-compose.matrix-v13.yml -f infra/docker-compose.h100-feedback.yml \
  --profile server config --quiet
```

Тот же префикс используется для `up -d --build` и остальных действий. Старый одиночный `stack.sh server up` не подключает V9 overlays. Старый `check-competition-profile.py` проверяет исторический V6; текущий guard — `infra/h100-readiness.py`. Точные команды и отдельная аппаратная приёмка приведены в инструкции V9.

После запуска web доступен на **http://127.0.0.1:8080**, API health — **http://127.0.0.1:4100/api/health**. На удалённом сервере используйте SSH-туннель либо согласованный HTTPS-адрес. Проверенная установка CPU-контейнеров не подтверждает работу CUDA и настоящих моделей: H100 при подготовке был недоступен.

Для компьютера без GPU используйте [CPU-запуск](docs/operations/CPU_LOCAL_QUICKSTART.md). Профиль `laptop` с отдельной NVIDIA GPU описан в [Docker-профилях](docs/operations/DOCKER_PROFILES.md); его настройки не заменяют профиль H100 V9.

> **Перед публичным показом:** любой посетитель открытого стенда может менять данные в его рабочей области. Поэтому используйте отдельную демонстрационную базу и только согласованные документы. По умолчанию Compose открывает порты лишь на самом сервере (`127.0.0.1`).

## Где пока нужна проверка человеком

- Справочник охватывает 132 пункта, но автоматическое сравнение всех 132 пока не готово. Интерфейс показывает, что удалось проверить, а что осталось открытым.
- Найденная строка в одном PDF не подтверждает, что документы относятся к одной редакции и одному элементу. Сопоставимость и само замечание устанавливает инспектор.
- Точность выявления нарушений на полном наборе, число ложных срабатываний и работа стенда на H100 ещё не подтверждены. [Методика оценки](docs/DATASET_AND_EVALUATION.md) и [итоги проверок](docs/FINAL_VALIDATION_2026-09-29.md).
- Для каждой сохранённой версии доступны JSON, PDF, DOCX и XML. Отчёт повторяет семь разделов приложения №2, показывает источники, решения инспектора и пробелы. Повторное скачивание возвращает сохранённые байты. [Экспорт и проверка](docs/operations/PROTOCOL_EXPORT_ACCEPTANCE_20261020.md).
- Кандидаты и решения инспектора разделены. Электронная подпись и подтверждённый обмен с ИАИС пока не реализованы. Хакатонный pull facade действующего FINAL доступен через ссылку в протоколе: точный snapshot и локальные файлы, без исходящей доставки.
