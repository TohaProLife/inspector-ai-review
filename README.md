# Инспектор ИИ

> Публичный снимок для просмотра жюри. Материалы с неподтверждёнными правами на распространение исключены; состав и ограничения указаны в [PUBLIC_RELEASE.md](PUBLIC_RELEASE.md).

Сервис для проверки строительной документации: загрузить ПД, РД и ИД, найти исходную страницу, разобрать подсказку и сохранить решение инспектора. В справочнике 132 контрольных параметра; это **не означает, что для всех 132 реализован автоматический анализ**.

Передача на 29 сентября 2026 года: [состав проекта и сценарий проверки](docs/SUBMISSION.md), [финальные проверки и ограничения](docs/FINAL_VALIDATION_2026-09-29.md).

## Возможности

- Создание объектов, возобновление загрузки, дозагрузка в существующий объект и запуск новой проверки.
- Проверка формата и антивирусная проверка файла, SHA-256, дедупликация и сохранение оригинала в локальном или S3-совместимом хранилище.
- Проверка источников: редакция, согласование, раздел, группа связанных документов и стадии страниц смешанного PDF. Решения включаются в следующие запуски.
- Просмотр оригинала, страницы и фрагмента; сохранённый текстовый слой, ограниченный OCR и подсказки выбранного профиля. Подсказки и подтверждённые замечания показаны отдельно.
- Очередь решений, причины отказа от сравнения, покрытие правил и справочник; поиск по объектам, текущим результатам и справочнику.
- Версии протокола, финализация, отзыв при соответствующих правах и экспорт JSON. Финальная версия имеет неизменяемый снимок и контрольный хеш.
- Светлая и тёмная темы, мобильная навигация, клавиатурный поиск и настройки плотности текста.

API сохраняет серверные сессии, CSRF, объектные права, журнал команд, проверку версии и идемпотентность. PostgreSQL хранит рабочие данные; RabbitMQ и workers выполняют обработку через очередь с проверкой попытки и версии входов.

## Границы результата

Предметные правила и вспомогательные OCR/review-профили реализованы частично. По умолчанию выбран `SCAFFOLD`; ограниченные пилотные правила включаются явно. `PARTIAL`, `UNSUPPORTED`, `ABSTAIN` и «нельзя сравнить» описывают ограничения запуска, а не отсутствие нарушения. Подсказка по строке или теме не доказывает расхождение ПД/РД и не повышает покрытие правил.

Основной проверяемый путь — PDF. Приём DOCX/XML не означает полного предметного анализа этих форматов. Экспорт JSON не равнозначен интеграции с ИАИС, УКЭП или выпуску подписанного PDF-протокола. Точность на всех 132 параметрах, эксплуатационная готовность и работа на целевом H100 требуют отдельных подтверждений.

Рабочий кабинет не заполняется десятью seed-замечаниями. Публичные данные используются как тестовые материалы; три PDF из `fixtures/public-review` загружаются отдельно по [инструкции подготовки](docs/operations/PUBLIC_REVIEW_VISITOR_20260929.md). Показатели определяются сохранённым запуском, а не фиксируются в интерфейсе.

## Локальная разработка

Нужны Node.js 22+, npm 10+ и доступный PostgreSQL 17 с созданной БД и правами на миграции. Для Python-проверок нужен Python 3.11+. Текущий web получает сессию через `/api/auth/open-workspace`, поэтому для кабинета обязательны `DATABASE_URL` и `INSPECTOR_OPEN_WORKSPACE=1`. Memory-adapter без БД этот сценарий не заменяет.

В PowerShell, из корня репозитория, укажите действительные реквизиты локальной БД:

```powershell
npm ci
$env:DATABASE_URL = 'postgresql://USER:PASSWORD@127.0.0.1:5432/inspector'
$env:INSPECTOR_OPEN_WORKSPACE = '1'
$env:API_HOST = '127.0.0.1'
$env:API_PORT = '4100'
$env:ALLOWED_ORIGINS = 'http://localhost:5173,http://127.0.0.1:5173'
$env:SESSION_COOKIE_SECURE = '0'
$env:VITE_API_URL = '/api'
$env:UPLOAD_STORAGE_DIR = (Join-Path (Get-Location) 'runtime')
npm run db:migrate
npm run dev
```

Web: `http://localhost:5173`, API health: `http://127.0.0.1:4100/api/health`. Vite проксирует `/api` на порт 4100. Если он выбрал другой порт, используйте напечатанный адрес и добавьте origin в `ALLOWED_ORIGINS` при необходимости. `.env.example` служит справочником: команды API не загружают этот файл автоматически.

Для загрузки файлов перед запуском API задайте адрес **работающего `clamd`**, например `$env:CLAMAV_HOST = '127.0.0.1'` и `$env:CLAMAV_PORT = '3310'`. При недоступном сканере загрузка завершается ошибкой. Если выбран S3/MinIO, дополнительно настройте хранилище по [runbook](docs/operations/DOCKER_PROFILES.md).

Просмотр страниц и фрагментов PDF требует Poppler (`pdfinfo`, `pdftoppm`) в `PATH` процесса API. В API-образе Compose эти утилиты установлены; для запуска напрямую на Windows/Linux их нужно подготовить отдельно.

`npm run dev` запускает web и API. Для завершения фоновых проверок нужны RabbitMQ, outbox-relay, workers и провайдеры выбранного профиля. Полный контур запускается через Linux Compose ниже.

В открытом контуре посетители используют общую рабочую учётную запись и могут менять объекты её организации. Для локального просмотра сохраняйте loopback-привязку. `INSPECTOR_OPEN_WORKSPACE=0` оставляет прежний парольный API для совместимости, но текущий web не содержит формы входа в этот режим.

## Полный стек на Linux

Требования: Linux x86_64, Docker Engine 24+, Compose v2.30+, NVIDIA Container Toolkit и ресурсы выбранного профиля. `laptop` рассчитан на RTX 4060 Laptop 8 GiB; `server` — на один H100 80 GiB. Точные требования, загрузка весов и проверка провайдеров: [Docker profiles](docs/operations/DOCKER_PROFILES.md).

```bash
./infra/stack.sh laptop init
./infra/stack.sh laptop preflight
./infra/stack.sh laptop up -d --build
./infra/stack.sh laptop ps
```

Для H100 замените `laptop` на `server` и выполните [инструкцию конкурсного запуска](docs/operations/COMPETITION_H100_LAUNCH.md). Стек включает PostgreSQL, RabbitMQ, Redis, MinIO, ClamAV, API, web, relay и workers. Web по умолчанию: `http://127.0.0.1:8080`; секреты генерируются в `infra/.env.<profile>`, открытый кабинет включён по умолчанию. API стартует после успешного сервиса миграций. Проверка работающих контейнеров не заменяет проверку завершённого анализа PDF.

В репозитории **29 миграций: `001`–`029`**. Единый runner проверяет контрольные суммы и использует PostgreSQL advisory lock. Применяйте миграции через `npm run db:migrate` или штатный Compose-сервис; старые применённые SQL-файлы не редактируются. Обычный `down` сохраняет БД и model volumes для повторного запуска.

## Проверки

Для полного набора подготовьте отдельное Python-окружение. Пример для PowerShell:

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -e services/worker -r scripts/requirements-tests.txt
$env:PYTHON_BIN = (Resolve-Path .\.venv\Scripts\python.exe).Path
npm run check
```

В Linux используйте `python3`, `.venv/bin/python` и `export PYTHON_BIN="$PWD/.venv/bin/python"`. `npm run check` выполняет TypeScript, JavaScript/TypeScript-тесты, Python-наборы и сборку. Python-тесты запускаются переносимым runner без POSIX-синтаксиса переменных:

```bash
node scripts/run-python-tests.mjs
node scripts/run-python-tests.mjs worker
```

PostgreSQL integration запускается отдельно на тестовом сервере с правом создавать временные БД; набор создаёт и удаляет собственные тестовые базы:

```powershell
$env:INSPECTOR_POSTGRES_ADMIN_URL = 'postgresql://TEST_USER:TEST_PASSWORD@127.0.0.1:5432/postgres'
npm run test:postgres -w @inspector-ai/api
```

Unit-тесты не подтверждают доступность ClamAV, моделей, исходного корпуса или полного фонового контура. Выполненные проверки и ограничения зафиксированы в [финальном отчёте](docs/FINAL_VALIDATION_2026-09-29.md); дополнительные команды — в [матрице проверок](docs/operations/TEST_MATRIX.md).
